## 已完成的交互

1. **试剂批号与换批**：按厂家、产品或批号搜索，选择一行查看效期、来源、验证记录及各检验项目的使用情况。登记试剂批号、登记验证、切换批号均使用独立弹窗。停用的试剂或批号仅供查询。
2. **切换试剂批号**：明确选择本次切换的检验项目，显示原/新批号、实际启用时间之前的最新验证和依据；填写操作者、换批原因及原均值和标准差仍适用的依据，勾选确认后保存。一次选择多个项目时，全部通过校验才整体保存。
3. **历史记录**：各类事件统一查询，选择一行查看原事件、确认人及验证依据。试剂换批和此前更正可打开更正弹窗；保存追加一条关联原事件的记录，自动选中新记录。其他类型事件仅供查询。
4. Enter 只应用输入，不保存；校验失败保留输入；未保存取消时可继续填写或放弃。保存后保留所选批号，新增批号或更正后定位到新记录；跨页返回保留搜索、筛选和选择。多个待处理弹窗按顺序显示，不相互覆盖草稿。
5. 当前使用与未来安排分开显示，按生效时间及记录顺序确定所用批号。同一未来生效时间的后续更正替代此前安排的展示。清空日期不自动改为当前时间，保存会要求补填；仍可取消或恢复草稿。

## 原有业务规则与保护

复用 `services/lot_lifecycle_service.py` 的登记、验证、切换和追加更正服务。产品、检验项目和验证对应关系、效期、最新验证通过、时间、旧窗口冲突以及事务回滚规则继续执行。最新验证未通过时不能退用更早的通过记录。检验项目名称同时包含项目、仪器、方法学和质控方法，避免仅用内部编号选择。

原检测记录及当时使用的试剂批号、质控品批号、参数版本、结果和判读不改；试剂换批不重建均值和标准差，也不重置原连续规则。本次“更正试剂使用记录”更正的是默认使用安排，**不能用于改写既往检测实际批号**。重复追加更正仍遵循原服务规则，不增加只能更正一次的限制。

新弹窗打开和保存时核对资料内容，拒绝真实变更后的旧窗口。例行页面同步和内置资料刷新只改变的更新时间不再造成正常填写误报。基础资料编辑、参数管理的同类问题也已补齐：官方检验项目只忽略例行更新时间，实际字段变化仍检查。

实际应用联调另发现：启动时刷新官方检验项目会覆盖用户补充备注。已最小修正 `migrations/v1_1_master_data.py` 的重复初始化逻辑：新条目仍带默认分析物备注，已有条目保留本地备注，其他标准字段更新行为不变。未新增数据库结构或迁移版本；只在临时库和独立演示库验证，没有运行真实库迁移。
