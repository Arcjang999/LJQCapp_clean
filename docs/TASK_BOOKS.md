## 3. 建议顺序与依赖

保留主线：任务 0 → 既有业务/显示/打包验收 → 任务 1 → 任务 2 阶段 → 任务 3 → 主框架后的任务 4、5。

此次建议将任务 2 阶段安排为 **2A 基础资料 → 2 日常批量录入 → 2B 临时质控**。这样先有产品与检测项关系，再完成日常操作，最后独立验收临时记录的计算边界。此细分顺序尚不是用户确认的排期，不改变任务 0 优先，也不安排日期或并行开发。

- 任务 0 的首次整体验收只覆盖当时已有功能，不等待尚未开发的 2B、4、5。
- 任务 1 不等待临时质控或账号功能才能交付；2B 接入后补验临时失控处理。
- 2A 的厂家目录未取得正式资料时，可以验证导入和关联功能，但不能声称正式邦德盛目录已经完整交付。
- 3C 的临时记录验收在 2B 接入后完成；任务 5 接入后再补更正版报告验收。任务 3 不因账号后置而无法推进。
- 任务 5 不能拆成“先开放改数据，重算以后再补”。后台更正流程、计算结果和前台展示需一起验收。

## 4. 每份任务书的交付规则

每项明确目标、现有基础、范围、依赖、验收和待明确事项。旧弹窗只复用和扩展，不重建；源码、数据库结构及实际页面需在实施时核对，文档中的基线不等于当时现状已复验。

后续开发沿 `AGENTS.md` 和交接要求保护工作区，只用独立库或副本验证。核心计算公式、质控规则与判定粒度保持不变；更正/补录触发必要重算不等于改变算法。数据库迁移、备份恢复和旧数据兼容按实际改动验收。

完成报告应列明交付范围、修改位置、验证证据和未完成项；不得用“代码写好”“文档已拆”代替业务验收。界面交互、报告与计算分别按相应任务验证，不重复无关测试。
