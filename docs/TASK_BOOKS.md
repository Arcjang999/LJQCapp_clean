## 3. 建议顺序与依赖

保留主线：任务 0 → 既有业务链核验 → 任务 1 → 任务 2 阶段 → 任务 3 → 主框架后的任务 4、5。发布前的目标系统缩放与打包验收独立列为 R0-02；缺少目标设备时保留待验收，不阻塞本机可实施的后续功能，也不能据此宣称发布验收全部通过。

此次细化采用默认执行顺序 **2A 基础资料 → 2 日常批量录入 → 2B 临时质控**。这样先有产品与检测项关系，再完成日常操作，最后独立验收临时记录的计算边界。这是实现依赖顺序，不是用户承诺的日历排期；原细卡仍按真实依赖实施；当前合并轮次允许独立模块并行，统一集成验收。

- 任务 0 的首次整体验收只覆盖当时已有功能，不等待尚未开发的 2B、4、5。
- 任务 1 不等待临时质控或账号功能才能交付；2B 接入后补验临时失控处理。
- 2A 已于2026-09-28收到邦德盛源表，目录录入仅产品编号、产品名称、浓度、浓度编号，见[预处理记录](execution/notes/bondson_catalog_source_2026-09-28.md)。浓度与浓度编号任一项有有效文本即可；阴性、阳性、分型、基因型/位点按原文，不要求数字或两项同时填写，一项有效时另一项空白或“/”不标缺项。所有明确多目标混合（含生化/免疫复合多个检测项）及血筛排除并保留审计，同一目标多水平与分型/基因型/位点本身不等于多目标混合；仅两项均无有效内容时提示核对。资料预处理不代表目录导入和关联功能已交付。组合水平已明确为一个质控品包含多个水平，选择、更换或导入产品不能默认或自动切换Z-score；各检测项显式方法保留，未配置由用户选择或沿已明确panel设置，原算法约束不变。多个检测项关系仍单独维护且不得从名称/浓度猜测。
- 3C 的临时记录验收在 2B 接入后完成；任务 5 接入后再补更正版报告验收。任务 3 不因账号后置而无法推进。
- 任务 5 不能拆成“先开放改数据，重算以后再补”。后台更正流程、计算结果和前台展示需一起验收。

每项明确目标、现有基础、范围、依赖、验收和待明确事项。旧弹窗只复用和扩展，不重建；源码、数据库结构及实际页面需在实施时核对，文档中的基线不等于当时现状已复验。
