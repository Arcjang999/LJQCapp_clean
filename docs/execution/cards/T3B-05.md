## 1. 目标及用户可见结果

- 可预览、导出、重新查阅试剂比对报告，能从原数据复核每个统计。
- 修改配对或接受标准后形成明确修订，已确认报告完整保留。

## 2. 必读实际文件与复用函数

- `services/report_service.py::list_report_history_records / get_report_history_record`：报告历史读取能力。
- `services/report_pdf_layout.py`、`tests/report_pdf_assertions.py`：中文排版与 PDF 核对基础。
- `pages/report_history_page.py::render_report_history_page`：历史入口和模糊查询。
- 任务 1 的不可变文件/版本接口；拟新增试剂比对报告类型与生成器，不复写月报类型。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 组装报告数据包，保存系统、两批、日期、匿名样本、单位、原值、方向/分母、逐对差异和整体条件。
2. 完整呈现方案来源、浓度分段、不能评价原因、实验室结论及确认人/时间。
3. 报告引用确认时的数据与方案版本，PDF 生成时校验不能混用后来编辑的草稿。
4. 渲染长表与多页方案，表头重复、图例/单位清楚、匿名编号完整；无效值不能打印成无穷或通过。
5. 生成成功后按既有报告历史机制保存版本和文件；失败保留确认数据且允许仅重试输出。
6. 修订配对/标准时保留旧数据及报告引用，新增版本重新确认并能解释版本间变化。

数据契约与状态：

- 报告历史必须指向稳定数据/方案/结论版本，不通过读取当前草稿重建“原报告”。
- 重复点击同一输出请求不生成无提示重复历史；主动修订可产生清楚的新版本。
- 报告附件使用任务 1 存储合同，文件名相同不覆盖旧文件。

## 4. 本卡不做与禁止事项

- 不把比对报告混成日常月报或通用性能验证报告。
- 不因报告生成成功自动切换批号或将不评价数据判为通过。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 完整确认比较；When 导出；Then PDF 原配对、差异、方案和结论与页面一致且可复算。

2. Given 零分母与分段条件；When 查看 PDF；Then 不能评价和适用条件清楚，无无穷值或虚假通过。

3. Given 已确认版本后修改一对值；When 生成修订版；Then 原报告仍可下载，新版重新确认且标出修订关系。

4. Given 文件生成失败后重试；When 成功；Then 原确认不丢，历史没有无提示重复或空文件成功项。

## 6. 证据与完成条件

- 短/长表、分段方案、零分母和多页 PDF 逐页渲染证据。
- 报告历史版本、文件唯一性、失败重试与页面一致性检查。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
- 执行实现或验收时仅使用独立库/明确副本，记录版本和保护范围；此次编写卡片不运行应用或数据库操作。
