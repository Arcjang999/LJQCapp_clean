# T3A-06｜平行20点进度与人工正式切换

- 原任务：任务 3A：质控品新旧批号比对

- 类型：实现
- 前置卡：T3A-05；T3A-01 的有效点、整组及切换范围决策已明确
- 本卡交付：旧批正式、新批平行的进度展示及保留新数据的人工切换。
- 原需求锚点：[原任务 3A](../../task_03_comparisons_and_monthly_reports.md#2-3a质控品新旧批号比对)；[合并需求](../../requirements_merged_2026_09_21.md) §4.5、§6。

执行前阅读 [统一执行规则](../EXECUTION_RULES.md)。本卡是待执行范围，不表示功能已经实现。

## 1. 目标及用户可见结果

- 看到新批各检测项/水平已累积的有效点数，达到批准条件后明确确认参数与切换。
- 切换后旧批停止使用，新批平行数据继续保留在同一批次。

## 2. 必读实际文件与复用函数

- `services/lot_lifecycle_service.py::change_qc_lot / set_qc_usage_state / effective_qc_state`：现有状态和生效时间。
- `services/qc_lifecycle_edit_service.py::get_qc_binding_context / save_qc_lifecycle_action`：版本检查和保存。
- `ui/qc_lifecycle_workspace.py::_state_fields`、`ui/target_profile_workspace.py`：现有状态及参数确认。
- T3A-01 计数/切换合同及 T3A-03 查询；拟新增路径进度和原子切换编排。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 在既有平行状态显示各检测项/水平进度，明确 20 是有效数据点，不替换通用建靶配置。
2. 依据已确认计数规则处理禁用、完整 run 及保留水平，显示不足位置和可查看的计数明细。
3. 达到进度条件仅开放人工核对，不自动确认参数、验证或切换使用状态。
4. 人工确认前检查全部必要水平参数、适用质量要求、最新验证及效期，并展示新旧批及生效时间。
5. 在同一业务操作中完成指定范围的新批正式和旧批停止；并发或任一步失败不留下单边切换。
6. 切换后继续使用已有新批绑定及结果；日常录入按当前与检测时间状态校验，原旧批数据只读可查。

数据契约与状态：

- 20 点进度、参数完成、验证通过和正式使用是不同条件，不能互相替代。
- 切换范围以合同确认的检测系统/检测项/水平为准，不擅自停用其他仪器或全产品。
- 切换提交包含预览版本、生效时间、确认人和依据；重复提交不重复建新空批。

## 4. 本卡不做与禁止事项

- 不将第 20 个点保存动作自动变成正式切换；不复制旧结果给新批凑数。
- 不因新批转正式而重建空序列；不按日数伪造 20 点。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 新批有效点 19；When 查看进度并尝试切换；Then 按合同指出未满足条件，不自动正式使用。

2. Given 已有 20 点、参数和验证均完备；When 人工确认；Then 新批正式、指定旧批结束，新批原 20 点身份不变。

3. Given 操作中旧批结束写入失败；When 提交结束；Then 整个切换回滚，不出现两边状态只改一边。

4. Given 另一仪器也用同名产品；When 本系统切换；Then 不擅自修改另一仪器的批次范围。

- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
