# T4-05｜在所有写入服务统一执行权限

- 原任务：任务4《账号权限与实验室关联》
- 状态：未开始
- 类型：实现
- 前置卡：[T4-04](T4-04.md)；T4-01对应动作权限矩阵已确认
- 本卡交付：共用授权服务和完整写入入口覆盖表
- 原需求锚点：[任务4](../../task_04_accounts_and_lab_scope.md)第3节“服务层权限／任务5对接”、第4节；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.2、4.6及第6节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

普通账号无法经旧弹窗、导入或直接服务调用修改历史。
管理员的允许范围由同一服务判断，批次停用、参数及质量要求校验仍然生效。

## 2. 必读实际文件与复用函数

- `database.py`：`add_result`、`update_result`、`update_zscore_run`、`add_zscore_run`、`add_instant_result`、维护/禁用相关函数。
- `services/lot_lifecycle_service.py`：`require_writable`、`import_reviewed_results`、`correct_reagent_event`、`create_target_profile`。
- `services/project_config_service.py`：配置保存/启用/复制；`services/project_config_io_service.py`：`import_project_template_xlsx`。
- T1/T2/T2B/T3C实际新增写入服务，设置/备份恢复/报告保存；拟新增`services/authorization_service.py`和绕过测试。

## 3. 逐步实施

1. 以T4-01动作矩阵建动作枚举与共用授权接口，输入为经过验证的当前身份和准确资源身份；未知动作、无身份或无法确认范围默认拒绝。
2. 逐项盘点公开写入入口及其委托关系，包含数据录入、历史修改、建靶维护、配置导入、事件确认、批量提交、设置和恢复，不只列界面按钮。
3. 在真正写入的服务边界检查权限，并在事务内确认身份版本仍有效；页面可提前提示，但不得成为唯一校验点。
4. 保留生命周期、日期、参数、已采用质量要求等原业务校验；管理员权限不豁免任务0精确适用性、停止使用批次或跨检测系统限制。
5. 明确区分当前录入、历史补录、建靶维护和历史更正；普通补录未决定的分支不放行，不能借CSV追加或改检测时间绕过。
6. 批量导入在实际保存时再校验身份与每个目标范围，按已有全成功/全回滚机制执行；预览通过后撤权须整体拒绝。
7. 只交付管理员能通过指定维护权限检查的能力；所有历史维护用户可写入口必须等T5-12整链验收通过才开放，即使某个内部实现卡已经完成，也不得开放现有直接改值函数冒充任务5完整功能。
8. 记录安全拒绝与成功管理动作的真实身份和资源；内部迁移/测试若需系统执行路径必须明确受控，不提供任意布尔参数跳过权限。
9. 对每个入口写允许/拒绝样例，直接调用服务测试；陈旧会话与替换目标ID均必须被拒绝。

## 4. 本卡不做／禁止

- 不只隐藏按钮，不信任调用方提供的actor_name、role或is_admin。
- 不把管理员当作绕过所有业务校验的总开关。
- 不开发更正、补录、排除或重算，不重复既有试剂使用事件更正业务。

## 5. Given–When–Then 验收

1. Given：普通账号A有历史结果101。
   When：分别经旧维护入口、CSV导入和直接修改服务尝试改101。
   Then：都拒绝，原数值/判读/快照未变。

2. Given：管理员M获得任务5所需动作权限。
   When：调用统一授权检查，随后尝试绕过现行标准门禁启用不适用配置。
   Then：维护权限可通过；配置仍被原业务门禁拒绝。

3. Given：A完成20行导入预览后被撤权。
   When：点击保存。
   Then：全部拒绝，无部分行新增，不以预览时权限代替当前权限。

4. Given：调用方传入actor_name=管理员或伪造角色字段。
   When：调用受限写入服务。
   Then：仍依赖验证会话，伪造字段不提升权限。
