## 1. 目标及用户可见结果

- 临时结果、原因和结论始终可查，用户可选择是否在图上显示。
- 开关不改变常规有效点数、均值、SD、CV或已确认的规则窗口。

## 2. 必读实际文件与复用函数

- `pages/lj_sections.py::render_lj_chart_and_analysis_section / render_lj_records_section`：图表和记录区。
- `pages/zscore_sections.py::build_zscore_plot_dataframe / render_zscore_chart_analysis_section`：多水平视图。
- `plotting.py::plot_lj_chart`、`zscore_plotting.py::plot_zscore_overlay`：保留原绘图行为，优先外层数据适配。
- `qc_logic.py::calculate_realtime_stats`、`zscore_logic.py::calculate_formal_realtime_stats`：统计入口。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 列出常规统计、建靶、连续规则、数据表、图表五类消费者，逐个声明接收哪种记录用途。
2. 常规统计读取时排除临时值，防止仅图表隐藏但均值和 CV 已受影响。
3. 图表适配层加入可识别的临时标记与图例，避免将临时值连接成常规控制序列。
4. 数据表展示临时原因、实际批号、结论和参数；可打开独立详情及失控处理入口。
5. 将显示开关作为视图状态保存，切换或重新保存不修改结果用途、评价输入或统计缓存依据。
6. 比较显示前后和加入临时值前后的常规结果；若合同允许临时判读引用常规历史，仅临时评价读取，不反向污染常规。

数据契约与状态：

- “是否显示”仅属于视图；“记录用途”是持久业务属性，不能互相覆盖。
- 常规统计始终不纳入临时 L-J 值；Z-score 归属严格按 T2B-01 对完整 run 的批准规则。
- 无临时记录时开关不会造空点或改变图表纵轴及原来结果。

- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 常规 20 点及一个极端临时值；When 保存并切换显示三次；Then 常规点数、均值、SD、CV完全一致。

2. Given 临时检测失控；When 关闭图上显示；Then 明细仍保留原因、失控结论和详情入口。

3. Given 三水平当前使用合并视图；When 显示临时记录并新增检测；Then 合并视图保持且各水平真实批号不混淆。

4. Given 空临时列表；When 打开开关；Then 显示正常空状态，无虚构统计和图例。
