# T3A-07｜直接换批与部分水平路径接通

- 原任务：任务 3A：质控品新旧批号比对
- 状态：未开始
- 类型：实现
- 前置卡：默认排在 T3A-06 后；技术复用 T3A-02 与既有换批/组合服务；直接初期、部分水平规则分别确认后开放对应分支，不被无关平行计数问题阻塞
- 本卡交付：无需平行报告的直接换批，以及两路径下保留2/3水平部分换批能力。
- 原需求锚点：[原任务 3A](../../task_03_comparisons_and_monthly_reports.md#2-3a质控品新旧批号比对)；[合并需求](../../requirements_merged_2026_09_21.md) §4.5、§6。

执行前阅读 [统一执行规则](../EXECUTION_RULES.md)。本卡是待执行范围，不表示功能已经实现。

## 1. 目标及用户可见结果

- 用户可明确选直接换批，结束旧批后从新批自己的数据重新建立参数。
- 两水平或三水平只更换部分材料时，保留/替换水平、批号和参数来源始终清楚。

## 2. 必读实际文件与复用函数

- `services/qc_replacement_edit_service.py::get_qc_replacement_context / save_qc_replacement`：已有材料复制及保留引用。
- `services/lot_lifecycle_service.py::create_level_combination / set_qc_usage_state / require_writable`：组合与状态。
- `ui/qc_replacement_workspace.py::open_qc_replacement_dialog`：复用既有选择各水平批号入口。
- `zscore_logic.py::should_enable_formal_rules / resolve_zscore_batch_context`：完整组合正式判定条件。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 在已存在换批流程内明确选择平行或直接，路径选择写入业务记录；不新建另一套批号。
2. 直接路径先展示旧批结束与新批累积计划，保留现有质量要求、配置确认及材料准入检查。
3. 按 T3A-01 已确认合同表达新批未建靶时可录入/判读状态；无已批准规则时不开放该分支。
4. 复用各水平复制与组合引用，分别处理 2 水平替换 1 个、3 水平替换 1/2 个的真实批号。
5. 保留水平参数仅作为带来源的待确认依据，替换水平不能继承不适用旧参数；完整组合仍按既有全部水平条件确认。
6. 检验直接路径不要求平行数据或专门平行报告；提交失败/版本变化恢复草稿，不提前终止旧批而丢失新批准备。

数据契约与状态：

- 直接与平行共享身份、验证和来源服务，使用路径及初期规则不同；直接路径不被强制套入 20 点平行计数。
- 新组合创建新序列，既有组合结果保留原材料；保留水平来源引用不能伪造成新批实测数据。
- 何时结束旧批、何时允许新批录入与正式判读由确认合同定义并保持一致事务边界。

## 4. 本卡不做与禁止事项

- 不强迫直接换批生成平行报告或虚构旧/新配对数据。
- 不只完成全部水平同批号场景；不把内部组合锚定批号显示成所有水平实际批号。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 用户选直接换批且批准初期规则已配置；When 确认计划；Then 无平行报告仍可进入新批累积，旧结果保留。

2. Given 未建靶初期规则仍未确认；When 尝试开放直接判读；Then 明确阻止该分支，不显示默认在控。

3. Given 三水平仅更换第二水平；When 建立新组合；Then 第一/三水平保留来源引用，第二水平显示新实际批号，全部参数须确认。

4. Given 新批准备在最终提交失败；When 返回；Then 不留下未说明的旧批提前结束，重试不会生成重复组合。
