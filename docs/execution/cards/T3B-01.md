## 1. 目标及用户可见结果

- 清楚说明本次比较的旧/新试剂、检测系统、单位、样本范围和实验室方案。
- 没有适用方案时可以准备配对资料，但不能生成通用“通过”结论。

## 2. 必读实际文件与复用函数

- `docs/task_03_comparisons_and_monthly_reports.md` §3：患者样本配对及首轮边界。

## 3. 逐步实施、数据关系与失败行为

1. 锁定同一检测系统、同一试剂产品两批的真实检测值定量项目；明确 Ct/log、定性/半定量另定规格。
2. 规定匿名样本编号在单次比对中的唯一性、两侧检测时间、项目、单位和值，不采集患者姓名证件。
3. 为每个实验室方案明确用途、来源、版本、样本量、浓度分布、比较方向、相对差异分母和接受条件。
4. 对零分母、低浓度、分段边界和不满足样本量的行为逐项写清；绝对差异方案须有明确适用依据。
5. 将差值公式作为方案字段/合同确认；不把旧批作分母的实现建议写成所有项目必须采用。
6. 列出需核原文的方案及尚未定项；配对数据模型和预览可先做，未定临床接受规则只阻塞该评价分支。

数据契约与状态：

- 原始检测值、项目和单位精确匹配；模糊搜索不参与计算身份判断。
- 方案不完整状态与“未通过”分开；无条件不能评价，不用空值、零或默认百分比填补。
- T3A 的 20 点计数不自动应用于患者样本量；每个方案单独说明数量与分布。

## 4. 本卡不做与禁止事项

- 不将日常 CV 限值直接当作试剂偏差；TEa 也须明确适用性与评价方法。
- 不引入患者身份信息、通用性能验证平台、在线服务或未经需求确认的算法。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 定量真实值且两批同产品；When 建立方案合同；Then 检测系统、单位、方向和接受条件均明确。

2. Given 选择 Ct/log 或定性项目；When 进入首轮方案；Then 明确不适用本轮，不套用百分比。

3. Given 仅填写“允许差异 10%”而没有分母或依据；When 评价合同；Then 列明缺项，不作为已确认通用规则。

4. Given 一个配对旧值为零；When 核对方案；Then 定义不能做该相对评价或适用的有依据绝对评价，不能默认通过。
