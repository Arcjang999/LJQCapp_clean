# T1-08｜保存处理附件及版本关联

- 原任务：任务1《失控原因分析、复测关联、附件与独立报告》
- 状态：未开始
- 类型：实现
- 前置卡：[T1-07](T1-07.md)
- 本卡交付：受管理的附件上传、查看下载与历史关联
- 原需求锚点：[任务1](../../task_01_out_of_control_reports.md)第2节“附件”、第4节；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.3节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

在处理记录中添加PDF、图片、原始表格，重开后仍能查看或下载。
文件缺失、格式不支持或保存失败时给出明确业务提示，不产生虚假成功记录。

## 2. 必读实际文件与复用函数

- `database.py`：`atomic_write`、`get_db_path`；T1事件版本服务。
- `services/storage_service.py`：`get_database_location_status`、`validate_directory_writable`；文件需随受管理数据位置。
- `ui/out_of_control.py`（T1-03新增后）扩展附件区，不另建脱离事件的文件库。
- 拟新增`services/attachment_service.py`、附件迁移和`tests/out_of_control_attachment_smoke_test.py`。

## 3. 逐步实施

1. 制定统一允许格式、单文件/单次大小限制及重复文件处理，作为本次实现策略记入说明并在上传前显示；至少覆盖PDF、常用静态图片、CSV/XLSX。
2. 建立稳定附件ID，保存原文件名、实际媒体类型、字节数、摘要、受管理相对路径、上传时间/人员及说明；磁盘名称不用用户文件名直接拼路径。
3. 校验扩展名与实际文件内容、大小及目标可写；文件只作为业务资料，不执行宏、脚本、外部公式或系统打开命令。
4. 采用临时文件→校验→完成文件→数据库关联的可恢复流程；失败清理未关联暂存，不删除已有业务附件；明确崩溃后孤立暂存的处理。
5. 相同内容再次上传可复用存储对象，但每事件/版本的说明和关联独立；同名不同内容保留不同ID，不能覆盖。
6. 预览仅用受支持的安全静态呈现；不能预览时仍提供下载；关联ID在服务重新核对属于本事件，禁止任意本地路径下载。
7. 更换附件新增版本关联，已被报告引用的旧附件仍可追溯；取消未保存上传不留下正式关联。
8. 服务区分缺文件、摘要不符、无读取权限和不支持预览；UI只显示可采取的核对动作，技术细节留日志。

## 4. 本卡不做／禁止

- 不把浏览器临时上传路径作为永久附件位置。
- 不执行附件内容，不增加云文件服务、OCR或自动原因分析。
- 不直接删除已引用附件，不用去重机制覆盖不同文件内容。

## 5. Given–When–Then 验收

1. Given：事件E1上传“复测.pdf”和“结果.xlsx”。
   When：保存后关闭再打开。
   Then：两附件说明、下载内容和摘要一致，关联归属E1。

2. Given：名称为“报告.pdf”但内容是可执行文件或超过限制。
   When：上传。
   Then：拒绝并说明格式/大小，事件中不出现成功附件记录。

3. Given：两个不同文件都叫“结果.csv”。
   When：分别上传到同一事件。
   Then：保存为两个稳定对象，不覆盖第一份。

4. Given：已归档附件的实体文件被外部移走。
   When：查看或下载。
   Then：说明文件未找到，保留原关联和历史，不报原始堆栈。

## 6. 需要留下的证据与完成条件

- 格式/大小/路径穿越/伪造附件ID/缺文件/失败清理测试。
- 重启后下载字节一致、同名不同内容及重复上传的证据。
- 上传限制、去重策略和保留规则已记录，准备交T1-09验证完整备份。
- 未执行或未通过的项标注具体缺口，不用“代码已写”代替本卡验收。
