# T4-03｜接入登录、退出与即时失效的会话

- 原任务：任务4《账号权限与实验室关联》
- 状态：未开始
- 类型：实现
- 前置卡：[T4-02](T4-02.md)；T4-01会话时效规则已确认
- 本卡交付：登录界面、真实当前身份与会话失效机制
- 原需求锚点：[任务4](../../task_04_accounts_and_lab_scope.md)第3节“身份与会话”及末段；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.2、4.6及第6节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

用户登录后以真实账号操作，退出后旧页面不能继续保存。
账号停用或角色撤销可使持有旧页面的人立即失去相应权限。

## 2. 必读实际文件与复用函数

- `app.py`：`init_db`、页面路由与`_consume_pending_navigation_intent`；鉴权不能只挡首页。
- `ui/common.py`的`render_page_chrome`，复用现有页头，显示姓名/退出的业务入口。
- `pages/settings_page.py`当前设置入口；T4-02身份服务及凭据版本。
- 拟新增`ui/authentication.py`和身份服务会话方法、`tests/authentication_smoke_test.py`。

## 3. 逐步实施

1. 在所有业务路由前解析会话并验证当前账号状态；仅必要的初始化/登录入口可在未登录时访问，不能从旧导航标志绕过。
2. 实现确认过的登录方式，统一错误提示不泄露账户凭据；密码方案应有失败尝试控制，阈值按实施策略明确记录。
3. 会话凭证与账号、登录时间及可撤销版本关联；页面姓名、操作者输入或角色显示值不能作为授权来源。
4. 每次受限操作通过服务重新检查会话、账号启停、当前角色和范围；角色撤销后旧会话不能靠缓存继续写入。
5. 退出先撤销会话，再清除身份相关缓存、旧弹窗和未确认动作；保留草稿时不得让下一账号直接提交前一账号的确认。
6. 按合同实现空闲/总时长、重启和恢复后的失效；时效未确认不写任意永久登录默认值，相关分支仍待定。
7. 认证失败/会话过期在UI提示重新登录，服务返回结构化业务拒绝；不显示程序异常，日志不打印会话令牌或密码。
8. 测试两个浏览器会话与同窗口换用户；确认页面返回、导入预览和弹窗尚存时都必须重查身份。

## 4. 本卡不做／禁止

- 不把显示姓名或“管理员”字符串当认证，不允许调用方传角色文本自行提权。
- 不增加未确认的联网账号、邮箱验证码或订阅登录。
- 不通过登录页隐藏代替T4-05服务层权限，不在本卡宣称权限接入完成。

## 5. Given–When–Then 验收

1. Given：普通账号A已登录并打开一个待保存弹窗。
   When：退出后在旧窗口提交。
   Then：服务拒绝保存并要求重新登录，不以旧页面状态续写。

2. Given：管理员在另一窗口停用A。
   When：A尝试下一次受限写入。
   Then：立即拒绝，不必等用户主动刷新页面。

3. Given：未登录用户携带show_settings_page或旧项目导航状态。
   When：直接访问对应页面。
   Then：仍先登录，敏感业务内容与动作不能绕过入口。

4. Given：A退出后B登录，A有未确认导入预览。
   When：B进入导入。
   Then：不得无提示沿用A的确认和身份，需按B重新验证。

## 6. 需要留下的证据与完成条件

- 两个真实浏览器会话、陈旧弹窗及旧导航绕过尝试记录。
- 检查日志、提示与截图不含凭据秘密或技术堆栈。
