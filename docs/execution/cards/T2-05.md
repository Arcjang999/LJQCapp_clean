# T2-05｜连续键盘输入、粘贴与失败草稿

遵循 [统一执行规则](../EXECUTION_RULES.md)；本卡未授权超出原任务的新功能。

## 1. 目标及用户可见结果

- 操作者可用Enter、Tab和表格粘贴连续填写整组结果，输入不因重绘或打开详情而丢失。
- 无效输入保持原文并精确定位；失败重试无需重新输入已填写项目。

## 2. 必读实际文件与复用函数

- `pages/zscore_sections.py`：`render_zscore_entry_section`现有表单保护和视图恢复。
- `pages/lj_sections.py`：`render_lj_entry_and_stats_section`；`services/value_type_service.py`现有数值解析。
- `ui/daily_entry.py`（T2-04交付）和其草稿模型；`services/search_service.py`。
- 拟新增草稿/粘贴解析服务，不能把页面行号当身份键。

## 3. 逐步实施

1. 首版规定Tab移动下一可编辑单元、Enter结束当前单元编辑或移动焦点；只有明确“核对并保存”按钮触发提交。
2. 选用现有表格/表单组件后实际验证Enter语义；若默认回车会提交，禁用该行为或用明确提交保护，不依赖提醒文字。
3. 草稿更新以稳定行键存储原始字符串、共同时间、操作者、逐项试剂、选择范围和上下文修订；业务重绘不重建初值覆盖草稿。
4. 实现制表符/换行粘贴预览，按当前明确行/列映射；数量不符、未知表头或多出列时报告位置，不能截断或自动右移。
5. 默认空白保留为缺值而非0；科学计数法/负数/小数使用项目原解析规则，不在粘贴层擅自单位或log换算。
6. 打开批号详情、改变可见筛选、进入设置再返回时恢复草稿；项目消失或revision改变时保留旧输入并要求重新核对。
7. 提供恢复原输入、清空本组和放弃草稿的明确动作；有修改时确认，取消确认不改草稿及焦点定位。
8. 保存/验证失败只写错误状态与定位，不清值；完成保存后的清空由成功回执驱动，不能在按下按钮时先清空。
9. 为连续2—3次录入保留仪器、项目排序、操作者与视图，新一轮时间由用户核对；记录会话草稿不等于已保存检测。

## 4. 不做与禁止

- 不声称只运行自动化单测就完成Enter/Tab行为验证。
- 不在失去焦点时自动保存正式结果，不静默截断多行粘贴。
- 不把未保存草稿伪装成今日已做结果，不扩展应用关闭恢复承诺。

## 5. Given–When–Then 验收

1. 场景 1
   - Given：20项表格已有前10项输入
   - When：连续使用Enter/Tab填写剩余项
   - Then：没有意外提交、清空或跳到错误项目，提交前数据库仍无记录。
2. 场景 2
   - Given：粘贴包含空白、第8行非法文本和多一列
   - When：查看预览并取消
   - Then：错误定位准确且原草稿完整，没有把空白变0或截列后保存。
3. 场景 3
   - Given：表格已填且打开批号详情/设置
   - When：返回原录入页
   - Then：原值、检测时间、选择范围和逐项试剂保持一致。
4. 场景 4
   - Given：保存校验失败后连续修正再录入2—3组
   - When：每次完成明确提交与返回
   - Then：失败草稿保留；成功才清本组数值，排序与视图不重置。

## 6. 证据与完成条件
