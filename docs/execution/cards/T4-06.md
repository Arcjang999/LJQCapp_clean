# T4-06｜复用实验室设置并落实已选数据范围

- 原任务：任务4《账号权限与实验室关联》
- 状态：未开始
- 类型：实现
- 前置卡：[T4-05](T4-05.md)；T4-01实验室范围及维护权限已确认
- 本卡交付：现有实验室资料的权限接入与选定范围校验
- 原需求锚点：[任务4](../../task_04_accounts_and_lab_scope.md)第2节、第3节“实验室设置”、第4节；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.2、4.6及第6节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

用户继续使用同一套实验室资料，账号接入不要求重新登记。
若选择多实验室，则真实限制数据访问；若只选单实验室，明确只交付该范围。

## 2. 必读实际文件与复用函数

- `pages/settings_page.py`：`render_settings_page`；`services/settings_service.py`：`get_report_settings`、`save_report_settings_form`。
- `migrations/v1_1_master_data.py`中的仪器资料、`services/master_data_service.py`及项目配置关系。
- `services/report_service.py`：新报告默认资料与报告历史快照；T4身份/授权服务。
- 拟新增组织关系迁移/服务仅限已确认需要的范围；原`app_settings`不另复制成第二份可冲突资料。

## 3. 逐步实施

1. 按合同列清当前实验室资料谁可读/改，在现有设置页接入相应权限；旧负责人/审核人文本继续作报告默认资料，不等于账号角色。
2. 若决定稳定实验室ID，新增标识并将已有单套资料映射到当前实验室，保存原名称/科室/负责人；改名不改变仪器、成员和历史关联。
3. 单实验室分支自动使用当前范围，不增加每日实验室选择；账号不得构造不存在范围跳过授权，文档明确未实现跨实验室。
4. 多实验室分支仅在已确认时建立成员/角色与仪器归属；项目、批次、结果、事件、附件和报告范围须沿准确外键闭合，不只加一个列表筛选。
5. 对读取、搜索、导出、附件下载和写入都校验资源范围；用户提交仪器ID、项目ID或实验室ID时服务重新核对，禁止跨范围拼接。
6. 当前报告资料改动只影响新报告默认值，既有报告实体和版本快照保持原实验室名称；不能批量回写历史。
7. 仪器或成员跨实验室转移规则未确认时不开放转移按钮；不能随改名称或批量导入暗中重归属。
8. 错误提示使用实验室/项目/账号业务名称；组织ID、内部关系、开发语言不得出现在日常界面。

## 4. 本卡不做／禁止

- 不新建重复实验室信息页，不将panel当实验室组织。
- 不以UI标签过滤冒充多实验室隔离，不为未确认范围建云多租户。
- 不改变旧报告内容，不把历史未知人员文本强绑到成员账号。

## 5. Given–When–Then 验收

1. Given：当前资料为“检验科A”，已经用于旧报告。
   When：管理员改实验室显示名称。
   Then：成员/仪器身份不变，新报告用新默认，旧PDF仍用原名称。

2. Given：合同仅单实验室。
   When：普通账号日常登录进入工作台。
   Then：不被强迫重复选实验室，也不能访问伪造的另一范围。

3. Given：若合同选择多实验室，账号A仅属于实验室1。
   When：传实验室2仪器/事件/附件ID读取或保存。
   Then：服务拒绝所有路径，不能靠列表不显示代替隔离。

4. Given：普通账号无实验室资料维护权。
   When：直接调用保存设置服务。
   Then：拒绝且报告默认资料未变；原有读取范围仍可使用。

## 6. 需要留下的证据与完成条件

- 按所选单/多实验室分支归档范围矩阵，未选分支明确未实现。
- 资料保留与新旧报告对照；改名不改身份的测试。
- 若多实验室，补搜索/导出/附件/服务伪造ID越权测试，不只截图筛选。
- 未确认业务规则和未通过验证分别记录；不能以按钮隐藏或文档存在作为权限已生效的证据。
