## 1. 目标及用户可见结果

- 导出再导入和恢复后，临时记录仍保留用途、原因、判读及事件关系。
- 单份月报明确展示临时记录的归属，常规 L-J 统计保持隔离。

## 2. 必读实际文件与复用函数

## 3. 逐步实施、数据关系与失败行为

1. 在现有导入导出合同增加明确用途、临时原因及关联信息，输出填写说明，不靠自由文字猜类型。
2. 先预览每行类型、批次、检测时间、水平和错误；类型或原因缺失的临时行不能默认转常规。
3. 复用已验收导入身份与去重机制；导入必须保留多水平完整性，失败不形成一半临时记录。
4. 验证备份恢复同时保留记录、评价、事件和附件关系；检测缺件须给可理解状态。
5. 按 T2B-01 决策将临时结果与常规报告数据分开表达；未定时不输出自创总失控和分母，但保留临时详情准备。
6. 将单份报告查询接口交给 T3C，记录其类型归属和计算版本；原报告快照不跟随后续新规则改写。

数据契约与状态：

- 文件中的业务类型与数据库用途双向一致；稳定关联标识的交换方式按已有导入合同明确，不以显示名称当外键。
- 旧格式没有用途字段时只沿用既有明确常规导入行为；不得声称能还原未保存的临时历史。
- 月报合并口径未确认只阻塞该分支；交换与恢复可独立验收，整任务不能提前完成。

## 4. 本卡不做与禁止事项

- 不自行确定“临时失控计入总数”或分母；不开发批量月报任务 T3C。
- 不为旧测试数据补造临时类型、原因、实际批号或历史判读。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 一条临时及一条常规结果；When 导出并导入隔离库；Then 类型、原因、时间、批号保持且常规统计一致。

2. Given 文件临时行缺原因或一个水平；When 预览并尝试确认；Then 定位具体行且整批不产生半成品。

3. Given 临时失控附有处理附件；When 备份到空环境并恢复；Then 原结果、判读、事件和附件都能打开。

4. Given 已确认月报分母案例；When 生成单份 LJ/Z-score 报告；Then 常规和临时计数符合合同且旧报告摘要不变。
