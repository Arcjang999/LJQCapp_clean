# T1-09｜让数据库、附件和报告一起备份恢复迁移

- 原任务：任务1《失控原因分析、复测关联、附件与独立报告》
- 状态：未开始
- 类型：实现
- 前置卡：[T1-08](T1-08.md)
- 本卡交付：完整备份包及可回滚恢复／位置迁移
- 原需求锚点：[任务1](../../task_01_out_of_control_reports.md)第4节、第6节附件验收；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.3节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

用户在现有系统设置中一次备份业务数据与附件，换位置后仍能打开处理资料。
恢复失败保留当前可用数据，不出现数据库指向新附件而文件仍在旧位置的半完成状态。

## 2. 必读实际文件与复用函数

- `services/storage_service.py`：`create_database_backup`、`restore_database_from_backup_file`、`migrate_database_to_directory`、`_copy_database_snapshot`。
- `pages/settings_page.py`：`render_settings_page`和既有选择文件/文件夹流程；复用而非新增存储页。
- `database.py`：`save_db_path_config`、`get_db_path`；`services/attachment_service.py`为T1-08新增后复用。
- `tests/storage_smoke_test.py`；拟新增`tests/attachment_backup_smoke_test.py`。

## 3. 逐步实施

1. 设计含数据库快照、附件实体及清单的完整备份；清单包含版本、相对路径、大小和摘要，不依赖原绝对目录。
2. 生成备份时取得一致的数据库/引用文件视图；先写临时产物并逐项核对，全部成功再提供完成文件，不能把漏附件备份报成功。
3. 恢复前验证备份结构、路径边界、数据文件和文件摘要；压缩条目不得写到目标目录之外，缺文件清单须在替换前明确。
4. 建立当前数据和文件的保护备份，恢复先在暂存目录完整准备；切换失败回滚当前配置和文件关联，原数据始终可重新打开。
5. 扩展位置迁移为数据库与受管理资料共同复制、核验后保存新位置；目标已存在同名业务数据或不可写时拒绝，不覆盖。
6. 继续识别当前程序支持的仅数据库备份：可恢复有结构支持的备份，缺失附件显示未提供；不为用户已放弃的旧演示数据或不适配旧结构重建兼容层。
7. 恢复/迁移后要求按现有流程重启再使用；附件相对路径在新目录解析，旧路径不作为隐式后备。
8. 在隔离位置验证备份、恢复、迁移、损坏文件与中途失败；T1-10新增报告实体也必须注册同一受管理清单。

## 4. 本卡不做／禁止

- 不要求用户手填绝对路径，不改变真实用户保存位置。
- 不只复制数据库而遗漏附件，不静默修复摘要不符的文件。
- 不删旧位置或保护备份来掩盖恢复失败；清理另按既有明确操作处理。

## 5. Given–When–Then 验收

1. Given：E1有PDF和XLSX附件且原目录可用。
   When：生成完整备份，在独立新目录恢复。
   Then：事件、历史、两个附件字节均一致，新位置可独立读取。

2. Given：备份某附件摘要不符。
   When：尝试恢复。
   Then：替换前拒绝或明确失败，当前数据位置及资料保持可用。

3. Given：有当前版本仅数据库备份，其中引用附件不在备份内。
   When：恢复到隔离库。
   Then：结构支持时恢复数据，并明确附件缺失，不声称完整恢复。

4. Given：目标目录已有同名数据库或复制中断。
   When：执行迁移。
   Then：不覆盖已有文件；原配置保持，临时不完整产物不被选为当前。

## 6. 需要留下的证据与完成条件

- 完整备份清单及恢复前后事件/文件摘要对照。
- 故障注入覆盖验证失败、文件复制失败、配置切换失败和回滚。
- 浏览器实际选择目录/备份与重启回读的记录，存储回归通过。
- 未执行或未通过的项标注具体缺口，不用“代码已写”代替本卡验收。
