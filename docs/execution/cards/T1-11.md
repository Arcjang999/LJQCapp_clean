# T1-11｜接入报告历史和月报处理摘要

- 原任务：任务1《失控原因分析、复测关联、附件与独立报告》
- 状态：未开始
- 类型：实现
- 前置卡：[T1-10](T1-10.md)
- 本卡交付：统一报告查询及月报事件摘要／报告引用
- 原需求锚点：[任务1](../../task_01_out_of_control_reports.md)第5节第4项、第6节；合并稿第4.5节；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.3节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

报告历史能找到独立处理报告，月报能看到异常的处理状态和相关报告。
原备注、原失控数与处理状态分别展示，不因完成处理降低原失控统计。

## 2. 必读实际文件与复用函数

- `services/report_service.py`：`list_report_history_records`、`filter_report_history_records`、`regenerate_report_from_history`。
- `pages/report_history_page.py`：`render_report_history_page`、`_render_report_history_card`；`services/search_service.py`模糊搜索。
- `services/report_service.py`：`build_lj_monthly_report_package`、`build_zscore_monthly_report_package`、两种原因措施汇总。
- `pages/lj_report_section.py`、`pages/zscore_report_section.py`、`services/report_pdf_layout.py`及既有报告历史/月报测试。

## 3. 逐步实施

1. 扩展报告历史对象识别事件报告类型，以事件和报告版本为主键导航；不把事件报告强行视作LJ或Z-score月报重生。
2. 显示报告类型、项目、仪器、原检测时间、事件状态/版本、生成时间；模糊检索复用服务，筛选使用真实身份。
3. 提供下载归档PDF、查看绑定事件版本、查看当前处理记录；“重新生成”明确基于当前内容生成新版本，不改原报告。
4. 月报按照已有正式期检测集合关联事件，Z-score按整次run汇总；显示当前处理摘要及其来源版本、独立报告引用与生成时间。
5. 原手动备注继续列为备注，结构化原因措施独立展示；同一备注不得复制成多份已完成处理。
6. 月报生成时冻结所展示的处理版本；后来事件完成或修订不回写旧月报，新月报按当前数据重新生成并保留历史。
7. 保持已有月度在控/警告/失控分母、按参数版本统计及质量要求来源；临时记录归属留任务2B/3C约定，不在此卡猜算。
8. 检验报告历史空记录、文件缺失、已停用项目和长摘要；设置变更影响新报告默认信息，旧归档PDF保持原实验室资料。

## 4. 本卡不做／禁止

- 不实现批量月报，任务3C复用本卡接口。
- 不把月报“重新生成”伪装成下载旧快照，不静默覆盖历史。
- 不改变LJ/Z-score算法、失控计数或临时记录统计规则。

## 5. Given–When–Then 验收

1. Given：9月两次失控其中一次处理完成。
   When：生成9月LJ月报。
   Then：仍计两次失控，处理摘要分别为已完成/处理中并引用对应事件。

2. Given：三水平run只一份处理事件。
   When：生成Z-score月报。
   Then：异常与处理各按一次run关联，水平证据完整不重复计数。

3. Given：旧报告文件缺失。
   When：历史页点击下载。
   Then：明确提示无法读取旧文件，不能自动生成新内容冒充旧报告。

4. Given：事件V3出月报后更新V4，实验室名称也改变。
   When：查看旧报告并显式生成新报告。
   Then：旧资料和旧摘要保留，新版本采用V4与新默认信息。
