# T1-04｜保存原因、措施与患者影响评估草稿

- 原任务：任务1《失控原因分析、复测关联、附件与独立报告》
- 状态：未开始
- 类型：实现
- 前置卡：[T1-03](T1-03.md)
- 本卡交付：可恢复的处理表单和草稿保存
- 原需求锚点：[任务1](../../task_01_out_of_control_reports.md)第2节“原因与措施／患者结果影响”、第3节；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.3节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

操作者可分次填写原因分析、措施与影响评估，离开后继续处理。
记录评估依据，不把填写表单当成患者结果获准放行。

## 2. 必读实际文件与复用函数

- `ui/out_of_control.py`、`services/out_of_control_service.py`：T1-02/03新增后复用，执行时先确认实际名称。
- `ui/dialogs.py`：现有明确保存/取消与记录详情交互；`ui/user_messages.py`：业务错误呈现约定。
- `services/report_service.py`：`_build_corrective_actions`、`_build_zscore_corrective_actions`，理解旧备注来源但不自动迁移成分类。
- 拟新增`tests/out_of_control_draft_smoke_test.py`；原因分类初始列表在本服务统一维护。

## 3. 逐步实施

1. 建立原因分类可选项和“其他”，另存自由原因分析、纠正措施、补充说明；分类只是记录标签，不自动推断原因。
2. 加入患者影响评估字段：是否需评估、影响起止时间、措施、依据/说明；不知道时允许明确待评估，不自动显示无影响。
3. 草稿允许原因或复测未齐全，但已填写的时间范围必须合法；结束早于开始、非日期等在服务层拒绝并指明字段。
4. 保存使用事件期望版本，记录处理人文本与保存时间；首次有效草稿进入处理中，重复请求不重复增加相同版本。
5. 在页面区分已保存草稿和当前未保存输入；取消提供继续填写或放弃，切换事件不能把A内容带入B。
6. 重开从持久草稿恢复，不依赖当前浏览器会话；异常刷新后不能凭空声称未提交输入已保存。
7. 修改患者评估不更新检测结果、质控判读或患者明细；任何“需评估”选项都不接入自动放行。
8. 对字符串统一去除无意首尾空格，保留长文本换行；不将代码异常或内部字段作为校验说明显示。

## 4. 本卡不做／禁止

- 不连接LIS或患者数据，不做临床结论和自动报告放行。
- 不引入账号权限、电子签名或多级审批；处理人文本明确仅为记录。
- 不通过旧备注自动判定原因或处理效果。

## 5. Given–When–Then 验收

1. Given：事件E1未填写复测。
   When：填写“试剂混匀不足”、措施和处理人后保存草稿并重启。
   Then：内容可恢复、状态处理中，原失控结论不变。

2. Given：影响范围开始09:30、结束08:30。
   When：保存。
   Then：提示核对时间范围，不丢其余输入、不新增错误版本。

3. Given：A事件有500字未保存措施。
   When：取消后选择继续填写，再切换B。
   Then：A输入仍在继续填写时保留，B不会收到A的文字。

4. Given：原结果备注含“已处理”。
   When：首次打开表单。
   Then：备注展示但状态不自动完成，患者影响仍由人明确记录。

## 6. 需要留下的证据与完成条件

- 保存草稿重启恢复、非法时间、跨事件状态隔离和重复提交测试。
- 浏览器记录输入保留与保存反馈，长中文文本完整。
- 核对原检测表和原备注未被本卡写入。
- 未执行或未通过的项标注具体缺口，不用“代码已写”代替本卡验收。
