# T4-02｜保存稳定账号身份并建立首位管理员

- 原任务：任务4《账号权限与实验室关联》
- 状态：未开始
- 类型：实现
- 前置卡：[T4-01](T4-01.md) 的认证、首次管理员与组织身份基础决策已确认
- 本卡交付：账号身份、凭据、角色关系、初始化与审计基础
- 原需求锚点：[任务4](../../task_04_accounts_and_lab_scope.md)第3节“身份与会话／角色与账号管理／旧数据”；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.2、4.6及第6节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

按已确认流程建立可识别的账号；显示姓名与真实身份分开。
第一次使用能安全建立管理员，重复启动不会产生第二位默认管理员或重置凭据。

## 2. 必读实际文件与复用函数

- `database.py`：`init_db`、`atomic_write`、`get_connection`；`migrations/__init__.py`和现有迁移登记模式。
- `services/settings_service.py`：保留实验室负责人/审核人原文本，不推断账户。
- `migrations/v1_1_master_data.py`稳定UID及字典关系模式；当前没有账户表。
- 拟新增`migrations/accounts.py`、`services/identity_service.py`和身份初始化测试；命名可随实际实现调整并回填。

## 3. 逐步实施

1. 按确认合同定义不可变账号ID/UID、唯一登录标识、显示姓名、启用状态、角色/成员关系、凭据版本及创建/修改审计；姓名改名不改变历史身份。
2. 认证采用已确认凭据方案；若为密码，选维护中的安全密码散列实现并按当时官方文档验证参数，不存明文或可直接恢复密码。
3. 首位管理员初始化只在未建立有效账号的受控状态可执行；校验合同规定的操作者条件，一次事务创建身份、角色和初始化完成标记。
4. 两个初始化请求竞争时最多成功一次；初始化失败整体回滚，不留下无凭据管理员或允许任何人再次抢建的半状态。
5. 记录账号管理审计的目标账号、真实操作者、动作、时间、前后状态及理由；凭据正文、密码散列和会话秘密不进入业务日志或UI。
6. 旧检测的录入人/确认人文本原样保留，新增可空账号引用；不能把同名文本回填成某个账号的真实操作。
7. 按选定组织范围建必要关系；仅单实验室时不要增加未确认跨实验室成员规则，若稳定实验室标识未采用则记录边界而非伪造关联。
8. 在空隔离库和当前结构副本运行迁移两次，核查UID唯一、外键、角色重复及原结果/报告资料不变。

## 4. 本卡不做／禁止

- 不硬编码默认管理员密码，不生成未告知或无法交付的万能恢复口令。
- 不向用户界面显示凭据材料、数据库字段名、代码或堆栈。
- 不实现任务5数据修改，管理员存在不代表历史直改入口可开放。

## 5. Given–When–Then 验收

1. Given：隔离库未建立账号，初始化条件已满足。
   When：完成首位管理员流程并重启。
   Then：同一稳定账号可识别，初始化不会再次开放。

2. Given：两个请求同时创建首位管理员。
   When：同时提交。
   Then：只有一个成功，另一方得到初始化已完成提示，无重复默认身份。

3. Given：旧检测录入人文本为“张三”，新账号也叫张三。
   When：执行迁移。
   Then：旧文字保留但身份引用未知，不伪称由该新账号操作。

4. Given：账号创建到一半发生错误。
   When：再次启动或重试。
   Then：没有半角色/半凭据记录，按合同恢复可继续而不绕过初始化条件。

## 6. 需要留下的证据与完成条件

- 身份关系图、凭据方案依据和初始化条件说明；不提交任何真实秘密。
- 空库/重复迁移/并发初始化/故障回滚测试。
- 历史文本、实验室默认资料与原结果前后对照一致。
- 未确认业务规则和未通过验证分别记录；不能以按钮隐藏或文档存在作为权限已生效的证据。
