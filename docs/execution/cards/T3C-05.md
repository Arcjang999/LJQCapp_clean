## 1. 目标及用户可见结果

- 按月份和项目看到检测次数、在控/失控、待处理及采用要求后的 CV 评价。
- 分母、run 粒度和不能评价的原因清楚，临时统计口径尚未定时不自创总数。

## 2. 必读实际文件与复用函数

- `services/report_service.py::_build_statistics / _build_zscore_monthly_statistics / _build_zscore_level_statistics`：单份统计口径。
- `services/quality_target_service.py::batch_quality_summary / evaluate_cv`：已采用来源及适用条件。
- 任务 1 未完成处理查询及 T2B 类型/统计合同：执行时核对实际已交付接口。
- T3C-02 稳定数据包；拟新增汇总服务，复用同一有效数据，不在页面另算临床统计。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 定义项目/月分组并列出方法、仪器、批次及期间；跨批次/参数版本不无说明合并 CV。
2. 检测次数、在控、警告和失控沿单份口径，Z-score 使用完整 run 作为最终计数单位。
3. 关联任务 1 未完成处理，区分事件数、检测次数和处理状态，不把处理完成改为原结果在控。
4. 各批/各水平 CV 评价读取采用要求及其数量、天数等条件；未采用或不足明确不能评价，不计达标。
5. 临时值保持常规 L-J 隔离；总失控及分母只在 T2B 合同明确后合并，否则分别展示已确定范围并标注未完成分支。
6. 提供汇总到单份报告/原事件的追溯，刷新或重试使用一致有效版本；T5 后续通过共同接口更新新汇总。

数据契约与状态：

- 每个指标具有分子、分母、月份、方法与批次范围；没有执行计划不生成漏做率。
- 多水平最终失控不按触发水平重复计数；各水平精密度是另外的评价维度。
- 汇总是回顾与待办信息，不构成自动月度审核、签字或患者结果放行。

## 4. 本卡不做与禁止事项

- 不把数据不足、未采用要求或过程条款无 CV 说成达标。
- 不先开发权限/更正来阻塞常规汇总，也不声称 T5 已实现报告受影响处理。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 3 水平一次 run 两水平失控；When 汇总；Then 失控检测次数为 1，各水平证据可追溯。

2. Given 未采用质量要求或仅一条有效数据；When 查看 CV 比较；Then 显示不能评价原因，不纳入达标数。

3. Given 临时总失控分母未定；When 查看常规月汇总；Then 常规口径明确可验，临时合并项不伪造数值。

4. Given 没有执行计划且一个月无结果；When 查看汇总；Then 显示无数据，不能生成质控漏做率或自动审核结论。

- 分母、月份、run 粒度及分版本 CV 的复算表，与逐份报告对照。
- 未处理事件、不能评价、临时待定/已确认两种范围的浏览器证据及 T5 接口边界。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
