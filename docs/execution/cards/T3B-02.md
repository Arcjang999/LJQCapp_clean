## 1. 目标及用户可见结果

- 可录入同一样本在旧/新试剂下的成对结果，先修正重复或缺侧问题再保存。
- 问题能定位到样本与行号，不把半对数据保存成完整比较。

## 2. 必读实际文件与复用函数

- `ui/reagent_lifecycle_workspace.py::render_reagent_lifecycle_workspace`：既有试剂入口，新增比对动作而不重做换批。
- `services/export_utils.py::xlsx_bytes_to_dataframes / dataframes_to_xlsx_bytes`：可复用模板解析与输出。
- `services/value_type_service.py::parse_project_input_value`、`database.py::atomic_write`：数值及事务。
- 拟新增 `services/reagent_comparison_service.py`、专用配对模板和增量存储；复用既有试剂主数据。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 建立比对草稿，引用准确检测系统、新旧试剂批号、方案版本和操作者记录。
2. 手工行和模板使用一致字段：匿名编号、两侧时间、旧值、新值及必要项目/单位信息。
3. 校验编号重复、缺失一侧、非有限数值、时间、单位/项目不一致和相同新旧批号。
4. 专用导入先输出逐行预览和问题列表；保留原值，不自动换单位、补一侧或按相似姓名配对。
5. 所有行满足结构条件后人工确认整批保存；方案不完整仍可保存数据草稿但不能变成已通过。
6. 使用草稿版本和提交标识防止陈旧预览、重复点击及部分写入；失败保留输入，修正后重新预览。

数据契约与状态：

- 匿名样本编号只在当前比对版本内唯一，不与患者身份系统绑定；每行必须一对值。
- 配对记录属于专门比对，不写入日常 QC 结果表，不改变常规有效点数。
- 模板格式与版本明确，导出后可恢复相同配对关系；业务字段不暴露内部主键。

## 4. 本卡不做与禁止事项

- 不要求真实姓名/证件号，不根据近似编号自动合并不同样本。
- 不将配对样本保存为质控点，不自动建立未知试剂产品或更改默认批号。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 5 个合法匿名配对；When 手工或模板预览后保存；Then 两种入口得到同一结构和原始值。

2. Given 编号重复、缺新值或单位不同；When 预览；Then 指明对应行且不保存为完整比较。

3. Given 有零值和低浓度但结构有效；When 导入；Then 保留真实零值，由后续方案评价而不伪造替代值。

4. Given 保存中断或重复点击；When 重试；Then 整批成功或整批回滚，同一提交不重复建配对。

## 6. 证据与完成条件

- 模板样例、正常/错误行预览、草稿恢复和事务失败对照。
- 原日常质控数据不变的检查，浏览器连续输入及 Enter 不丢草稿证据。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
- 执行实现或验收时仅使用独立库/明确副本，记录版本和保护范围；此次编写卡片不运行应用或数据库操作。
