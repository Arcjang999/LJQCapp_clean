# T1-03｜接通LJ与多水平异常记录入口

- 状态：未开始
- 类型：实现
- 前置卡：[T1-02](T1-02.md)
- 本卡交付：原记录进入事件详情的完整界面
- 原需求锚点：[任务1](../../task_01_out_of_control_reports.md)第2节“从原记录进入／自动带入上下文”；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.3节

## 1. 目标及用户可见结果

用户在异常记录旁打开失控处理，看到本次检测的完整依据。
从详情返回后仍定位原项目、批次和记录，不再重新寻找。

## 2. 必读实际文件与复用函数

- `pages/lj_sections.py`：`render_lj_records_section`、`render_lj_abnormal_note_quick_entry`、`build_lj_workbench_context`。
- `pages/zscore_sections.py`：`render_zscore_rule_records_overview_section`、`render_zscore_abnormal_note_quick_entry`、`build_zscore_workbench_context`。
- `ui/dialogs.py`：`build_result_select_options`、`build_zscore_run_select_options`；`ui/traceability.py`：`evaluation_tables`。
- 拟新增`ui/out_of_control.py`事件详情入口；复用T1-02事件服务，已有数据维护弹窗继续保留。

## 3. 逐步实施

1. 在LJ正式期异常记录和最新异常摘要添加统一打开动作；选择必须携带真实结果ID，不用表格行号作为身份。
2. 多水平入口以run ID进入，显示整次结论与各水平结果、规则证据、各实际批号；两个异常水平仍只打开同一事件。
3. 第一次显式进入通过服务创建或取得主记录，随后均打开既有事件；警告按钮和标题明确“警告处理”，不能改名失控。
4. 详情顶部显示检测时间、仪器、方法、输入值类型、参数版本和采用质量要求，来源为检测时快照；缺失项显示未记录。
5. 原有手动备注单列已有备注，不自动填写原因分类；异常处理与原备注维护入口保持可区分。
6. 使用已存在导航状态保存返回位置；关闭/取消详情不触发原结果维护，未保存内容按统一弹窗约定提示。
7. 来源记录已停用批次仍允许只读查看证据；不因此解锁原批次录入，是否允许继续处理按事件服务规则独立判断。
8. 复用业务错误转换和现有布局，检查窄视口长项目名；界面不得出现原始字段名、编程语言、堆栈或内部实现提示。

## 4. 本卡不做／禁止

- 不重做现有记录维护、建靶禁用恢复、试剂换批弹窗。
- 不把即时法疑似离群和建靶期维护强制变成正式失控事件。
- 不根据模糊搜索结果关联事件；导航始终使用准确记录身份。

## 5. Given–When–Then 验收

1. Given：LJ IgG结果101正式失控且已有事件E1。
   When：在结果表和最新摘要分别打开。
   Then：两入口都进入E1，返回后选中原批次和记录。

2. Given：Z-score三水平run202只有高水平触发拒绝规则。
   When：点击任一水平的处理入口。
   Then：展示一个整次事件以及全部3个水平证据。

3. Given：来源缺批号或上游项目后来改名。
   When：打开详情。
   Then：显示原快照或未记录，不以新默认值覆盖。

4. Given：即时法第3个点为疑似离群。
   When：查看维护区。
   Then：沿用现有保留/禁用流程，不出现自动正式失控事件。
