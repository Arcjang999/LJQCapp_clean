# T1-10｜生成独立失控处理PDF并冻结报告版本

- 原任务：任务1《失控原因分析、复测关联、附件与独立报告》
- 状态：未开始
- 类型：实现
- 前置卡：[T1-09](T1-09.md)
- 本卡交付：独立报告预览、PDF实体与来源版本快照
- 原需求锚点：[任务1](../../task_01_out_of_control_reports.md)第2节“独立报告”、第3节及第6节；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.3节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

从处理事件生成包含原因、措施、复测和效果的独立PDF。
每份报告绑定当时事件版本和依据，之后修改不会改变已保存文件。

## 2. 必读实际文件与复用函数

- `services/report_service.py`：月报包、`build_lj_monthly_report_pdf`、`save_lj_monthly_report_snapshot`，复用设计但不伪装成月报。
- `services/report_pdf_layout.py`：`_chunk_rows_by_height`、`_split_row_to_fit_height`、分页页眉页脚及中文字体。
- `database.py`：`create_report_export_snapshot`及`report_exports`现有月度字段约束，先设计事件报告关系再迁移。
- 拟新增`services/out_of_control_report_service.py`及对应PDF测试；T1-08/09文件管理与备份清单复用。

## 3. 逐步实施

1. 定义事件报告数据包：实验室资料快照、原检测及规则、各水平和实际批号、参数/质量要求、原因措施、复测、患者评估、效果、人员时间和附件清单。
2. 生成时锁定事件内容版本及判读引用；资料核对未完成时可预览，若允许导出草稿须明显标明处理中/草稿，绝不显示已完成。
3. 新建独立报告类型与事件版本关联，明确报告号/生成时间/文件名；现有report_month不能伪造事件月份来替代真实来源身份。
4. 先从冻结数据包渲染PDF，检查输出成功后归档实体与摘要、数据包、事件版本引用；保存失败不新增成功历史。
5. 复用分页、字体、文字换行和表格分段；长原因、多复测、多附件清单跨页完整，不能用截断文本来挤一页。
6. 报告引用附件原文件名、说明及稳定标识，不把任意附件自动合并或执行；原文技术字段映射为实验室术语。
7. 用户修改事件后另建报告版本，旧版本和PDF字节保留；历史下载读取归档实体，不能按当前资料暗中重算旧版。
8. 将报告PDF和必要快照加入T1-09完整备份，恢复后旧报告可原样下载；中文字体在目标打包环境需要另验。

## 4. 本卡不做／禁止

- 不新增通用Word模板编辑器、电子签章或患者报告放行结论。
- 不把“处理完成”替换成原检测在控，不使用今天标准改写历史。
- 不因下载按钮重复点击就自动新增报告历史；显式重新生成才创建版本。

## 5. Given–When–Then 验收

1. Given：E1完成V3，有2条复测、3份附件。
   When：预览并保存PDF。
   Then：页面与PDF内容一致，报告明确绑定V3且可再次下载原文件。

2. Given：磁盘写入失败或渲染异常。
   When：保存报告。
   Then：不出现成功报告历史，事件版本不变，提示可重试。

3. Given：原因1500字、10次复测、15附件名称含长中文。
   When：生成并逐页查看。
   Then：无截断、重叠或缺页，页眉页脚与内容可读。

4. Given：保存V3报告后事件修订V4。
   When：下载V3再生成V4报告。
   Then：两份独立保存，V3字节不变，V4标明新版本。

## 6. 需要留下的证据与完成条件

- 短/长内容PDF及逐页渲染检查，页面数据包与PDF字段比对。
- 归档失败、重复下载、事件修订及备份恢复后文件一致性测试。
- 新报告类型数据迁移和原LJ/Z-score月报回归通过。
- 未执行或未通过的项标注具体缺口，不用“代码已写”代替本卡验收。
