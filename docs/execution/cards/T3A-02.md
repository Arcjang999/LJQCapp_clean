# T3A-02｜比较记录与新旧批次数据范围

- 原任务：任务 3A：质控品新旧批号比对
- 状态：未开始
- 类型：准备、实现
- 前置卡：T3A-01（比较对象身份合同明确；切换问题可待定）
- 本卡交付：同一检测系统同产品的比较会话、观察范围及来源查询。
- 原需求锚点：[原任务 3A](../../task_03_comparisons_and_monthly_reports.md#2-3a质控品新旧批号比对)；[合并需求](../../requirements_merged_2026_09_21.md) §4.5、§6。

执行前阅读 [统一执行规则](../EXECUTION_RULES.md)。本卡是待执行范围，不表示功能已经实现。

## 1. 目标及用户可见结果

- 从现有“新旧批号比对”入口选定新旧实际批次、对应水平和期间，知道比较的是哪些数据。
- 不同批次各自保留原结果，不因建立比较记录复制或改写检测。

## 2. 必读实际文件与复用函数

- `pages/lot_lifecycle_section.py::render_lot_management`、`ui/qc_lifecycle_workspace.py::render_qc_lifecycle_workspace`：已有入口。
- `services/lot_lifecycle_service.py::source_context / context_dataframe / qc_lots_for_source`：检测系统及实际批号。
- `services/project_config_service.py::list_lot_config_items / list_lot_item_levels`：配置项和水平身份。
- 拟新增 `services/qc_lot_comparison_service.py` 及比较会话存储；不得另建产品/批号主数据。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 在现有入口增加专门比较动作，沿用已实现换批、验证和参数弹窗，不重复重做。
2. 用检测系统身份、质控产品、新旧配置项及水平映射建立会话；拒绝同批自比、跨产品或无对应浓度水平。
3. 期间按实际检测时间边界选择，显示旧/新两边候选记录数与检测日数，不要求同一时间一一配对。
4. 保存范围、记录身份、用途、阶段、参数版本和排除原因的快照/引用，使后续报告可解释当时取数。
5. 部分水平比较保留旧组合与新组合的每个实际批号、保留/替换角色及参数来源，不把表头锚定批号冒充全部材料。
6. 新增保存采用事务和版本检查；源配置或选择变更后重新预览，取消和失败不留半份比较。

数据契约与状态：

- 比较会话引用既有批次及结果；建议区分草稿、待确认、已确认，状态须与后续方案合同统一。
- 每边候选记录保留纳入/排除及理由；原质控状态不是比较界面可随意改写的字段。
- 新批记录继续属于原新批序列；比较会话不能成为另一套常规结果存储。

## 5. Given–When–Then 验收

1. Given 同系统同产品的新旧批；When 选择期间保存草稿；Then 两边记录身份与实际批号清楚且原结果数不变。

2. Given 同名但不同质控产品；When 模糊搜索选中后提交；Then 精确身份检查拒绝比较。

3. Given 三水平仅一个水平换批；When 打开范围预览；Then 每个水平的保留/替换身份与实际批号均正确。

4. Given 保存中断或期间重新选择；When 再打开；Then 不存在半份会话或沿用过期取数预览。
