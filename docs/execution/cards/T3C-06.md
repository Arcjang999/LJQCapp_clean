# T3C-06｜批量月报与主框架阶段验收

- 状态：未开始
- 类型：验收
- 前置卡：T3C-01—05 的常规 LJ/Z-score 分支完成；临时完整范围须 T2B 口径及对应分支验收
- 本卡交付：批量月报完整链、范围明确的主框架验收与任务4/5接口交接。
- 原需求锚点：[原任务 3C](../../task_03_comparisons_and_monthly_reports.md#4-3c批量月报与汇总)；[合并需求](../../requirements_merged_2026_09_21.md) §4.5—4.6。

执行前阅读 [统一执行规则](../EXECUTION_RULES.md)。本卡是待执行范围，不表示功能已经实现。

## 1. 目标及用户可见结果

- 多仪器、多项目、LJ 和2/3水平批量报告可用，单份失败能恢复且每份独立追溯。
- 常规和临时范围分别验收，常规通过不能被写成全部临时业务已完成。

## 2. 必读实际文件与复用函数

- `docs/task_03_comparisons_and_monthly_reports.md` §4—5：主验收范围及 T5 接口边界。
- `tests/lj_monthly_report_smoke_test.py`、`tests/zscore_monthly_report_smoke_test.py`、`tests/report_history_smoke_test.py`：既有基线。
- `tests/quality_report_layout_smoke_test.py`、`tests/report_pdf_assertions.py`：质量要求与 PDF 内容。
- T3C-01—05 实施证据及 T2B 临时合同；T4 身份权限和 T5 维护仍为后续阶段。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 构造多仪器、多项目、LJ、2/3水平、同月多批、空月及跨参数版本的隔离数据集。
2. 完成清单核对、批量生成、单份失败、定向重试、归档下载、历史查看及汇总追溯。
3. 与逐份生成逐项对照统计和参数/实际批号/采用要求，核对无法评价及未处理事件。
4. 解包全部成功 PDF，逐页渲染，验证中文、图例、长内容、文件名消歧和同名不覆盖。
5. 按范围分别出具常规与临时验收；待定临时口径明确未完成及责任卡，不要求先开发账号或 T5 更正。
6. 交接稳定报告/结果版本和精确身份引用给 T4/T5，说明后续更正需同步新报告且原版保留；记录主框架已验与未验范围。

数据契约与状态：

- 阶段状态必须列明范围：常规主框架可独立通过；临时分支未结不能勾为全范围完成。
- 向 T4 提供常规主框架证据与未完成清单；是否进入后续按总执行规则，不把排期当无关技术阻断。
- T5 之后新单份/批量报告共用有效结果，原报告受影响标记及更正版由 T5 接入验收，本阶段仅预留关系。

## 4. 本卡不做与禁止事项

- 不靠运行一次生成器就宣布 PDF/浏览器验收通过，不遗漏部分失败和重试。
- 不自动审核或签字，不扩展即时法月报，不宣称权限和重算已完成。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 多仪器多批次的混合 LJ/Z-score 清单；When 批量生成及下载；Then 每份与逐份生成一致，历史和文件独立。

2. Given 一份失败后重试；When 查看总历史及 ZIP；Then 成功项不重复创建，失败项恢复后独立加入。

3. Given 空月、无采用要求和分版本参数；When 看汇总；Then 排除/不能评价原因准确，不输出虚假达标或漏做率。

4. Given 临时分母仍待确认；When 记录验收状态；Then 常规通过可单独记录，临时完整范围保持待完成，不写全部已支持。

## 6. 证据与完成条件

- 需求/范围矩阵、逐份与批量复算、任务失败恢复及原业务回归结果。
- 完整浏览器、全部代表 PDF 逐页及 ZIP 解包记录；给 T4/T5 的身份/版本/缺口交接。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
- 执行实现或验收时仅使用独立库/明确副本，记录版本和保护范围；此次编写卡片不运行应用或数据库操作。

- 停止位置：完成本阶段已确认范围验收并保留待定分支，停止无关功能扩展。
