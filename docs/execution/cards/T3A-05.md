# T3A-05｜比较报告、确认与批号验证关联

- 原任务：任务 3A：质控品新旧批号比对
- 状态：未开始
- 类型：实现
- 前置卡：T3A-04；任务 1 已交付附件与报告版本接口
- 本卡交付：专门比较 PDF、不可静默覆盖的报告版本及既有质控批号验证关联。
- 原需求锚点：[原任务 3A](../../task_03_comparisons_and_monthly_reports.md#2-3a质控品新旧批号比对)；[合并需求](../../requirements_merged_2026_09_21.md) §4.5、§6。

执行前阅读 [统一执行规则](../EXECUTION_RULES.md)。本卡是待执行范围，不表示功能已经实现。

## 1. 目标及用户可见结果

- 保存比较结论后可预览并导出包含数据范围、排除理由、标准和来源的专门报告。
- 报告可作为验证依据追溯，但未完成的比较不能自动变成通过验证。

## 2. 必读实际文件与复用函数

- `services/report_service.py::save_lj_monthly_report_snapshot / list_report_history_records`：现有历史机制，比较为新报告类型。
- `services/report_pdf_layout.py`：复用中文排版及分页组件，勿把月报标题套作比对报告。
- `services/lot_lifecycle_service.py::record_lot_verification`：真实验证入口及精确系统检查。
- 任务 1 报告文件、附件及备份合同；拟新增比较报告生成器和版本关联。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 形成确认前数据包：旧/新批、范围、水平、纳入/排除、分段统计、方案、采用要求及实验室结论。
2. 确认时重新校验数据和方案版本；缺失依据、数量条件未满足或状态已变时拒绝正式通过。
3. 生成 PDF 并逐页核对完整性后保存报告历史引用；失败不声称报告已成功，也不提前写通过验证。
4. 复用既有验证入口明确记录人工结论、确认人、时间和报告版本；报告生成不能代替验证确认。
5. 修订比较数据或标准时产生新报告版本，旧版可查询；最新失败不能被较早通过记录绕过。
6. 将附件及报告文件纳入任务 1 已完成的备份/恢复机制，损坏或缺失时给可重试业务提示。

数据契约与状态：

- 比较记录版本、PDF版本、验证记录三者显式关联；报告成功与验证通过分别记录。
- 历史报告保留生成时范围、方案及统计，不依赖现目录或当前参数重新解释。
- 重复生成允许有意新版本；重复提交同一请求不得无提示制造重复历史。

## 4. 本卡不做与禁止事项

- 不自动切换质控批号；不绕过实际批号最新验证、效期及所有水平参数检查。
- 不以一个 PDF 文件存在就认定平行数据和接受依据已完成。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 完整比较及明确接受依据；When 人工确认并导出；Then PDF、历史及验证引用指向同一数据版本。

2. Given PDF 生成失败；When 查看验证记录；Then 没有新通过记录，原草稿可重试。

3. Given 已确认报告后标准被修订；When 再次生成；Then 旧报告可查，新版重新确认且没有覆盖。

4. Given 早期通过后新增失败验证；When 准备正式使用；Then 既有最新验证规则仍阻止旧通过绕行。

## 6. 证据与完成条件

- 长方案、多水平、多个参数版本及排除明细的 PDF，逐页渲染检查。
- 正常/失败/修订/重复提交、附件恢复和验证引用一致性证据。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
- 执行实现或验收时仅使用独立库/明确副本，记录版本和保护范围；此次编写卡片不运行应用或数据库操作。
