# R0-02｜目标设备缩放与安装包发布验收

- 原任务：既有发布前验收；来源：[下一阶段清单 §3](../../NEXT_SESSION_TASKS.md#3-整体验收清单)。
- 状态：待环境/待执行；本轮没有新增环境测试。
- 类型：发布验收；前置：需要验收的候选版本已完成对应阶段验收，且具备实际目标环境。
- 本卡交付：带环境和版本标识的发布验证记录。
- 公约：[逐卡执行规则](../EXECUTION_RULES.md)。

## 1. 目标

软件在目标系统、实际系统缩放和打包环境下可完成关键业务。此卡独立跟踪，不冒充新功能的本机开工前置。

## 2. 必查入口

`run_app.py`、现有打包说明/构建配置、`services/storage_service.py`、三方法页面与导入导出/报告历史；该候选版本的阶段验收交付记录。

## 3. 逐步验收

1. 记录源码提交/工作区标识、构建命令、依赖环境、操作系统、CPU架构、屏幕分辨率和真实系统缩放。带未提交代码的包需要可追溯的文件/构建记录。
2. 实机分别验证 `2560×1440 @ 100%`、`2560×1600 @ 150%`、`2880×1800 @ 200%`。缺哪一项就列哪一项待环境；截图缩放和浏览器小视口不能替代。
3. 核对首页、列表、最长弹窗、连续录入、表格粘贴、图、质量要求核对、报告和设置；核心按钮可访问，无遮挡或因滚动丢草稿。
4. 用目标Windows安装包启动独立空库，核对中文路径、首次初始化、正常退出/重启、存储目录迁移、导入导出、中文PDF及附件备份恢复（候选版含附件功能时）。
5. 运行短业务链和对应版本新增关键路径；相同源码本机通过不替代目标包通过，macOS服务包结果单列。
6. 缺陷只做对应最小修复；重新构建后重验受影响路径，不能把旧包截图作为新包证据。

## 4. 不做

- 不自动上传发布、提交或推送源码；发布动作遵循用户该次任务授权。
- 不在用户真实数据上测试安装/恢复；不将未实测写为兼容。
- 不把前期基线通过当作后续全部功能最终版本已通过。

## 5. 验收案例

R0-02-A1：给定实际200%系统缩放，打开最长管理弹窗，输入、错误提示、保存、取消均可完成，截图同时有环境记录。

R0-02-A2：给定目标Windows新安装和中文存储目录，首次启动、录入、导出中文PDF、备份恢复成功，数据引用一致。

R0-02-A3：给定某设备缺失，报告明确“未验证”，其余已测环境单独给结论，不能汇总成全部通过。

## 6. 完成证据

`docs/execution/deliveries/R0-02.md` 列出各环境/候选版本/实际结果/截图和包位置。全部指定环境完成才可标发布验收通过。

## 7. 停止位置

完成记录后停止。验收不自动触发下一功能或发布到远端。
