# T3A-03｜有效结果与分参数版本统计

- 原任务：任务 3A：质控品新旧批号比对
- 状态：未开始
- 类型：实现
- 前置卡：T3A-02；T3A-01 中本卡采用的纳入及计数口径已明确
- 本卡交付：两批各水平的有效结果、日数、均值、SD、CV及排除明细。
- 原需求锚点：[原任务 3A](../../task_03_comparisons_and_monthly_reports.md#2-3a质控品新旧批号比对)；[合并需求](../../requirements_merged_2026_09_21.md) §4.5、§6。

执行前阅读 [统一执行规则](../EXECUTION_RULES.md)。本卡是待执行范围，不表示功能已经实现。

## 1. 目标及用户可见结果

- 操作者能从结果列表复算每项统计，知道禁用、警告、失控及临时记录怎样处理。
- 不同参数阶段分别展示，不给未经依据的混合 CV 合格结论。

## 2. 必读实际文件与复用函数

- `qc_logic.py::calculate_qc_results / calculate_realtime_stats`：保留原结果和统计规则。
- `zscore_logic.py::calculate_level_target_stats / get_zscore_runs / get_building_stat_run_ids`：水平统计与 run 身份。
- `services/lot_lifecycle_service.py::report_lot_trace / target_profile`：分参数版本及来源。
- `services/cv_service.py::calculate_cv_percent`、`services/quality_target_service.py::evaluate_cv`：已有 CV 及适用条件。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 把 T3A-01 已确认纳入规则绑定比较草稿，明确建靶/正式期、禁用、警告、失控及临时用途。
2. 逐记录列出纳入标记及排除理由，保留所有候选证据，不为统计好看删除异常。
3. 按旧/新批、水平及必要的参数版本分组取有效值，分别计算结果数、检测日数、均值、SD、CV。
4. 均值为零、数量不足或参数缺失时展示不能评价原因；不造零 CV 或通过状态。
5. 读取该检测项已采用质量要求和适用条件作为各批独立评价依据；不把无 CV 的过程条款变成数值限制。
6. 记录计算输入和输出的版本关系；范围或规则变更后使旧预览失效，重算失败保留草稿及原记录。

数据契约与状态：

- 统计按各批自身浓度及参数分组，新旧均值可以不同；不能直接以其接近程度判合格。
- 20 点进度与本卡统计数是否相同须以 T3A-01 为准；没有独立分析批标识只显示日数及结果数。
- 缺少适用加权方案时跨参数版本不合并单个 CV；预览注明分段原因。

## 4. 本卡不做与禁止事项

- 不排除失控结果以自动提高通过率；不改变原记录禁用状态。
- 不把任务 0 日常 CV 要求当作新旧均值差允许值，不制定最低样本量。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 两批浓度不同但各自完整；When 统计；Then 分别展示均值和精密度，不因均值不同自动失败。

2. Given 范围包含禁用、临时和失控记录；When 核对明细；Then 按批准口径逐条纳入或说明排除，原状态不变。

3. Given 观察期有两个参数版本；When 生成统计；Then 分段清楚且无未经依据的单一合格 CV。

4. Given 仅一个有效值或均值为零；When 计算；Then 显示具体不能评价原因，不输出虚假的零 CV/通过。

## 6. 证据与完成条件

- 固定候选集、排除清单、分组统计及手工复算对照；记录有限值和数量不足边界。
- 受影响统计服务与既有算法回归，确认日常结果和历史判读没有被写回。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
- 执行实现或验收时仅使用独立库/明确副本，记录版本和保护范围；此次编写卡片不运行应用或数据库操作。
