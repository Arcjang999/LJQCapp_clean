## 1. 目标及用户可见结果

- 在同一页查看各批各水平图表、统计、参数和采用要求，再填写实验室比较方案。
- 没有明确接受标准或数据条件时清楚显示尚不能形成正式结论。

## 2. 必读实际文件与复用函数

- `ui/qc_lifecycle_workspace.py`：复用列表、详情、显式保存交互，不重造换批弹窗。
- `plotting.py::plot_lj_chart`、`zscore_plotting.py::plot_zscore_single_level`：作为可复用图表能力，保留原控制线。
- `services/quality_target_service.py::runtime_goal / batch_quality_summary`：读取实际采用版本。
- T3A-02/03 比较服务；拟新增比较预览区块及方案校验，不在页面内堆放计算。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 并列显示旧/新批的日期范围、各水平实际材料、结果/日数、统计及参数来源。
2. 图表按各自尺度和参数注明轴、单位、浓度水平及版本边界，避免视觉上暗示均值必须重合。
3. 方案保存用途、依据、最低数据条件、接受标准和人工结论说明；条件数值由适用方案给出。
4. 校验方案适用的产品、检测系统、单位和评价指标；引用标准须核原文及适用范围，不能只写文号。
5. 方案或纳入集修改后保留草稿修订并重新计算预览；已确认版本不被静默覆盖。
6. 缺条件或渲染失败时保留可恢复草稿，定位需补内容；可以看统计，但不能生成虚构通过状态。

数据契约与状态：

- 方案与比较数据版本绑定，至少可区分观察性比较与具有明确接受标准的正式评价。
- 旧/新批各自评价；若方案另有要求，须显式记录依据和适用条件，不能泛化成全项目规则。
- 界面显示业务结论，不显示内部序列标识、开发注释或原始异常。

## 4. 本卡不做与禁止事项

- 不套用患者配对差异算法；不把质控材料不同浓度当成异常。
- 不宣称完成暂定/常用参数制度、短稳定性质控方案或长期加权 CV。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 数据充足且方案明确；When 预览；Then 图表、统计、接受标准及适用范围可逐项核对。

2. Given 方案没有最低数据条件；When 尝试确认结论；Then 指出缺项，仍允许保留观察草稿。

3. Given 改了观察期或标准；When 再打开预览；Then 显示新版本并要求重新确认，旧确认不沿用。

4. Given 长方案文字和三水平；When 在 200% 缩放查看；Then 内容可读，水平和控制线图例不遮挡。

## 6. 证据与完成条件

- 方案校验案例及正常/不足/修订的页面记录；保存可复算比较预览。
- 记录标准原文来源及对应接受条件；无来源的临床阈值不得作为本卡默认配置。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
- 执行实现或验收时仅使用独立库/明确副本，记录版本和保护范围；此次编写卡片不运行应用或数据库操作。
