## 1. 目标及用户可见结果

- 操作者核对配对与条件后保存实验室结论、说明、确认人和时间。
- 比较完成不自动切换默认试剂，后续验证仍检查最新结论和适用条件。

## 2. 必读实际文件与复用函数

- `services/lot_lifecycle_service.py::record_lot_verification / switch_reagent_lots`：验证与切换是两个动作。
- `services/reagent_lifecycle_edit_service.py::save_reagent_verification / save_reagent_switch / build_reagent_switch_preview`：既有操作契约。
- `ui/reagent_lifecycle_workspace.py`：复用验证/切换入口，不另建第二套状态。
- T3B-02/03 数据及计算版本；拟新增比对确认与验证关联函数。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 确认页并列显示两批身份、配对数量、浓度分布、采用方案、逐对结果和整体条件。
2. 要求实验室结论与依据明确；尚不能评价或方案缺项时可保存说明，但不能提交自动通过验证。
3. 确认时核对输入/方案版本仍与预览一致，防止看到旧结果却确认新数据。
4. 通过既有验证服务关联精确系统、新试剂批号及本次比对版本，记录人工确认信息。
5. 保存结论失败整次回滚，不留比较已确认而验证来源缺失的假成功；需要重试时保留可核对草稿。
6. 保留既有人工换批入口，比较后仅提供可用的关联依据；不自动修改默认批号或历史实际试剂。

数据契约与状态：

- 计算评价、实验室结论、验证记录和默认使用状态分离，关系可追溯。
- 历史通过不能覆盖之后失败；切换继续使用生效时间前最新适用验证规则。
- 配对/方案变更形成新版本并需重新确认，旧确认记录不被静默复用。

## 4. 本卡不做与禁止事项

- 不为不完整方案生成“通过”，不把人工说明改写成自动算法结果。
- 不修改已有试剂使用事件更正，也不更正旧日常检测的实际批号。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 完整且可评价的比较；When 人工保存结论；Then 验证关联精确新批号与版本，默认批号保持原值。

2. Given 用户预览后配对被修改；When 确认；Then 要求重新核对，拒绝陈旧版本。

3. Given 较早通过后又有失败验证；When 从原通过比对进入切换；Then 不能绕过最新验证检查。

4. Given 写验证时失败；When 查看比较及批号；Then 没有半成功确认，重试不会自动切换。

## 6. 证据与完成条件

- 确认与拒绝案例、版本冲突及验证关联测试；实际页面展示两种状态独立。
- 检查默认试剂使用事件和旧检测实际批号未因比较保存改变。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
