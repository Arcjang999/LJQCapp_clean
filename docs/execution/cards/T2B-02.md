## 1. 目标及用户可见结果

- 同日多次临时检测各自保留，能追溯当时的仪器、检验项目、实际批号和参数。
- 常规与临时类型稳定区分，不依赖显示开关或自由备注判断。

## 2. 必读实际文件与复用函数

- `database.py::atomic_write / get_results / get_zscore_runs_with_levels_for_batch`：既有事务与结果身份。
- `services/lot_lifecycle_service.py::record_result_context / append_evaluation / require_writable`：原子保存及来源校验。
- `migrations/v1_2_lot_lifecycle.py`：来源、水平、参数及判定版本表关系。
- 拟新增 `services/temporary_qc_service.py` 与增量迁移；名称为实施建议，先核实 T2 已验收接口。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 盘点已有结果和完整 run 身份，选择增量类型字段或关联结构；形成一个明确模型，不并建第二套批号体系。
2. 定义临时主记录与水平明细、质控批次、检测时间、实际试剂、参数版本、原因及判读快照关系。
3. 使用稳定身份和精确外键核验；名称模糊搜索仅帮助选择，不能把相似项目或批号自动合并。
4. 同日多次记录以独立业务身份区分；保存尝试标识仅防重复提交，不能按日期和值去重真实复测。
5. 在一个事务内保存结果、类型、来源、水平和必要状态；中途失败整次回滚，不留无类型结果。
6. 提供类型明确的查询及常规数据排除入口；默认值只适用于明确常规的新录入，不猜填历史临时原因。

数据契约与状态：

- 临时主记录可独立存在，不强制关联当日常规记录；多水平明细必须组成完整 run。
- 建议状态区分草稿、已记录待判读、已判读；采用前须与 T2B-01 及 T2 数据契约统一。
- 判读引用原检测参数及版本；缺少来源保留“未记录/待核对”，不借当前默认值补造。

## 5. Given–When–Then 验收

1. Given 没有常规记录的空日期；When 保存一个合法临时对象；Then 独立主记录与来源可查询。

2. Given 三水平保存第三个水平时失败；When 事务结束；Then 不存在半个 run 或孤立来源。

3. Given 同日同值连续两次真实检测及一次重复提交；When 保存；Then 保留两次业务记录，重复提交只返回原结果。

4. Given 当前默认试剂已切换；When 查看先前临时记录；Then 仍显示原检测实际批号和参数引用。
