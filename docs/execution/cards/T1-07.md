- 原需求锚点：[任务1](../../task_01_out_of_control_reports.md)第2节“查询”；合并稿第4.3—4.4节；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.3节

## 1. 目标及用户可见结果

按时间、项目、仪器和处理状态找到未完成事项或历史，直接继续处理。
任务2以后调用同一待处理接口，避免各页面各算一套事件数量。

## 2. 必读实际文件与复用函数

- `services/search_service.py`：`fuzzy_match`、`filter_frame`；复用现有全软件检索规则。
- `app.py`、`pages/main_page.py`：现有导航；`pages/report_history_page.py`筛选/返回交互。
- T1事件服务：准确事件ID、当前版本和状态；拟新增`pages/out_of_control_page.py`。
- 拟新增待处理查询合同及`tests/out_of_control_query_smoke_test.py`；未来任务2B/5只消费明确接口。

## 3. 逐步实施

1. 提供事件列表读取服务，返回事件ID、来源类型、检测时间、项目/仪器快照、原结论、当前状态、最后处理时间和报告引用；尚无事件的正式期失控合并为待处理候选，事件ID留空并带准确来源键，打开时才去重创建，不在查询中写库。
2. 明确默认按原检测时间筛选，处理中跨月仍可通过状态查到；需要按处理时间时另设明确选项，不能混成一个日期。
3. 文字搜索复用模糊服务，状态/日期/项目真实ID精确过滤；同名仪器显示可区分的业务信息，不把搜索相似度当权限或身份。
4. 一个Z-score run计一个待处理事项；“待处理数量”排除已完成，包含未建事件的正式期失控及已有待处理/处理中/待确认，按来源去重。警告只有显式发起后进入处理队列，并单独标明种类。
5. 行操作统一打开原记录、继续处理、查看附件和报告；原配置停用仍可查历史，缺文件/来源时给业务提示而非崩溃。
6. 为任务2给出只读待处理列表和数量接口；为任务2B预留记录用途来源适配；当前未实现的临时结果不得伪造显示。
7. 为任务5声明原判读引用与最新判读引用关系，不在本卡写重算或修改检测；后续新版本应能提示差异而不删除事件。
8. 列表空结果和返回恢复筛选均有明确反馈；UI只使用业务词汇，不显示内部来源键、代码和开发计划。

## 5. Given–When–Then 验收

1. Given：9月失控事件E1到10月仍处理中。
   When：选择全部日期和处理中。
   Then：可查E1；切9月按检测时间过滤仍可查，计数口径明确。

2. Given：三水平失控run有3个水平证据，但尚未打开处理记录。
   When：先查待处理列表，再打开并保存草稿后重查。
   Then：前后均只计一项；第一次为待处理候选，打开后关联唯一事件，全部水平可见。

3. Given：用户搜索“免球蛋白”。
   When：使用文字搜索后按仪器A筛选。
   Then：遵循已有模糊规则找到IgG相关事件，准确仪器过滤不混入B。

4. Given：原记录配置已停用、附件文件缺失。
   When：打开历史行。
   Then：来源证据可读，附件说明缺失；没有技术异常页面。
