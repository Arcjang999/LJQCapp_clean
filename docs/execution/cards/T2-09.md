## 1. 目标及用户可见结果

- 缺水平、质量来源、人工参数或使用验证时直达原设置入口，完成后回到未丢失的日常草稿。
- 日常结果文件有模板、预览、行号错误和明确身份；与配置文件及未来临时记录分开。

## 2. 必读实际文件与复用函数

- `ui/project_navigation.py`：`open_project_setup`；`ui/batch_workspace.py`及`ui/quality_applicability.py`原批次确认入口。
- `import_review.py`：现有LJ/Z预览和列构建；`services/lot_lifecycle_service.py`：`review_import_lots`、`import_reviewed_results`。
- `database.py`：`export_batch_results`；`pages/zscore_sections.py`：`build_zscore_phase_export_dataframe`。
- 拟新增批量结果文件适配层；实际保存统一调用T2-06/07，T2B与T5只写消费合同。

## 3. 逐步实施

1. 把每种阻断原因映射到原批次/质量来源/参数/使用验证入口，携带配置项ID、返回上下文和草稿ID。
2. 设置返回后重新加载revision并重新预校验；质量来源已确认不等于参数和使用状态已确认，不能用一个“启用”按钮吞并。
3. 已启用批次的质量采用保持只读；缺口按现有规则处理，不为日常快捷入口打开冻结资料编辑。
4. 批量结果模板至少含仪器/检测项、实际材料批次/水平、实际试剂、时间、操作者、值、输入尺度和记录类型；往返所需稳定ID放兼容结构中，界面和业务表头不铺开发字段解释。
5. 保留现有单项LJ/Z导入，新增整组适配复用解析/预览口径；即时法需经现有save_instant_result对应校验，不能假定现有import_reviewed_results已支持。
6. 导入预览明确源文件行号和对应项目/水平；未知或模糊身份要求明确映射，文件变更后重新预览，取消不写入。
7. 整组结果导入复用同一冻结请求、全组事务与幂等回执；失败保留文件/草稿，不走另一套循环保存。
8. 导出当前有效结果，标明仪器、项目、批号、水平、输入类型及记录用途；内部值routine，对用户显示“常规质控”；Z保留完整检测归组，不能混为配置模板。
9. T2B未验收前不开放可保存的伪临时入口；登记未来临时独立入口/类型过滤合同，以及T5结果版本更新后总览/导出失效刷新合同。

## 4. 不做与禁止

- 不重做质量目标页或新增独立“批次采用要求”页，不恢复推荐顺序横幅。
- 不实现临时质控算法、权限、误录更正或历史补录，后续合同不冒充完成。
- 不让导入跳过任务0核对或结果事务，不把既有仅LJ/Z导入描述成三方法已支持。

## 5. Given–When–Then 验收

1. 场景 1
   - Given：日常草稿有20项但一项质量来源待核查
   - When：去原入口确认后返回
   - Then：草稿仍在、该项重新校验，其他参数/使用缺口仍分别显示。
2. 场景 2
   - Given：已启用批次使用SD型要求
   - When：从日常入口查看本批次质量目标
   - Then：保持只读并显示SD条件，不显示成统一CV或允许快捷改值。
3. 场景 3
   - Given：结果文件包含第8行错误批号及不完整Z run
   - When：预览后尝试导入
   - Then：准确定位行/水平并整组零写入，文件和草稿可继续修正。
4. 场景 4
   - Given：同文件成功后重试并导出Z及即时法记录
   - When：核对回执和导出
   - Then：不重复写入；导出有正确身份/类型，未来临时与维护功能不被宣称已完成。
