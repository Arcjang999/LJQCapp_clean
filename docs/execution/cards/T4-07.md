# T4-07｜验证身份恢复并交付任务5授权合同

- 原任务：任务4《账号权限与实验室关联》
- 状态：未开始
- 类型：实现
- 前置卡：[T4-06](T4-06.md)；T4-01恢复规则已确认
- 本卡交付：带身份的备份恢复、会话撤销和任务5接口说明
- 原需求锚点：[任务4](../../task_04_accounts_and_lab_scope.md)第3节“任务5对接／旧数据与备份”、第4—5节；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.2、4.6及第6节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

按已确认方案恢复业务资料和账号关系后，旧会话不能继承过时权限。
任务5可取得真实身份、准确授权范围和操作审计能力，而无需另建账户体系。

## 2. 必读实际文件与复用函数

- `services/storage_service.py`：`create_database_backup`、`restore_database_from_backup_file`、`migrate_database_to_directory`；实施时同时读T1-09增量。
- T4身份/授权服务及T1事件版本；T2/T3新增业务操作的人员记录。
- `database.py`：事务和配置切换；`tests/storage_smoke_test.py`现有恢复验证。
- 拟新增`tests/account_restore_smoke_test.py`及任务5身份权限接口合同。

## 3. 逐步实施

1. 把账号、角色、实验室关系与审计随完整数据库/文件备份保留；凭据材料不导出为明文账号清单，备份读取/恢复按权限矩阵检查。
2. 恢复前确认执行人有恢复权限并按已确认恢复合同处理无人可登录场景；不为了恢复方便提供未认证通用入口。
3. 恢复到暂存位置校验账号唯一、角色引用、管理员可恢复条件和实验室关系，任一失败不切换当前数据。
4. 恢复/迁移成功后刷新应用身份有效期标识并撤销既有会话，不能恢复备份里的旧登录状态；重新登录读取恢复后的角色。
5. 历史未记录账号的文本保留未知身份；T1既有处理人/确认人文本不凭同名匹配升级为已认证签名，新动作可另外保存真实账号引用与当时姓名。
6. 给任务5定义取得当前身份、检查动作/资源范围、保存真实操作者、事务内再次校验和权限失败返回的合同；示例动作覆盖更正、补录、排除。
7. 说明管理员授权成功并不等于维护成功：任务5必须完成原记录保留、影响评估、重算与事务提交后才可反馈成功；本卡不实现这些算法链。
8. 用隔离备份模拟账号被撤权前后、停用后和实验室改名后恢复，确认所有陈旧页面和批量预览失效。

## 4. 本卡不做／禁止

- 不把旧备份权限当作当前会话继续有效的依据。
- 不提供绕过认证的恢复后门，不假定联网账号或许可证绑定已确认。
- 不在本卡开放历史直改或把任务5重算留成“稍后再做”的半交付。

## 5. Given–When–Then 验收

1. Given：备份含管理员M、普通A及两个附件。
   When：按合同恢复到隔离位置再登录。
   Then：身份/角色/附件关系一致，恢复前会话全部失效。

2. Given：备份角色引用损坏或无合法管理恢复路径。
   When：执行恢复校验。
   Then：切换前拒绝，当前可用数据和账号未被替换。

3. Given：历史处理人文本张三，新账号同名。
   When：恢复并查看T1旧报告。
   Then：显示旧文本和身份未记录，不伪造账号签名。

4. Given：任务5试调用更正授权，操作者只有普通角色。
   When：请求准确结果101的维护权限。
   Then：统一拒绝并给业务原因，任务5不需要另写角色判断。

## 6. 需要留下的证据与完成条件

- 账号/角色/范围/附件恢复对照与会话失效记录。
- 权限接口文档包含真实身份来源、动作枚举、资源对象和失败返回。
- 角色撤销、旧预览恢复后提交及非法备份的故障测试。
- 未确认业务规则和未通过验证分别记录；不能以按钮隐藏或文档存在作为权限已生效的证据。
