## 3. 逐步实施

1. 将已确认项单列：普通账号不可直接修改历史；管理员使用后续更正/补录/排除流程；真实身份不依赖操作者姓名；实验室设置复用原入口。
2. 给出需要用户确认的范围选项：当前单实验室多账号，或多实验室及成员归属；是否跨实验室账号、谁可维护实验室资料分别决定，不能从“共用”推导多租户。
3. 列出首次管理员建立及遗失凭据或全部管理员不可用时恢复的业务流程选项；可以给方案和代价，未有答案的业务范围明确标待定。密码安全存储、局部接口和会话实现等工程细节由开发者依据已选流程落实，不另加逐项批准门槛；退出/停用/撤权后旧会话不可继续受限写入已是明确要求。
4. 建立操作矩阵：当前录入、草稿、建靶保留/禁用、配置、备份/恢复、历史结果更正/补录/排除、批量导入、报告生成和账号管理；区分历史结果维护与既有试剂使用事件更正。
5. 普通账号的历史补录范围仍待明确，不能因普通录入允许就开放回填；按检测时间补录、当前时间录入但旧批次等边界都给具体场景供确认。
6. 软件使用许可未获明确要求时直接记录不进入本阶段，不为这一排除项额外追问；不实现付费、联网激活、订阅、设备绑定或云服务。
7. 确定最小阻塞关系：认证/首次管理员方案未决阻塞T4-02/03；角色矩阵未决阻塞相关T4-05入口；多实验室未选不阻塞已明确单实验室分支；恢复未决阻塞恢复交付及最终验收。
8. 对每个决定保存用户原话/日期或明确批准记录、影响卡及开放问题；仅凭本执行卡文本、实现者偏好或已有负责人文本不能变为已确认。

## 4. 本卡不做／禁止

- 不创建账号、数据库表或真实初始密码，不运行应用。
- 不把建议单实验室、管理员恢复或许可方案写成已确认需求。
- 不要求任务5先实现；管理员更正权限合同与具体更正/重算业务分开。

## 5. Given–When–Then 验收

1. Given：用户只确认普通/管理员两类账号，未确认多实验室。
   When：形成合同。
   Then：多实验室标待定，不创建租户模型或每日实验室选择需求。

2. Given：“授权账号”含义仍未说明。
   When：评审软件许可分支。
   Then：不出现付费/激活已决定的结论，只阻塞确需该分支的工作。

3. Given：首次管理员与凭据恢复尚无答案。
   When：计划进入账号持久化和发布验收。
   Then：明确相关阻塞，先完成可独立的入口清单/权限场景，不偷偷设万能密码。

4. Given：用户明确单实验室、管理员维护账号，但普通补录未定。
   When：拆分后续工作。
   Then：已确认分支可推进，历史补录仍关闭并列待定，不扩大为普通账号全禁或全放。
