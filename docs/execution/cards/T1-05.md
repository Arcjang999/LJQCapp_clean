# T1-05｜关联准确的后续复测并显示批号参数差异

- 原任务：任务1《失控原因分析、复测关联、附件与独立报告》
- 状态：未开始
- 类型：实现
- 前置卡：[T1-04](T1-04.md)
- 本卡交付：复测候选、选择、差异说明与版本化关联
- 原需求锚点：[任务1](../../task_01_out_of_control_reports.md)第2节“复测关联”、第3节及第6节；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.3节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

用户明确选择哪些后续检测用于说明处理效果。
复测换批号、换参数时显示差异并要求说明，避免把无关在控结果当证据。

## 2. 必读实际文件与复用函数

- `services/lot_lifecycle_service.py`：`source_context`、`context_dataframe`、`target_profile`及`qc_detection_systems`身份。
- `database.py`：`get_results`、`get_zscore_runs_with_levels_for_batch`、`get_zscore_run_with_levels`。
- `services/search_service.py`：`fuzzy_match`仅用于候选文字检索；T1事件服务负责准确关联校验。
- 拟新增事件服务的复测候选/关联方法及`tests/out_of_control_retest_smoke_test.py`。

## 3. 逐步实施

1. 按事件准确检测系统枚举原检测之后的记录；跨批次可候选，但仪器、检测项、方法、单位和输入类型须是同一已核身份。
2. 候选显示日期时间、数值、质控/试剂批号、参数版本、各水平及原判读；按实际检测时间排序，稳定ID作选择值。
3. 同一时间缺可靠先后顺序时不推定为后续；使用已有检测序号时必须属于同一序列且有明确信息，否则要求选择更晚记录。
4. 选择提交时服务重读目标，不相信UI过滤结果；拒绝关联事件自身、早于原结果、其他仪器同名项目或已失效目标。
5. 比较原事件与复测的实际批号、参数版本、水平组合；不同项逐项显示，要求填写差异原因才保存关联。
6. 保存复测稳定ID和当时判读版本快照；一次关联多条在同一事务内提交，同一条重复选择合并为一个关系。
7. 取消复测关联仅新增关系变更历史和原因，不删除原检测；已完成事件关联变更通过新内容版本处理。
8. 保留复测失控结果作为真实证据，不能只允许在控候选；新增在控结果不自动选择或完成事件。

## 4. 本卡不做／禁止

- 不通过项目名称模糊相似直接建立关系，不把同一质控品视为同一检测系统。
- 不把复测保存为更正或覆盖原值；历史更正由任务5完成。
- 不修改参数、批号使用状态或现有连续规则窗口。

## 5. Given–When–Then 验收

1. Given：IgG仪器A09:00失控，09:30同系统复测在控。
   When：明确选择09:30记录保存。
   Then：关联成功但事件不会自动完成，保存原判读版本引用。

2. Given：同名IgG仪器B09:40在控。
   When：伪造其ID直接调用关联服务。
   Then：服务拒绝，事件及原关联没有变化。

3. Given：同系统新批号/参数V2的10:00结果。
   When：不填差异说明提交，再补说明提交。
   Then：第一次拒绝且保留输入，第二次保存并同时展示原V1与V2。

4. Given：多水平run有3个水平，用户连续两次点同一复测。
   When：提交同一请求。
   Then：只关联一次完整run，各水平证据齐全。
