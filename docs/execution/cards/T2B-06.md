- 原需求锚点：[原任务 2B](../../task_02b_temporary_qc.md) §1—6；[合并需求](../../requirements_merged_2026_09_21.md) §4.4、§6。

执行前阅读 [统一执行规则](../EXECUTION_RULES.md)。本卡是待执行范围，不表示功能已经实现。

## 1. 目标及用户可见结果

- 临时失控可直接打开同一套处理流程；重复打开仍是同一事件。
- 同日多次临时检测分别保留，后续复测在控不会覆盖原失控或自动结案。

## 2. 必读实际文件与复用函数

- `docs/task_01_out_of_control_reports.md` §2—3：事件与复测合同；执行时读取其实际已交付服务。
- `ui/traceability.py::evaluation_tables`、`services/lot_lifecycle_service.py::context_dataframe`：原判读及来源展示。
- `pages/zscore_sections.py::_build_zscore_run_records_dataframe`：完整 run 的可见证据。
- T2B-02/04 临时稳定身份和评价版本；拟新增事件来源适配，不再新建独立临时失控系统。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 将临时记录身份和判读版本接入任务 1 原事件入口；唯一关系按记录或完整 run 定义。
2. 自动带入临时类型、变动原因、原值、批号、参数和触发规则，变动原因不能自动等同失控原因。
3. 复测候选来自同一检测系统的后续检测，明确临时/常规类型；跨批号或参数须显示差异并说明。
4. 拒绝无关项目、早于原事件的检测及不完整 run；模糊搜索命中后仍按真实身份校验。
5. 保存原因、措施和效果使用任务 1 的状态规则；原检测不更新为在控，完成仍须人工确认。
6. 模拟事件保存失败及重复点击，保持检测已经保存的事实，重试只补事件关联，避免重复造检测。

数据契约与状态：

- 一个临时 run 对应一个原事件，水平证据为明细；复测为新记录引用，不替换原值。
- 事件状态与质控结论分离；待处理、处理中等沿用任务 1，禁止临时再造一套词汇。
- 后续任务 5 使用同一稳定身份识别更正影响；本卡不提供历史修改授权。

## 4. 本卡不做与禁止事项

- 不复制附件、报告、处理状态实现；不擅自把跨类型复测当成等效，需要按已确认关联条件核对。
- 不将复测在控自动解释为患者结果可放行或原异常不存在。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 同一临时失控记录；When 连续两次打开处理；Then 进入同一事件且不重复创建。

2. Given 原临时失控后有两次复测；When 第二次在控并被关联；Then 三条检测都保留，事件须人工确认完成。

3. Given 搜到同名但不同仪器的结果；When 选择复测；Then 拒绝错误系统关联，原草稿不丢。

4. Given 临时三水平 run 仅一水平触发；When 开始处理；Then 只有一份事件并展示三个水平证据。

## 6. 证据与完成条件

- 临时→事件→原因措施→复测→人工确认的完整浏览器记录。
- 核对重复打开、关联失败后检测/事件数量及原判读不变，复用任务 1 的相关回归。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
- 执行实现或验收时仅使用独立库/明确副本，记录版本和保护范围；此次编写卡片不运行应用或数据库操作。
