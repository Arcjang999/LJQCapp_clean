# T2A-05｜产品覆盖项与在用检测项关联

- 原需求锚点：[任务 2A](../../task_02a_master_data_and_catalog.md) §2质控品独立入口、产品目录；[面聊确认](../../2026_09_21_iqc_meeting_requirements.md) §1—2

遵循 [统一执行规则](../EXECUTION_RULES.md)；本卡未授权超出原任务的新功能。

## 1. 目标及用户可见结果

- 在已有质控品页面可查看产品支持哪些检测项，以及本机哪些仪器和项目正在使用。
- 可靠目录关系与本地人工关联分开标明，供panel带入和日常录入稳定查询。

## 2. 必读实际文件与复用函数

- `pages/master_data_page.py`→`ui/material_catalog.py`：`render_material_catalog`。
- `services/material_catalog_service.py`：`get_material_product`、`get_control_material`。
- `services/project_config_service.py`：`list_project_templates`、`list_template_items`、`list_lot_config_items`。
- 消费T2A-04目录合同；拟新增产品—检测项覆盖关系服务，不以md_test_items名称代替关系。

## 3. 逐步实施

1. 定义覆盖关系键product_id+test_item_id，附来源版本/记录键或本地确认人、依据和确认时间；是否方法限定按实际资料保存。
2. 在原产品详情增加覆盖项区和在用项目区；在用关系从现有模板/批次外键查询，不另造第二套在用项目表。
3. 搜索检测项复用search_service；选择后固定test_item_id，名称相似或同缩写项目必须人工明确选择。
4. 从正式目录带入时保存来源关系；本地补充要求记录依据，不冒充厂家声明。
5. 保存覆盖项采用版本检查和事务；重复同一关系返回既有结果，删除改为停止未来推荐而保留历史来源。
6. 按仪器/大项目展示在用检测项、配置项ID和当前资料状态；停用关系不出现在新建推荐中。
7. 新建空项目无覆盖/人工关系时显示尚未关联，不通过名称推断一组检测项。
8. 取消回到原产品及搜索位置；失败保留已勾选草稿，保存成功后重读关系而非仅更新界面计数。
9. 暴露稳定ID查询给T2A-06/07，输出覆盖来源和在用关系两个集合，调用方不得混为同一个概念。

## 4. 不做与禁止

- 不重复建立质控品独立页面，扩展已有入口。
- 不因产品覆盖了检测项就自动确认质量目标、方法或单位。
- 不硬删在用关系，不把产品更新回写已保存的批次/结果。

## 5. Given–When–Then 验收

1. 场景 1
   - Given：产品目录确认覆盖18项
   - When：保存并重新打开产品
   - Then：18个稳定检测项关系可重现且显示来源；相同名称不同ID不被合并。
2. 场景 2
   - Given：本地人工关联某项但厂家资料未包含
   - When：查看覆盖项与在用项目
   - Then：清楚区分本地依据，不能显示为厂家官方覆盖。
3. 场景 3
   - Given：用户勾选后发生版本冲突
   - When：尝试保存再取消
   - Then：服务拒绝旧版本，草稿不丢；取消后数据库关系不改变。
4. 场景 4
   - Given：空项目没有覆盖资料且相似名称很多
   - When：打开整组带入入口
   - Then：不自动勾选相似项目，明确没有可靠关联。

## 6. 证据与完成条件

- 提供产品→覆盖项→在用仪器/项目的查询样例和界面证据。
- 用重复保存、停用、恢复/重选及资料版本冲突验证关系一致性。
- 所有失败场景须核对保存前后记录数和业务关联，不能只截图错误提示。
- 验收仅使用独立数据库；保留本卡结果、未通过项及可复现操作。
