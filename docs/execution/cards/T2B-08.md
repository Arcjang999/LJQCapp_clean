## 1. 目标及用户可见结果

- 以真实业务路径证明临时质控可独立使用，并能明确追溯每一次检测。
- 把已确认合同与实际界面、统计、报告逐条对应，发现缺口后退回责任卡。

## 2. 必读实际文件与复用函数

- T2B-01 决策记录及 T2B-02—07 实施证据；核对没有待定规则伪装默认实现。
- `tests/lj_v12_integration_smoke_test.py`、`tests/zscore_v12_integration_smoke_test.py`：沿用实际来源场景。
- `tests/report_history_smoke_test.py`、`tests/storage_smoke_test.py`：报告历史及恢复基础。
- `docs/task_02b_temporary_qc.md` §5：阶段验收原文；新增临时用例位置以实际交付为准。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 建立可复算隔离样本：空日期、同日多次、LJ、2/3 水平、缺参数、失控及正常复测。
2. 沿独立入口和常规变动入口分别完成录入、查看判读、隐藏图面、打开处理及人工完成。
3. 比较临时值加入前后及开关切换前后的常规统计和规则序列，逐项核对批准窗口合同。
4. 验证缺水平、陈旧批号、计算/保存失败、重复提交及重试都不产生假成功或重复对象。
5. 执行交换、备份恢复、单份报告及长原因界面的验收，检查类型及关系不丢失。
6. 整理阻断项和通过证据，明确哪些接口供 T3A/T3C/T5 使用；只有所有必需分支通过才交付阶段。

数据契约与状态：

- 验收按检测类型、方法、水平及失败类别分层，不能以页面打开代替完整业务通过。
- 任何未确认窗口、总失控或分母仍存在时，阶段状态只能是待完成。
- 阶段通过只涵盖临时业务；任务 4 权限和任务 5 更正重算仍是后续交付。

## 4. 本卡不做与禁止事项

- 不通过改临床阈值或跳过来源验证让测试通过；不改真实库。
- 不把即时法原有通过证据当作临时质控完成证据。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 完整正常场景；When 按两条入口完成录入到报告；Then 每次临时检测独立保存、判读和追溯。

2. Given 参数缺失或保存失败；When 检查 UI 与数据；Then 没有在控假结论和半份记录，修正后能重试。

3. Given 极端临时值和不同显示状态；When 比较常规统计；Then 有效点数、均值、SD、CV及批准序列完全一致。

4. Given 仍有月报分母未确认；When 提请阶段通过；Then 阻止完成并准确列明只待该分支，不谎称全任务完成。

- 记录原算法保护结果、当前版本及验收环境；向下一阶段提供稳定类型/参数/事件/报告契约。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
