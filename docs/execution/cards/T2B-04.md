## 1. 目标及用户可见结果

- 每次临时检测可查看独立结论、触发证据、采用参数及不能评价的原因。
- 连续规则所用记录范围与已确认业务合同一致，不由页面隐式决定。

## 2. 必读实际文件与复用函数

- `qc_logic.py::calculate_qc_results`：LJ 计算入口；不得改公式来迁就临时类型。
- `zscore_logic.py::evaluate_zscore_run_with_phase / evaluate_zscore_run / should_enable_formal_rules`：完整 run 评价。
- `services/lot_lifecycle_service.py::target_profile / append_evaluation`：按检测时间选参数、追加判读快照。
- T2B-01 决策及 T2B-02 服务；拟新增临时上下文适配函数，保留既有算法入口。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 把已确认合同转成可核对的输入窗口规则，列明临时前序、常规前序、版本分界和检测顺序。
2. 按检测时间解析适用参数，不接受属于其他批次或未来生效的参数；缺失时返回待核对。
3. 构造独立评价输入，调用适用的既有算法；若当前引擎不能表达合同，先记录适配缺口，不改规则凑结果。
4. 多水平提交完整 run，保存整体结论以及各水平数值、标准化结果和触发证据。
5. 将输入记录身份、参数版本、规则范围及结论作为同次评价快照保存，重复点击不追加相同判读。
6. 模拟计算失败：不报告已判读成功；保留可定位的待判读状态和恢复入口，重试按同一输入重新验证。

数据契约与状态：

- 临时判读的结果身份始终指向 T2B-02 对象；常规判读快照不被覆盖。
- 可评价结论、缺少条件、计算失败三类状态明确分开；失败的详细技术信息仅进日志。
- 窗口规则未确认时该分支保持未完成；其他方法已确认分支可以分别验收，整任务仍不算完成。

## 4. 本卡不做与禁止事项

- 不发明临时万能单点阈值，不擅自清空或引入常规历史。
- 不将未建靶、缺参数、无有效规则解释成在控；不扩展为临床性能验证。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 已确认参数与预先手工核对的临时输入；When 调用评价；Then 数值和触发规则与既有算法一致。

2. Given 参数尚未生效或不属于该批次；When 判读；Then 明确待核对，不能产生在控结论。

3. Given 临时与常规交替且跨参数版本；When 评价；Then 参与窗口的记录逐条符合 T2B-01，常规历史结论不变。

4. Given 保存判读时发生异常；When 重试成功；Then 原结果保留且只增加一份有效评价，不出现半份 run。

## 6. 证据与完成条件

- 小型可复算数据、输入窗口清单、参数版本和判读对照；包含缺参数与计算失败。
- 运行受影响的既有 LJ/Z-score/即时法回归证明原算法不变，补本卡适配的有意义失败测试。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
- 执行实现或验收时仅使用独立库/明确副本，记录版本和保护范围；此次编写卡片不运行应用或数据库操作。
