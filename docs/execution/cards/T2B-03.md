# T2B-03｜独立入口与临时检测录入

- 原任务：任务 2B：独立临时质控
- 状态：未开始
- 类型：实现
- 前置卡：T2B-02；T2-10 的日常入口及保存契约
- 本卡交付：独立“临时质控”入口与常规“变动”入口共用的录入流程。
- 原需求锚点：[原任务 2B](../../task_02b_temporary_qc.md) §1—6；[合并需求](../../requirements_merged_2026_09_21.md) §4.4、§6。

执行前阅读 [统一执行规则](../EXECUTION_RULES.md)。本卡是待执行范围，不表示功能已经实现。

## 1. 目标及用户可见结果

- 校准、试剂变更、搬迁或维护后，可直接登记临时检测，无需虚构常规结果。
- 检测时间、实际材料、变动原因、结果及缺失条件在保存前可核对。

## 2. 必读实际文件与复用函数

- `pages/lj_sections.py::render_lj_entry_and_stats_section`、`pages/zscore_sections.py::render_zscore_entry_section`：既有录入。
- `pages/lot_lifecycle_section.py::render_result_lot_choice / is_batch_writable`：批号与只读检查。
- `services/value_type_service.py::parse_project_input_value`、`ui/traceability.py::evaluation_tables`：数值与判读展示。
- T2 已交付入口、T2B-02 临时保存接口；拟新增公共临时录入区块，不能复制三份保存逻辑。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 在 T2 日常入口提供独立入口，并将常规录入的“变动：是”跳转到同一流程，保留原草稿。
2. 按仪器、检测项、具体批次定位上下文；多水平展示各水平真实批号与浓度编号。
3. 检测时间和实际试剂依据现有适用规则核对；缺失项列明原因，不用今天的默认值填历史。
4. 变动原因用类别与补充说明结构化保存；明确原因与失控原因分析是不同字段。
5. 保持 Enter、逐格输入、取消返回及保存失败后的草稿；提交前展示时间、用途、批号、水平和值。
6. 调用 T2B-02 单一事务接口；未具备 T2B-04 评价能力时只按批准的待判读流程保存，不能显示成功在控。

数据契约与状态：

- 两入口使用同一草稿和记录用途，成功后返回该临时记录详情；取消不制造结果。
- 有效输入值沿用所选检测项的真实值/Ct/log 配置，不在录入时临时换算或改类型。
- 保存时重新校验批次、资料状态及版本；陈旧页面失败时保留输入并要求核对最新资料。

## 4. 本卡不做与禁止事项

- 不把临时用途放进“质控方法”选项替代即时法；不强制先录入常规值。
- 不重做任务 2 批量工作台，也不放宽任务 0 质量要求或现有批次准入。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 当天没有常规结果；When 从独立入口完成一次录入；Then 能查询临时记录且常规结果数仍为零。

2. Given 打开表单后实际批次已停用；When 点击保存；Then 提示无法使用且输入仍在，没有新结果。

3. Given 三水平漏填一个值；When 提交；Then 定位缺失水平并不保存不完整 run。

4. Given 已填写原因和数值；When 按 Enter 再取消返回；Then 不意外清空草稿或创建常规记录。

## 6. 证据与完成条件

- 独立入口与变动入口的浏览器证据；包括空日期、取消、Enter 和陈旧页面失败。
- 对照页面及保存对象，确认原因、实际批号、时间与水平一致；复核搜索支持模糊查找。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
- 执行实现或验收时仅使用独立库/明确副本，记录版本和保护范围；此次编写卡片不运行应用或数据库操作。
