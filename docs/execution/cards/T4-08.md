## 3. 逐步实施

1. 固定已选范围与未选范围，列出所有仍待定问题；基础认证/首次管理员/恢复/核心权限矩阵未闭合时不得标整阶段通过。
2. 在独立库建管理员M、普通A、停用B；覆盖真实项目、批次、事件、附件、报告和批量预览，保持任务0适用性与核心算法。
3. 按权限矩阵逐入口做普通/管理员/未登录/过期/停用/撤权的正反测试，包括直接公开服务调用和伪造资源ID。
4. 实际浏览器双窗口验证退出、停用、改角色、恢复备份后陈旧页面保存失败；姓名填“管理员”不能提升权限。
5. 验收首次管理员一次性建立、最后管理员保护和选定恢复流程；没有合同支持的恢复或许可分支不显示完成。
6. 验收实验室资料继承、改名身份稳定及旧报告不变；若选择多实验室，读取/写入/搜索/导出/附件每类都做越权测试。
7. 完整备份恢复后重新登录，核对角色及范围；旧历史人员文本保持原状，新业务管理动作都能追到真实身份。
8. 在最终本机包验证登录→当前录入→普通历史修改拒绝→管理员账号管理→退出旧窗口拒绝；目标Windows/缩放实测缺项单独列明。
9. 向任务5交付已验证身份/授权接口与动作矩阵；阶段结论只声明身份和权限完成，不声明更正、补录、排除或重算已交付。

## 4. 本卡不做／禁止

- 不以界面按钮不可见替代服务越权测试，不以一类入口代表全部入口。
- 不更改真实用户账户/数据，不留演示密码或可绕过权限的调试开关。
- 不趁验收实施任务5业务；历史维护用户可写入口须等T5-12整链验收通过，不把管理员可以直接改旧值列为本阶段成功。

## 5. Given–When–Then 验收

1. Given：管理员M、普通A、停用B均有已建立会话样例。
   When：按全部公开写入入口提交正常及伪造请求。
   Then：允许/拒绝结果与矩阵逐项一致，失败无半写入。

2. Given：A已预览批量录入，随后退出/撤权。
   When：旧页面点击保存。
   Then：拒绝全部提交；重新登录后需重新核对，不能复用旧批准。

3. Given：旧报告记录未知人员，实验室名称后来变更。
   When：升级身份后查看并恢复备份。
   Then：旧文字和报告不变，不伪造账号来源，新关系准确。

4. Given：合同只选单实验室、未选择软件许可。
   When：审核交付声明。
   Then：明确单实验室权限能力，不声称多实验室、云许可或任务5重算完成。

- 未确认业务规则和未通过验证分别记录；不能以按钮隐藏或文档存在作为权限已生效的证据。
