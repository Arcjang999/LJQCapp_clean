# T1-02｜实现事件保存、来源快照与历史版本

- 状态：未开始
- 类型：实现
- 前置卡：[T1-01](T1-01.md)
- 本卡交付：事件存储、去重及版本服务
- 原需求锚点：[任务1](../../task_01_out_of_control_reports.md)第2、3、5节；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.3节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

打开同一异常始终得到同一处理记录；原检测和判读保持不变。
重启后草稿、来源证据和处理历史仍可读取。

## 2. 必读实际文件与复用函数

- `database.py`：`init_db`、`atomic_write`、`get_connection`及已有结果读取。
- `migrations/v1_2_lot_lifecycle.py`、`migrations/quality_review.py`：迁移登记及已有上下文/判读引用。
- `services/lot_lifecycle_service.py`：`context_dataframe`、`target_profile`；读取既有快照，不能用当前默认批号补历史。
- 拟新增：`migrations/out_of_control.py`、`services/out_of_control_service.py`、`tests/out_of_control_service_smoke_test.py`。

## 3. 逐步实施

1. 按T1-01建事件主表、内容版本、复测关系及状态历史；保存来源类型/方法/结果ID组合唯一键和当前版本号，关联保留原判读引用。
2. 在统一初始化登记迁移，重复运行不得产生重复事件或版本；新增表不改写原检测数值、状态和手动备注。
3. 实现创建或读取事件服务：重新读取来源、确认正式期及异常种类，再冻结上下文；警告需要显式发起标志，普通在控记录不自动建失控事件。
4. 将原结果、各水平、规则、参数、已采用质量要求及实际批号保存为事件起点快照；无法取得原判读时明确标记当前核查资料，不能冒充原时点判读。
5. 事件内容保存同时携带期望版本和请求标识；旧窗口版本不符返回“资料已更新，请重新打开核对”，不覆盖他人或另一窗口修改。
6. 主记录、内容版本、状态历史在同一事务内提交；任何一项失败均回滚，重复点击同一请求返回原成功结果。
7. 实现只读获取事件、版本和来源证据接口；技术字段在服务内部，供UI映射为业务用语。
8. 用隔离库验证首次初始化、重复初始化、并发旧版本和写入中断；保留来源表前后业务列对比。

## 4. 本卡不做／禁止

- 不改变计算引擎，不调用更新原检测来实现“处理完成”。
- 不写真实库，不为不再需要的旧测试数据增加复杂迁移。
- 不先做附件或PDF；本卡专注可靠事件和版本保存。

## 5. Given–When–Then 验收

1. Given：LJ结果101为正式失控。
   When：连续两次请求创建处理事件。
   Then：同一事件ID返回，主记录只有一条且来源结果101不变。

2. Given：窗口A/B都读取内容V1，A已保存V2。
   When：B携带V1提交。
   Then：明确拒绝覆盖，V2与B未提交内容均可区分。

3. Given：多水平run202有3个水平。
   When：在保存版本后、写状态前模拟失败。
   Then：事务回滚，没有半个事件或缺水平的快照。

4. Given：旧来源未记录实际试剂批号。
   When：建立事件并重启读取。
   Then：持续显示未记录，不使用今日默认批号代填。
