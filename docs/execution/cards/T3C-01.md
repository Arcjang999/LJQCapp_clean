# T3C-01｜批量月报范围与待生成清单

- 类型：准备、实现

- 原需求锚点：[原任务 3C](../../task_03_comparisons_and_monthly_reports.md#4-3c批量月报与汇总)；[合并需求](../../requirements_merged_2026_09_21.md) §4.5—4.6。

执行前阅读 [统一执行规则](../EXECUTION_RULES.md)。本卡是待执行范围，不表示功能已经实现。

## 1. 目标及用户可见结果

- 生成前先看到项目、实际批次、月份、方法、数据充足性及不生成的原因。
- 同月多个质控批号清楚分列，常规月报可独立推进，未定临时汇总单独说明。

## 2. 必读实际文件与复用函数

- `services/report_service.py::list_lj_report_month_options / list_zscore_report_month_options`：现有月份来源。
- `services/project_workspace_service.py::list_item_batches / resolve_batch_binding`：项目与工作台绑定。
- `services/workbench_config_service.py::list_lj_workbench_projects / list_lj_workbench_batches` 及 Z-score 同类查询：现有范围。
- 拟新增 `services/batch_monthly_report_service.py` 与批量月报入口，复用现有报告页，不复制生成器。
- 所有业务搜索复用 `services/search_service.py::fuzzy_match / filter_frame`；选中后以稳定身份精确关联。

## 3. 逐步实施、数据关系与失败行为

1. 定义月份、仪器、项目和 LJ/Z-score 方法范围，排除即时法原生月报，转入 LJ 后沿用现有规则。
2. 按方法、运行批次、月份形成待生成单元，同一项目当月多个实际批号分别列出且不静默合并。
3. 通过有效结果查询检查正式期范围、是否有数据、水平完整性、参数版本及质量要求评价条件。
4. 把可生成、无正式数据、不适用方法和需核对项目分列，用户先核对选择，不自动忽略排除项。
5. 仅预览不得写报告历史；注意现有 LJ 数据包构建会持久化离群快照，清单预检应复用合适查询而非盲调生成器。
6. 记录清单的源数据/参数版本；确认前若数据变化重新核对，范围没有任何可生成项时显示清楚空状态。

数据契约与状态：

- 一个待生成单元精确定位方法、批次和月份；展示名称变化不改变身份。
- 参数版本可在单份报告内分段说明，不把跨版本统计混成一个无说明均值/SD/CV。
- 常规范围与临时分支分别记录完成状态；T2B 口径未定不阻止常规预览，但不能宣称已支持全部临时汇总。

## 4. 本卡不做与禁止事项

- 不生成即时法月报，不新建计划管理来臆造漏做率。
- 不把质量要求未采用或数据不足当作 CV 已达标；不启动生成就写成功历史。
- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 同月同项目两个质控批号；When 预览清单；Then 分成两份报告单元并显示各自期间。

2. Given 混合 LJ、2/3水平 Z-score 和即时法；When 选择范围；Then 仅支持的 LJ/Z-score 可生成，即时法有明确排除原因。

3. Given 空月份或只有建靶数据；When 预览；Then 显示无法生成原因且报告历史数不变。

4. Given 临时总失控口径未定；When 查看常规清单；Then 常规可独立准备，临时分支明确待定而非默认混入。

## 6. 证据与完成条件

- 多仪器、多项目、多批号、空月及不支持方法的预览证据；核对预览前后历史数量。
- 清单数据合同和精确分组键说明，验证所有业务搜索支持模糊查找。
- 证据逐条对应本卡验收编号，记录未执行项和失败原因；未通过不得勾选完成。
- 执行实现或验收时仅使用独立库/明确副本，记录版本和保护范围；此次编写卡片不运行应用或数据库操作。
