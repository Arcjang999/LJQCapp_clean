## 1. 目标及用户可见结果

- 已确认：没有当日常规结果也能录入；临时检测独立判读，保留原因且不纳入常规 L-J 统计。
- 待确认：临时序列是否使用连续规则、是否引用常规历史窗口、月报总失控次数及分母是否包含临时记录。

## 2. 必读实际文件与复用函数

- `docs/task_02b_temporary_qc.md` §4：不得把“独立”自行解释为某套跨点算法。

## 3. 逐步实施、数据关系与失败行为

1. 把记录用途与质控方法分成两个维度，列出 LJ、多水平和现有即时法各自可用上下文；未确认适用方式不自动开放。
2. 用单次临时超限、连续两次临时、常规与临时交替三组示例列出需要业务回答的规则窗口问题。
3. 单独列出常规统计、临时统计、月报总失控及分母四项，展示每种候选口径会怎样影响同一示例。
4. 对多水平明确沿用完整 run 和各水平参数引用；不把一次 run 拆成多个最终失控事件。
5. 逐项记录答复人、时间、适用范围、依据与仍未确认项；候选方案必须标为建议，不能写成已确认要求。
6. 标注依赖：记录结构、草稿、来源查询可准备；对应跨点评价与合并汇总在口径未确认前不能上线。

数据契约与状态：

- 决策按问题独立记录“已确认/待确认”，包含范围及证据；不能用一个笼统批准覆盖所有分支。
- 数据结构不得让“临时类型”依赖已有常规结果 ID；关联复测属于另外的关系。
- 缺少判读规则或适用参数时为“待判读/缺少依据”，不显示在控或通过。

## 4. 本卡不做与禁止事项

- 不在本卡实现算法、页面、数据库或自动推定临床阈值。

- 不修改既有质控公式、规则阈值或 Z-score 整次检测判定粒度；任务 0 的适用性继续精确判断。
- 界面不得显示编程语言、代码、开发说明、内部字段或错误堆栈；使用实验室业务用语。

## 5. Given–When–Then 验收

1. Given 只有当日临时检测；When 检查合同；Then 允许独立记录且没有“先保存常规结果”的前置。

2. Given 常规窗口是否参与尚未答复；When 排定 T2B-04；Then 该评价分支标明等待，T2B-02 的独立资料设计可继续。

3. Given 月报含 2 次常规失控和 1 次临时失控；When 核对决策；Then 未确认时不得擅自写成 3 次总失控或固定分母。

4. Given 一次三水平临时检测有一个水平失控；When 核对关联契约；Then 最终事件仍按完整 run，水平证据保留。
