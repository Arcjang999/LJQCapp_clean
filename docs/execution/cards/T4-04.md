# T4-04｜实现管理员账号维护与角色变更

- 类型：实现
- 前置卡：[T4-03](T4-03.md)；T4-01管理与恢复规则已确认
- 本卡交付：账号列表、新增/启停/角色变更及审计
- 原需求锚点：[任务4](../../task_04_accounts_and_lab_scope.md)第3节“角色与账号管理”、第4节；[需求合并稿](../../requirements_merged_2026_09_21.md)第4.2、4.6及第6节
- 执行公约：[EXECUTION_RULES.md](../EXECUTION_RULES.md)，执行前必须遵守。

## 1. 目标及用户可见结果

管理员在确认的现有设置位置维护普通/管理员账号。
每次管理操作保留真实操作者，角色变更后旧授权不能继续使用。

## 2. 必读实际文件与复用函数

- `pages/settings_page.py`：`render_settings_page`；在现有设置承载账号区，不另建重复实验室资料页。
- `services/search_service.py`：`fuzzy_match`，用于账号姓名/登录名查找，不用于身份判定。
- T4-02/03身份和会话服务；现有`ui/dialogs.py`交互原则，实际账号表单拟新增。
- 拟新增`ui/account_management.py`和`tests/account_management_smoke_test.py`。

## 3. 逐步实施

1. 列表展示登录标识、姓名、普通/管理员、启用状态及确认过的范围；搜索采用模糊服务，选中后用稳定账号ID编辑。
2. 新增账号校验登录标识唯一性与凭据流程；初始凭据交付/首次更换按T4-01选择，不通过日志或无保护文本泄露。
3. 所有新增、停用、恢复启用、角色变更先验证真实管理权限，再在事务内更新状态和审计；伪造界面角色无效。
4. 角色变更与停用更新可撤销版本，让T4-03旧会话下一次受限动作失败；重新启用不能自动恢复此前失效会话。
5. 管理员自停用/自降权、最后一位可用管理员处理按合同保护；恢复方案未确定时不能让程序进入无法管理且无合法恢复的状态。
6. 账号不硬删除，显示姓名改变后历史动作保留当时姓名快照和同一账号ID；离职停用不影响历史报告查阅。
7. 凭据恢复只实现用户已确认路径；恢复记录真实执行人/时间/目标，撤销目标既有会话；未确认分支显示待办于开发文档，不摆占位功能给用户。
8. 提交使用期望版本防另一窗口覆盖角色；取消、重复点击及校验失败保留原数据并提供明确反馈。

## 4. 本卡不做／禁止

- 不引入未确认第三种角色、多级审批、跨客户超级管理员。
- 不让恢复功能绕过身份核实或建立后门，不把恢复建议当授权。
- 不把停用账号历史业务删除或改为另一个操作者。

## 5. Given–When–Then 验收

1. Given：管理员M新增普通账号A。
   When：A登录后列表检索A并停用。
   Then：A被停用且旧会话写入失败，审计操作者为M。

2. Given：普通账号A伪造管理员表单请求。
   When：直接调用角色变更服务。
   Then：拒绝且角色未变，不受界面字段“管理员”影响。

3. Given：仅有一位可用管理员且没有已确认恢复路径。
   When：尝试停用或降权自身。
   Then：拒绝会导致无人管理的操作，并说明需先建立可用管理安排。

4. Given：窗口1修改A为管理员，窗口2仍持旧版本。
   When：窗口2提交旧角色。
   Then：拒绝覆盖；历史保留首次角色改变和操作者。
