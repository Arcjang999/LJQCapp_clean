## 3. 逐步实施

1. 核对真实表和主键；复用结果、上下文、判读快照，不复制第二套项目/批次。新增修订关联应表达稳定原记录/run、父修订、操作类型、原/新值、原因、真实账号、实际检测时间、录入时间、操作键及版本。
2. 保留原实测值、原上下文和历史判读；不继续仅靠 UPDATE 覆盖唯一一份原值。采用修订表或原始/有效投影均可，但写明读取合同与唯一有效版本约束。
3. 多水平修订以完整 run 为单位，水平是子记录；不得只更新某水平而把原联合结论当新结论。批号关系保存实际来源及参数引用，不只存展示文字。
4. 补录保存实测时间、当前录入时间及合同要求的实际检测身份/来源编号，支持事务内业务重复检查；请求键不是检测身份。排除保存范围/原因，恢复新增反向操作记录；每类操作保留原始身份和类型。
5. 实现显式读取当前有效数据与完整历史两个路径。默认普通业务读有效版本，追溯读历史；迁移时未知旧人员不伪造账号。
6. 测试迁移在独立空库和当前基线副本重复运行，验证无重复修订及外键断裂；不为用户已放弃的旧演示结构增加兼容层。
7. 为下游提供内部构造/读取接口及测试夹具；暂不接任何可点击的历史修改入口。

## 4. 本卡不做与禁止

- 不开放写页面，不将当前数值修订直接视作维护成功。
- 不删除原值、原判读或旧报告；不以数据库自增ID推断临床先后规则。
