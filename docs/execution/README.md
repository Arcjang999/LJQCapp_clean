## 4. 前置缺口怎样处理

- **正式邦德盛资料缺失**：完成目录机制和人工资料流程，T2A-09分别给功能/正式内容结论。T2可消费已验收的人工关系接口，不能用测试目录冒充正式内容。
- **临时判读/分母待定**：T2B记录结构等独立准备可以继续；判读和对应报告分支不开放。T3A同产品换批独立依赖既有生命周期与T2A资料，不因临时月报分母未定停工。
- **换批20点细节待定**：可以准备选批和只读数据清单；切换条件/直接换批初期判读按决策结果实现。不能为了快速推进默认一个算法。
- **任务4组织方案待定**：未明确的多实验室/许可不自动加入。身份、角色、恢复的必要业务决定准确记录，代码组织和安全存储实现由开发者负责。
- **任务5参数/历史补录分支待定**：可以完成内部版本与影响分析等独立能力；整阶段未通过时不向用户开放可修改数据的半套入口。
- **仅缺目标设备**：R0-02标待环境，继续本机可做的卡；发布结论保持未全通过。

卡的“前置”中既有技术依赖也有默认排队顺序。遇到上述明确例外，在进度表注明采用的已验收接口与缺口；不能以顺序为由扩大功能，也不能跳过真实计算或保存依赖。

## 6. 验收与交付边界

- 任务书拆分已交付，R0-01已验收，T1-01合同与样例已完成；后续新功能尚未实现，动态完成状态以进度表和交付记录为准。
- 每个阶段先完成小卡，再由最后一张卡验收可操作的完整业务链。中间卡只声明自己的能力，不能提前宣称整体完成。
- 所有界面卡包含业务语言、模糊搜索、草稿/取消/错误处理；只涉及服务的卡不强迫新增页面。
- 核心公式和判读规则不变；任务5必须复用原算法执行必要重算。这个要求不能被拆分成“可选优化”。
- 原任务仍保留；[覆盖表](COVERAGE.md)查缺失，[决策表](DECISIONS.md)查未定项，[进度表](STATUS.md)查实际完成。
