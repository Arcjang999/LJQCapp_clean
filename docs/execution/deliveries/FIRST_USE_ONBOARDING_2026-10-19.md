# 2026-10-19 首次引导

用户确认实施首次引导：可跳过、保留进度，已有项目不自动打开，右上角提供“首次引导”按钮。说明沿用现有操作手册的简短操作语言，不加入开发说明。用户随后明确本轮仅本地实现、验证并推送GitHub，云端环境不在本轮范围。

## 交付行为

| 步骤 | 用户看到的操作 |
|---|---|
| 单位信息 | 填写实验室、科室、检验员、复核员，保存设置并核对当前数据保存位置 |
| 准备资料 | 打开仪器、试剂、质控品管理，或直接打开单位资料准备清单 |
| 建立项目 | 进入现有三步建项，核对质量要求后保存并进入录入 |
| 开始检测 | 登记试剂批号验证，选择项目与批次，按实际方法保存检测 |

- 无项目且未跳过/完成时，首次进入首页显示原生弹窗。任何已登记项目均抑制自动弹出，草稿、停用项目和三方法项目均计入；内置检验项目及产品目录不算已建项目。
- 右上角“首次引导”随时打开，回到上次步骤；“稍后再做”关闭并保留步骤，下次不自动弹出。完成引导后进入项目工作台，也可再次手动打开。
- 前后切步与各操作入口先保存引导进度。进度写入失败时保持原步骤，显示“引导进度未保存，请重试。”，不会继续跳转。
- 点击实际操作按钮时关闭引导，复用已有页面或编辑弹窗；保存或取消后点击“继续首次引导”返回。编辑资料、导入清单或建项时，顶部引导按钮暂不可用，避免两个弹窗同时打开。
- 保存的是引导步骤与跳过/完成状态；现有表单、未保存草稿及业务校验仍沿用各自流程。引导不代替质量目标确认、实际批号验证或检测准入，也不为完成引导创建检测数据。

## 实现范围

`services/onboarding_service.py` 使用 `app_settings.first_use_onboarding` 独立保存版本、步骤及状态；读取损坏内容时安全回到可用步骤，不覆盖报告设置。无需新建数据库表，进度随现有完整备份保存。自动提示每会话/当前数据位置仅检查一次，准备情况只在打开引导时查询，不预先加载帮助全文、图片或业务表单。

`ui/onboarding.py` 负责四步弹窗、跳过/继续、实际入口及错误提示。`app.py` 接入一次性自动检查；`ui/common.py` 增加顶部按钮，保留原导航；菜单关闭可选择延后，修复从已渲染引导进入仪器/试剂页时的控件赋值冲突。`ui/lab_preparation.py` 提取公用打开函数，仍使用原来的清单审查、取消和保存逻辑。顶部导航复用原窄窗口换行规则。

同轮纳入此前[启动与目录查询优化](../notes/RUNTIME_OPTIMIZATION_2026-10-19.md)。在用数据库、附件、报告和保存位置配置不提交；仅源码、测试及文档。分支沿用 `codex/project-workflow-alignment`，提交与远端结果以本轮Git记录及远端核验为准。
