# 填写与操作提示关联普查

用户反馈新建项目的质量要求页无法进入下一步，又看不到原因；部分提示需要返回上一页才能修改。随后要求把其他填写页面一并排查，并提供已登录的服务器后台。

## 原因与修复

截图场景为丙型肝炎病毒RNA、实时荧光PCR、Ct、研究用途、血清，确认人已填但底部确认项未勾选。原按钮按确认条件禁用，却没有直接说明缺少该操作。现在确认人和确认项就地标出必填，按钮上方按当前输入列具体待办；勾选后提示消失，原有下一步条件随之满足。没有要求用户通过更改真实检测用途或结果类型绕过校验。

普查从 `ui/`、`pages/`、入口中233处包含 `disabled=` 的候选位置开始（包含字段锁定、服务参数等，不能当作233个按钮），继续追踪填写控件、保存校验、草稿和实际返回入口。

## 草稿与范围

并发产生同名项目或上游资料失效时，质量页先保存本次事件提交的最新控件输入，按相同设置身份恢复，避免返回修改时丢失刚填写的确认人和说明；不同检测设置和不同窗口不共用这份输入。补充标准文件按原合同保留有效全文的SHA记录；无效新文件清除旧标识并持续提示重新上传。减少标准数量、关闭登记、更换检测设置或窗口后，不会恢复已经移除的文件记录；文件上传控件本身不直接恢复。

无数据库迁移、依赖升级或质控算法变化。所有自动检查使用隔离数据，不向运行库保存新检测或资料；本地浏览器使用最小临时夹具。实际Windows和指定200%缩放未在本轮实测。
