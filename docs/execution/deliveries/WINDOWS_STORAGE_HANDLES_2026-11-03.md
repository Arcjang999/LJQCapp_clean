# 2026-11-03 Windows 备份与迁移文件占用修复

后续提交授权：用户要求在打包升级前推送当前修改，本修复与全应用说明修订、对应测试和交付记录一并收录至 `codex/project-workflow-alignment`，实际提交与远端结果以Git核验为准。本次未更新腾讯云运行程序；下文未提交状态为修复验收时事实。

## 范围与原因

从 `codex/project-workflow-alignment@6f4a8623` 接手，在 Windows 11（26200）、Python 3.14.4、SQLite 3.50.4 上复现备份和保存位置迁移的 `WinError 32`。本轮按用户要求修复 Windows 文件占用；Mac Air 此前已由用户完整验证，本轮没有重新进行 Mac 实机验收。

`services/storage_service.py` 中的两个只读查询及快照复制的源、目标连接使用了原生 SQLite 事务上下文。该上下文负责提交或回滚，不负责关闭连接；临时库因连接尚未释放而无法删除。Windows 对打开文件的限制使这一问题直接表现为备份或迁移失败。

## 修改

- 两个只读查询使用 `contextlib.closing()`，包括正常返回、提前返回和异常路径。
- 快照复制的源、目标连接均明确关闭；原事务上下文保留，先提交或回滚，再关闭，最后校验和清理临时文件。目标连接打开失败时源连接也会关闭。
- 新增 `tests/storage_connection_lifecycle_smoke_test.py`：强引用保留真实连接，检查连接已关闭并立即改名、删除和重建临时文件，避免自动回收掩盖泄漏。
- 修正附件存储回滚测试中的 Unix 路径分隔符判断，改用 `Path.parts`，让 Windows 下的文件复制失败注入实际生效。生产路径校验不变。

没有新增依赖、数据库迁移或格式变化；备份、恢复和迁移的输入、输出、事务边界及失败回滚接口不变。未改质控计算、历史结果、报告或附件内容。没有提交、推送或更新云端。
