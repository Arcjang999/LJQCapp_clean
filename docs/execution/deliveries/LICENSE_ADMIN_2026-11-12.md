# 独立验证码管理页面（2026-11-12，本地）

按用户要求新增独立管理页面，可自行生成验证码、查看已用台数、延期、停用和解绑，并查看设备激活和验证的网络IP。现有展示网页版没有新增入口；本轮只完成本地实现和隔离验收，未上线正式管理网址。

## 操作

1. 从独立管理网址登录管理员账号。
2. 点击“生成验证码”，填写客户或实验室备注、允许台数和截止日期/时间。默认10台、北京时间2026年11月30日23:59。
3. 明确点击“生成验证码”，再点击“复制验证码”保存。验证码仅本次显示，不保存在列表、浏览器Storage、URL或日志中。
4. 在列表搜索备注、按状态筛选，点击“查看与管理”查看已用名额、设备状态、首次激活时间、最近验证时间、首次记录IP和最近IP。
5. 选择新的截止日期和时间，点击“保存延期”。已激活电脑下次联网验证时自动更新期限。
6. 停用或解绑需点击确认，取消不提交。解绑释放名额，保留设备和IP记录；重新启用后原电脑须重新输入验证码验证。

停用和解绑不能追溯收回已签发的离线许可。离线电脑最多继续至原24小时租约到期，且不超过原总期限。所有日期时间按北京时间显示并精确到分钟，表单回车不直接提交。

## 实现范围

- 新增`licensing_server/admin_auth.py`、`admin_httpd.py`、`admin_cli.py`和`admin_assets/`，复用既有授权库，不复制业务数据库。无需新依赖。
- 管理页独立进程，默认仅监听`127.0.0.1:8519`，正式外部入口必须独立HTTPS主机名并固定Origin/Host；现有业务UI、桌面菜单和公开资料未加入入口。
- 管理密码仅在CLI中通过两次交互输入设置，不接受密码命令参数，不提供默认密码。配置位于源码和业务资料目录之外，0600权限，保存`scrypt N=16384,r=8,p=5`摘要和盐。
- 管理会话只在内存中保存，登录时旋转，退出或服务重启后失效；30分钟空闲、1小时绝对上限。HTTPS Cookie使用Secure、HttpOnly、SameSite=Strict与`__Host-`约束。
- 所有修改接口要求登录会话、精确Origin、CSRF令牌及有界JSON；登录也有匿名会话CSRF及全局/IP限速。页面禁止嵌入，接口和资源no-store，不开放CORS。
- 前端使用文本节点显示用户内容；生成码在关闭窗口、退出或超时时清除。会话代次和请求取消防止旧响应在退出后重新显示验证码。
- IP只在成功设备证明和席位事务后记录。默认取真实连接IP；仅明确启用代理信任且连接来自loopback时，采用单个合法`X-LJQC-Client-IP`。通用转发头和用户JSON声明不能冒充IP，失败/重放不更新记录。
- 授权库从v1升级到v2，只增加`first_ip`和`last_ip`，原码摘要、设备、代次和审计保持；旧设备的历史IP不补造。IP是网络出口地址，多台电脑可相同，不能视为机器身份或精确位置。
- 管理代码和资产均位于`licensing_server/`，不在桌面源码清单、编译模块或公共资源中。成品检查会拒绝误拷此目录；本轮无需重编译178个客户端业务模块。

## 正式上线边界

本轮未提交推送、部署服务器、设置生产管理员密码、签发正式码或发布桌面程序。正式管理网址、DNS和证书尚未确定，不擅自购买域名或修改账号设置。服务器操作继续统一使用本机OrcaTerm。

正式部署必须使用独立管理主机名。相同IP仅更换端口仍共享Cookie主机范围，不能当作完整隔离；现有展示网页版也不提供管理入口。反代必须覆写`X-LJQC-Client-IP $remote_addr`并保留准确`Host $http_host`，相应服务需显式开启代理信任；不应盲信客户端转发头。

先部署独立授权服务及管理页并验证HTTPS，再发布带授权的桌面更新。已发布旧0901程序和固定1.01安装包保持，本轮不追溯启用它们的激活。部署和签发步骤见[管理操作说明](../../../licensing_server/OPERATIONS.md)。
