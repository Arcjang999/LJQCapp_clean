# 全系统日期时间输入控件（2026-11-09）

用户要求全系统检查日期时间输入，日期使用控件，时间到分钟。本轮在本地完成实现与验收。

## 修改范围

检查 `app.py`、54个UI模块、22个页面模块及2个工具，共79个文件。含输入的39个文件，以及动态字段、两处可编辑表格和日常录入组件均已核对。

| 入口 | 当前行为 |
| --- | --- |
| 整组录入 | 检测时间由手写文本改为日期时分控件，修改与清空及时保留草稿 |
| L-J、多水平法、即时法录入 | 统一日期格式和1分钟步长，默认值清除秒与微秒 |
| 检测记录编辑、新旧维护窗口 | 使用分钟控件；只改其他内容时保留原时间精度，调整时间才保存所选分钟 |
| 患者影响评估 | 影响开始、结束时间改为可留空、可清空的日期时分控件，保留范围顺序校验 |
| 处理效果确认 | 沿用上一轮分钟确认控件，接入全系统共用控件 |
| 试剂及质控品 | 验证、启用、生效、更正时间统一到分钟，取消后继续填写保持时间 |
| 均值和SD、统计方式切换 | 生效时间统一到分钟；默认建议满足既有版本及最后检测的精确下界 |
| 补充标准登记 | 实施日期、废止日期、确认日期由文本改为日历，空值不自动填今天 |
| 其他日期、效期及报告范围 | 已使用日期控件，继续沿用原业务条件 |

共用控件为 `ui/date_time_inputs.py`，统一 `step=60` 与日期格式。已有草稿日期纳入可选范围，避免较早或较远日期在填写其他字段后变空。补充标准日历可选择历史标准日期，业务服务继续核查未来日期及日期顺序。

带日期时间控件的表单均关闭回车直接提交，包括多水平录入、旧维护窗口及实验室自定要求。点击原有明确的保存或确认按钮提交。

同时修复L-J维护和多水平记录编辑中原有的微秒截断：保存已经校验的精确时间，不通过仅到秒的显示格式重写。仅修改备注的记录保持原秒及微秒。

文件版本依据允许非日期版本号，继续使用文本字段；目录取得日期来自上传资料，界面只读。两处可编辑表格及日常自定义表没有日期时间文本列。Excel、CSV和粘贴导入继续解析文件里的时间，系统生成的审计时间保持原精度。

## 验证

18套隔离检查共176项通过，失败、错误、跳过及越界均0。覆盖分钟保存、空值与清空、同分钟确认、未来时间拒绝后纠正、影响范围顺序、草稿往返、既有记录精度、版本严格后界、时区与跨日，以及2001和2099等日期在其他字段变化后的保留。36个相关及基础Python文件编译通过，`git diff --check` 通过。

实际Chrome检查使用本轮新建的隔离资料：

- 整组录入选择分钟并按回车，检测人和时间留在草稿，未新增检测记录。
- 患者影响时间选择日期和时分后，点击“保存处理草稿”保存到第2版；冻结内容与选择的分钟一致。
- 补充标准选择2001年实施及确认日期、2099年废止日期，修改版本后全部保留。
- 试剂验证时间调整后按回车不提交；取消并继续填写，时间与确认人保留。
- 多水平录入表单填写三个水平值，调整分钟后按回车，三个值保留，未提交检测。

原检测来源逐表核对保持。证据汇总在 `output/system-date-time-controls-2026-11-09/`：`verification.json`、`compile.json`、`inventory.json`、`browser-before-save.json`、`browser-checks.json`及实际截图。各分项原始日志保存在汇总所列路径；早期检查发现的问题及测试字段更新前失败日志保留，最终统计仅计最终通过结果。
