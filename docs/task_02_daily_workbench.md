## 1. 目标与现状

2026-09-21 需求合并：本任务承接按质控品及具体批次展开检测项的日常批量录入；独立临时质控拆为任务 2B。上游实验室上下文、panel 和产品关联由任务 2A 承接，原核对依据见 [基础资料增量](project_material_workflow_alignment.md#8-2026-09-21-面聊合并后的基础资料增量)。总体归属见 [需求合并稿](requirements_merged_2026_09_21.md)。本次仅更新规格，功能尚未开发。

让日常操作者按仪器/项目快速查看今日情况、连续录入一组项目，并直接处理异常；减少在方法、项目、批次和设置页之间反复切换。

当前首页以项目列表、检验项目及批次选择和新版使用说明为主，原方法入口折叠保留。支持批量配置和文件导入，但不等于跨检验项目的日常表格录入。质量目标独立页、项目/批次设置及参数确认已有服务与规则，应复用这些能力改善操作衔接。

## 2. 今日质控总览

- 提供统一入口，默认查看当天，在当前实验室上下文内按仪器、大项目、质控品及方法筛选。实验室资料复用系统设置；是否增加多实验室切换及账号范围在后续方案中确定，不在总览内另建第二套实验室资料或强制增加重复选择步骤。
- 展示项目/批次、各水平最新结果、检测时间和数据阶段；区分参数建立期、正式期、即时法过渡期，不将三类状态混为同一种“正常”。
- Z-score 的最终结论按整次 run 展示，各水平只作为明细证据。今日多次检测可展开，不只保留最后一次。
- 今日曾发生的失控与任务 1 中仍未完成的处理分别展示；最新复测正常不能把未完成处理隐藏。历史未完成事件应可进入，不能仅因跨日消失。
- “今日无记录”与“计划应做但未完成”区分。未配置执行计划时，不计算漏做率或把所有启用项目认定为当天必做；首轮可只显示无记录状态。
- 从总览直接打开相应批次录入、质控图、失控处理记录和报告，并保留日期/筛选条件；返回后不必重新选择。
- 对 CV 超限提示明确统计期间、有效点数及采用要求，复用质量目标计算，不把单次检测值当作 CV，也不把不满足 CV 要求等同本次 Westgard 失控。

## 3. 多项目日常录入

首轮支持同一仪器下已配置的大项目及其检测项。共用检测时间、操作者等信息，各检测项保留明确的质控品批号、水平、单位及实际试剂批号；不同方法分别调用既有保存和判读服务。大项目中的检测项支持整组带入和批量配置，不要求逐项手工新建；这与本节日常结果批量录入分别验收。

1. 在当前实验室上下文内按仪器→质控品→一个明确的实际批次定位，自动展开该质控品及批次关联的全部在用检测项形成表格；实验室信息复用系统设置，不把另建或每天重复选择实验室当作前置要求。保留大项目筛选和原单项入口，不要求逐个挑选检测项。批号、水平、单位及输入值类型清楚展示，允许打开核对详情。多水平法仍须收齐既定组合，不因单选本次材料批次而丢掉其他必要水平。
2. 支持键盘连续输入和表格粘贴，保留未保存草稿；时间、筛选或辅助详情变化不能无提示丢掉输入。
3. 提交前逐项目检查数值、批号效期/使用状态、时间适用性及必要水平；定位错误，不悄悄跳过。
4. Z-score 一次完整 run 为最小保存单位，全部水平一并保存，不允许出现只保存了部分水平的检测。
5. 若允许部分项目成功，必须返回逐项目成功/失败清单；失败草稿保留，重试不重复写入成功项目。所有项目通过后整体保存也可作为首版方案，但界面需明确且经过验证。
6. 保存后原位展示各项目结论与可打开的图/明细，维持仪器、项目排序及视图。继续支持原单项目入口和文件导入。

不得为了批量录入绕开已有建靶维护锁定、参数版本、批号追溯、整次检测判定或即时法 3/20 点规则。

### 3.1 独立临时质控

本节为任务 2 与 [任务 2B](task_02b_temporary_qc.md) 的衔接要求；记录类型、独立判读和统计隔离由 2B 统一实现，不在本任务再写第二套。

- 提供独立录入路径；常规录入处的“变动：是/否”也可进入同一流程，但没有常规记录时仍能登记临时质控。
- 保存校准、换试剂、搬迁、维护等原因及实际检测上下文，独立判读并在数据表中显示；不是只加备注，也不是改用即时法。
- 临时值不纳入常规 L-J 统计；图上是否显示作为独立选项，不改变其统计归属。临时失控可进入任务 1 的处理流程，复测新增关联记录。
- 临时跨点判读规则、月报总失控次数归属尚待明确，不在本次合并中擅自设定阈值、连续窗口或分母。

### 3.2 导入导出与后续数据维护

优化现有模板、粘贴、预览、行号/错误定位和结果导出，明确检测项、实际批次、水平及记录类型。批量配置导入和检测结果导入分别处理，不能互相冒充已完成。

管理员更正、历史补录及其计算联动由主框架后的 [任务 5](task_05_result_maintenance_recalculation.md) 完整实现，本任务为有效结果和判读版本保留衔接。后续维护成功时，总览、表格、图表和导出必须刷新到重算后的版本，不能因缓存继续显示旧结论。

## 4. 设置衔接

2026-09-20 已完成局部调整：质量目标页统一为“质量目标设置”，批次逐水平确认直接放入“批次管理”相应检验项目中，已有批次显示“本批次质量目标”且只读。后续复用这一入口，不再恢复独立“批次采用要求”页；以下其它引导和上下文恢复仍待完成。

- 新建项目/批次时直接查看和选择质量要求，或通过带当前项目上下文的入口返回确认；复用 `quality_target_service`，不另造采用记录。
- 当前批次显示具体未完成项：水平未配齐、质量要求待核对、人工参数未确认、使用验证未完成等，能直达相应位置并返回。
- 保持批次资料确认、参数确认、实际使用状态三个概念独立；改进导航不能把它们合成一个含义模糊的“启用”按钮。
- 不重复加入用户此前要求移除的整块“推荐顺序”横幅和资料数量统计；提示放在当前操作所需位置。
- 建议提供常用/最近使用项目及返回位置记忆；具体布局以真实浏览器操作为准，避免用更多菜单取代减少切换。

## 5. 交付顺序与代码入口

建议顺序为任务 2A 资料依赖 → 本任务总览/批量录入/设置衔接及日常验收 → 任务 2B 独立临时质控及衔接验收。任务 1 的待处理查询接口直接复用。2、2B 分别记录完成状态，不重复开发已完成弹窗。

主要入口：`pages/main_page.py`、`app.py`、`ui/common.py`、三方法页面及 workbench services、`pages/project_management_page.py`、`pages/lot_lifecycle_section.py`、`ui/quality_targets.py`。聚合查询和批量保存协调放入 service 层，尽量避免每次页面刷新重复全量计算所有历史结果。

## 6. 验收条件

本任务日常流程先独立验收；下列临时质控场景在 2B 接入时补验，不能用本任务的通过记录宣称 2B 已完成。

- 空库、只有旧项目、混合三方法、多仪器、今日无结果、多次检测、跨日未处理事件均显示正确。
- Z-score 任一水平触发拒绝规则时总览按整次失控；复测正常仍能找到待处理事件；参数建立和即时法阶段不会显示误导性的正式期结论。
- 以生化 panel 的 18—20 个关联检测项验收：选择质控品及具体批次后一次展开并连续录入，覆盖不同水平数、缺失值、错误单位/批号及失败重试；无半个 run、重复记录或跨项目串值。没有产品覆盖资料时不能伪造关联检测项。
- 没有当日常规记录时可独立录入临时值；临时判读可查，数据表保留，常规 L-J 统计不受其纳入影响，切换图上显示不改变统计；临时失控可关联任务 1。
- 键盘 Enter、Tab、粘贴、切换辅助页和返回、连续保存 2–3 次均实际浏览器验证；没有静默丢失草稿或重置视图。
- 质量目标确认后返回当前批次，已启用批次仍只读；不同水平及 SD 型要求不会误显示为统一 CV 上限。
- 按适用环境复核 2880×1800 @ 200% 及正常缩放。无法获得真实系统缩放环境时记录未验证项，不能以小视口替代并声称全部通过。
- 比较与原单项目录入的统计、判读和快照一致；受影响的界面、三方法接入、批号生命周期、质量目标回归通过。
