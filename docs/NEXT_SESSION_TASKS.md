### 2.2 第二项：新旧质控品换批全过程核查

目标操作：旧批继续日常使用 → 新批同时检测并积累自身数据 → 确定新批适用均值和标准差 → 新批正式使用 → 旧批停止使用。

| 核查项 | 预期与边界 |
|---|---|
| 新批数据衔接 | 正式使用前后的新批属于同一批，已积累数据保留，不重新建立空批；旧批原始结果不并入新批 |

| 已有自动跳转 | “建立新批次草稿”后自动选中新草稿进入核对已实现，保留并验证即可 |
| 标准与现有计算差距 | 逐项核查独立分析批计数、暂定与常用均值/标准差、长期精密度资料利用、稳定性较长/较短质控品的不同方案；先提供代码与标准对照，不把未核查项写成已确认缺陷 |

## 4. 用户选定的后续功能与范围

用户已选定下列五项，并认可9月15日对用途和名称的解释。它们不再全部归入“未选择的可讨论增强”，但仍未实现；先完成第2节，再分阶段开发，完成一项验证一项。建议顺序为质量目标 → 失控原因分析与报告 → 历史批号更正 → 试剂换批比对；附件随相关报告建设。此顺序是交接建议，不是用户额外指定的硬性顺序。

| 功能 | 具体交付与验收边界 |
|---|---|
| 历史检测记录批号更正 | 从某次检测进入更正，保存原批号、新批号、原因、更正人及时间；更改当前默认批号不能回写旧结果。质控品批号更正若影响参数和判读，须明确核查和更正处理，不能静默改写原判读 |
| 上传附件 | 放在换批验证或失控报告中，保存已有表格、扫描件等；支持查看/下载并纳入备份恢复。上传不代表计算或验证通过；文件格式、大小及保存方式属于待实现细节，无需单独业务入口 |
| 试剂换批比对 | 录入同一患者样本用两批试剂得到的成对结果，计算差异并输出报告；按明确的适用标准或实验室方案判断。与两批不同质控材料的新旧批号比对分开，不扩展为通用性能验证平台，不预设万能合格阈值 |
| 质量目标 | 按适用WS/T预置/导入，优先核对WS/T 403—2024与406—2024；支持检验项目匹配、单位、浓度区间、允许不精密度、允许偏倚、允许总误差、标准版本和实施日期。已内置WS/T 886项目名称代码不代表目标库已做；标准缺项不能臆造，TEa不能直接当CV上限，旧批次保留原采用要求 |
| 失控原因分析与报告 | 从原失控记录填写原因分析、纠正措施、复测结果、处理效果和必要的患者结果影响评估，保存/查询/导出失控报告；保留原失控记录，不以“处理完成”覆盖原判断。填写确认人不等同引入权限与电子签名系统 |

本轮未纳入：即时法月报、LIS、权限与电子签名、安装包发布，以及手册里的其他功能。数据库迁移、原始结果变更、报告生成和附件备份均按实际影响单独验证，不能把需求清单直接写成完成清单。
