# 任务 1：失控原因分析、复测关联、附件与独立报告

更新时间：2026-09-18。状态：任务已列入下一阶段，尚未开发。优先级：三阶段中的第一项。

## 1. 目标与现状

让操作者从某次失控记录直接完成原因分析、纠正措施、复测结果关联、处理效果确认和独立报告，之后能查询未完成事项与处理历史。

当前已有 LJ / Z-score 规则判读、逐次批号与参数追溯、手动备注、月报和报告历史。月报中的“原因与纠正措施”目前主要汇总手动备注，不能当作独立失控处理模块。质量目标首版已完成，不重复建设目录或规则引擎。

下一 session 从核对现有结果 ID、整次检测判定、备注及报告保存链路开始，再落实增量数据结构和最小可操作页面。不要只新增填写表格而不关联原始检测。

## 2. 首轮交付

| 内容 | 必须实现的行为 |
|---|---|
| 从原记录进入 | LJ 关联原结果；Z-score 关联整次 run，展示各水平证据。同一事件再次打开进入既有处理记录，避免重复新建 |
| 自动带入上下文 | 项目、仪器、实际批号、检测时间、原结果、触发规则、参数版本及所采用质量要求；缺失历史信息显示未记录，不猜测补齐 |
| 原因与措施 | 常用原因分类、原因分析、纠正措施与补充说明；允许先保存草稿，后续继续填写 |
| 复测关联 | 从同一检测系统的后续检测中明确选择复测，显示日期、批号、水平、规则结论。若批号或参数版本不同，显示差异并要求说明；拒绝关联无关项目 |
| 处理状态 | 至少区分待处理、处理中、待确认、已完成；记录处理人、确认人、时间及效果说明。此状态与原始在控/失控结论独立 |
| 患者结果影响 | 可记录影响时间范围、是否需要评估、处理措施和依据；首版不接入患者明细，不自动宣称患者结果可放行 |
| 附件 | 在处理记录内上传、查看/下载与说明；支持常用 PDF、图片及原始表格。具体格式、大小上限在实现时统一制定并显示，文件不执行 |
| 独立报告 | 预览、导出 PDF、保存报告版本及历史；包含原事件、原因、措施、复测、效果、人员/时间、附件清单及必要声明 |
| 查询 | 按时间、项目、仪器、处理状态筛选；能打开原记录、继续处理、查看报告和附件。为任务 2 提供统一的待处理数据接口 |

首轮以 LJ / Z-score 正式期失控事件为主。警告可以显式发起处理，但不能自动改称失控。即时法疑似离群点继续使用其现有维护流程，不强行套用正式期失控报告；通用关联结构可预留扩展。

## 3. 必须保留的业务边界

- 原失控结果、规则证据及当时快照不因填写报告或确认完成而改变。不能把“处理完成”写成“原检测在控”。
- 后续出现一个在控结果不自动结束事件；由操作者关联证据、确认处理效果。未能完成复测时可保留处理中，不强迫编造结果。
- 完成时校验必要的原因、措施、效果及确认信息；已完成记录的补充/更正保留版本、原因、人员和时间，不静默覆盖已导出报告。
- 复用既有软停用、历史锁定及数据维护边界；已被报告引用的检测若发生合法更正，应可识别差异并保留原报告依据。
- 旧手动备注继续显示，不根据自由文本自动推断原因分类或认定处理完成。
- 确认人字段仅用于记录，不引入账户权限、电子签名或多级审批。

## 4. 附件与备份

附件作为业务记录的一部分保存在应用管理的本地目录，使用稳定文件标识、相对路径及摘要信息关联数据库，避免依赖上传时的临时路径或文件名唯一性。明确重复文件、缺失文件和不支持格式的提示。

必须同步扩展现有备份/恢复、存储位置迁移流程，使数据库与其附件可一起迁移、恢复；旧版仅数据库备份仍可恢复，并明确附件缺失状态。不得只做上传成功而遗漏恢复路径。引用中的附件不直接不可逆删除，替换时保留历史关联。

## 5. 代码入口与交付顺序

优先阅读 `services/report_service.py`、`services/report_pdf_layout.py`、`pages/lj_sections.py`、`pages/zscore_sections.py`、`ui/dialogs.py`、`ui/traceability.py`、`services/lot_lifecycle_service.py`、`services/storage_service.py` 与对应迁移。复杂逻辑放在 service 层，避免扩张主页面。

1. 落实事件关联、处理状态和历史版本，增加只增不损的迁移。
2. 做“从失控记录打开 → 保存分析与措施 → 关联复测 → 人工确认”的完整路径及查询。
3. 加附件、备份恢复及迁移验证。
4. 加独立 PDF、报告历史和月报中的处理摘要/报告引用，完成整条路径验收。

## 6. 验收条件

- LJ 与 2/3 水平 Z-score 均能从失控记录进入；同一 run 只形成一份事件主记录，各水平证据完整。
- 草稿可恢复；复测选择校验项目和先后关系；不同批号/参数版本清楚展示；重复点击不重复保存。
- 原记录和判读保持不变；后续在控不会自动完成事件；缺少必要依据不能确认完成。
- 附件在重启、备份恢复和存储迁移后仍能打开；缺失文件有可理解提示；旧备份仍可恢复。
- PDF 与页面数据一致，历史版本可查；长原因、多条复测、多附件情形无内容截断或分页重叠。
- 使用隔离库和用户库副本验证迁移幂等及旧记录保留；执行受影响的三方法、报告历史、存储和新流程测试，补充实际浏览器与 PDF 逐页验收。
