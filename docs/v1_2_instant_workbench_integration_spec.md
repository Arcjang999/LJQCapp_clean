# V1.2 即时法工作台接入

> 版本提示（2026-09-11）：本文记录工作台首次接入阶段。后续批号生命周期已实现，最新准入、控制参数版本及历史保护规则以 [实现与验收说明](v1_2_lot_lifecycle_implementation.md) 为准；新 session 从 [下一阶段任务书](NEXT_SESSION_TASKS.md) 接手。LJ/Z-score 已支持经确认的人工/厂家参数，即时法仍采用本批次建靶。

日期：2026-09-11。状态：已在 Mac 实现并纳入 V1.2 整体交接提交。

## 1. 范围与操作路径

本轮按用户确认顺序，先完成即时法新版上游配置接入。试剂批号、质控品换批、控制参数版本的整体改造另见 `v1_2_lot_lifecycle_design.md`，尚未实施。

操作路径：基础资料维护仪器、试剂、质控品、批号、水平、单位和方法 → 项目模板中配置即时法检验项目 → 建立并启用批号配置 → 即时法选择项目和批号 → 当前批次录入。

接入条件：

- 模板、批号配置及关联基础资料启用，检验项目启用且方法为即时法。
- 固定单水平、20 个有效点，水平属于当前质控品批号。
- 水平使用“本批次建靶”，启用配置快照存在且水平一致。
- 工作台只选择已有配置，旧版独立创建即时法项目和批次的表单已移除。
- 普通旧即时法项目不自动迁移到新版选择器，数据库记录保留；旧即时法转入的 LJ 批次仍可查看。

这是一版软件接入范围，不表示所有即时法场景都必须采用相同的临床配置。

## 2. 保留的计算与维护规则

- 输入类型继承项目配置：真实检测值、Ct 值、log 值；已绑定项目不能改变输入类型。
- 1–2 个有效点继续累计，第 3 个有效点起执行既有即刻法 SI 检验。
- 疑似离群点在人工停用前仍参与有效统计；待处理疑似离群点阻止转入。
- 达到 20 个有效点只提示可转入，必须人工确认，不自动切换方法。
- 转入复制所有有效记录，保留检测时间、检测人、数值及备注；前 20 个有效点作为 LJ 建靶数据，之后作为正式期数据。
- 转入后源批次只读，不能新增、停用或恢复结果，不能重复转入；可跳转到对应 LJ 批次继续录入。
- 录入、维护和转入写入使用事务，检查配置可用状态与源批次只读状态。

## 3. 绑定与历史保护

新增 `services/instant_workbench_service.py`，以 `qc_workbench_bindings` 将上游配置项目绑定到 `instant_projects` / `instant_batches`。即时法使用自己的运行时表，不复用 LJ/Z-score 的 `batches` ID。

同一模板检验项目下的多个质控批号共用即时法项目，各自保存独立批次与结果。重复同步不重复创建对象，停用/恢复不删除检测记录。无检测记录时可以刷新配置展示；已有记录后冻结来源快照，不随字典改名或上游重新启用覆盖历史。

已有结果时，仪器、试剂产品、质控材料/批号、检验项目、单位、方法、水平、输入类型、建靶点数及 CV 限值等关键配置变化会阻止该绑定继续进入工作台，需另建配置。该限制是整体版本与换批机制接入前的保护措施。

工作台展示单位、检测方法、配置名称、质控水平和效期。停用配置/模板/相关字典后，即使旧页面仍打开，也拒绝继续保存或转入。选择其他项目时清空批号选择，防止把结果写入上一项目。

## 4. 转入 LJ 的来源快照

`batches.source_config_snapshot_json` 保存转入时的即时法来源快照，包含源配置及检验项目 ID、配置快照 ID、仪器、试剂、质控品、质控批号、效期、单位、方法、水平、输入类型和 CV 限值。

转入目标项目按来源即时法项目复用，避免仅凭检验项目名称把不同来源合并；同名冲突时生成独立名称。旧即时法项目仍保留既有同名/输入类型匹配策略。

LJ 当前批次与月报读取转入快照，源配置以后停用或字典改名不会改变已转入批次的单位、方法和来源。月报摘要保存 `config_snapshot_id`。原 LJ 上游配置的历史同步问题属于下一阶段批号整体改造，本轮没有改写其业务规则。
