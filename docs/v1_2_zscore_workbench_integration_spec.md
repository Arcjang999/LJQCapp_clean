# V1.2 Z-score 工作台接入规格

> 版本提示（2026-09-11）：本文记录工作台首次接入阶段。后续批号生命周期已实现，最新准入、控制参数版本及历史保护规则以 [实现与验收说明](v1_2_lot_lifecycle_implementation.md) 为准；新 session 从 [下一阶段任务书](NEXT_SESSION_TASKS.md) 接手。LJ/Z-score 已支持经确认的人工/厂家参数，即时法仍采用本批次建靶。

更新时间：2026-09-11。第一阶段已在 Mac 源码环境完成，开发分支为 `codex/v1-2-lj-integration`。

## 1. 范围与入口

复用现有 Z-score 计算、录入、图表、整次检测维护、CSV 和月报，只替换上游项目/批号选择。

从全局“基础资料”建立字典，从“项目/批次”建立并启用模板和批号配置，再在多水平工作台的“项目与批号”中选择。工作台不再提供旧项目和批次创建入口，普通旧测试项目不进入新选择器。

准入条件：

- 模板、批号配置均为 active 且未停用；
- 项目为已启用的 `zscore`，水平数为 2 或 3；
- 检验项目、本地仪器、质控品、批号和对应水平有效；
- 有效水平数量与项目水平数一致，水平属于当前批号；
- 所有水平的目标来源均为 `building`；
- 当前修订号有启用快照，水平顺序与快照一致。

人工、厂家、待确认靶值暂不进入本阶段工作台；页面显示无法接入的原因。原有厂家参考信息仍仅供参考。

## 2. 绑定和配置保护

`services/zscore_workbench_service.py` 在同一数据库事务内同步 `qc_workbench_bindings`，复用 `projects`、`batches`、`zscore_project_config` 和 `zscore_batch_config`，原始结果仍保存在现有 Z-score 表。

- 一个批号配置项目对应一个运行批次；重复同步不创建副本。
- 同一模板项目下相同输入值类型和水平数的多个批号复用运行项目，各批号结果独立。
- `qc_workbench_bindings.source_snapshot_json` 保存启用快照 ID、配置名称、字典展示信息、水平顺序和计算相关身份。
- 输入值类型和水平数在运行项目绑定后锁定。其余允许的配置变化只在尚无检测记录时同步。
- 产生检测记录后使用原始快照；仪器、试剂、质控品、批号、项目、值类型、单位、方法、水平顺序、建靶要求或 CV 要求改变时，阻止继续接入并提示新建配置。
- 字典改名不会覆盖已有检测记录的上下文。
- 停用使绑定 inactive，不删除原始记录。恢复相同配置后沿用原项目、批次和结果。
- 项目切换会清空批号选择，防止旧批号文字残留；停用当前配置会清空无效选择。

`migrations/v1_2_workbench.py` 自动增加 `source_snapshot_json` 字段，登记 `v1_2_zscore_snapshot_002`。迁移幂等，不需要手工 SQL，不迁移普通旧结果。

## 3. 保留的业务规则

- 最终判定以 run 为单位，任一水平触发 reject 即整次失控。
- 建靶保留、禁用、恢复按整个 run 联动；原始结果保留。
- 正式期隐藏建靶维护操作，历史建靶数据只读。
- 新检测保存后保留单水平/合并视图及图表控制。
- 原始值、Ct 和 log 类型从项目继承，不增加实时换算流程。
- 不改变建靶、Westgard、多水平规则模板和统计计算。

本次页面回归还修复了只有一次正式检测时外置图例被紧裁切的问题：图例不受坐标轴裁切，导出边界包含完整图例。原有图例位置保持在曲线外。

## 4. 工作台和报告

工作台显示输入值类型、仪器、试剂、质控品、水平、单位、检测方法、配置名称、效期、建靶次数及 CV 要求。

月报从绑定快照读取项目上下文，新增单位和检测方法，靶值来源标记为“新版配置：本批次建靶值”，报告快照保存来源配置快照 ID。没有绑定的旧月报仍可通过底层和报告历史读取。

统计表在样本不足时将提示换行，避免被窄列截断。报告沿用现有固定模板和生成逻辑。
