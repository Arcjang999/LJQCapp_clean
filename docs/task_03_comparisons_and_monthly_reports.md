# 任务 3：换批比对与批量月报

更新时间：2026-09-18。状态：已规划，尚未开发。顺序：任务 1、2 验收后推进；内部按 3A、3B、3C 分别交付。

## 1. 目标与现状

把需要在外部表格完成的换批比较和月底逐项整理，逐步收回现有应用。当前已有批号登记、验证结论/依据、使用事件、独立批次数据、参数版本、月报和报告历史；这些不等于已实现专门比对计算或批量月报。

依托已有批号对象、结果及报告服务增量建设，不再创建另一套平行批号体系。任务 1 的附件和报告历史能力应优先复用。

## 2. 3A：质控品新旧批号比对

### 操作范围

选择同一检测系统下同一质控产品的新旧批号、对应水平和观察期间，显示两批各自的有效结果数、检测日数、均值、SD、CV、采用参数及适用质量要求，提供并列图表和专门报告。

选择纳入结果时明确参数建立期/正式期、禁用点、警告及失控数据的处理口径；可查看未纳入记录和原因。观察期新批数据在转为正式使用后继续保留，不复制旧批结果代替新批数据。

### 判定边界

- 两批不同质控材料的浓度可能不同，不以新旧均值接近、差值为零或患者样本配对算法作为通用合格标准。
- 分别评价各批次、各水平的精密度与适用性；如需正式通过/不通过，必须有明确方案、最低数据条件、接受标准和人工确认。
- 没有独立分析批标识时只能说明结果数和检测日数，不能把“20 个点”写成“20 个独立分析批”。
- 变更参数版本时注明分段，必要时分别统计；没有适用的加权方案时不能将不同均值阶段直接混成单个 CV 并给合格结论。
- Z-score 部分水平换批按各水平的实际来源批号展示；保留水平与替换水平不混淆。
- 首轮限同产品换批号，更换质控产品另行规划。暂定/常用参数、短稳定品质控方案与长期加权 CV 不通过本轮比对功能顺带宣称完成。

### 交付与验收

能从现有“新旧批号比对”入口完成选批、选水平/期间、核对数据、填写方案与依据、保存比较记录、生成 PDF，并关联既有验证记录。没有完成的统计或依据不能自动通过验证/正式启用。

验证两个普通批次、2/3 水平、部分水平换批、数据不足、范围内有禁用/失控、跨参数版本、重复生成报告等路径。旧批、新批结果及其历史结论不变，报告包含数据范围、排除说明与采用标准。

## 3. 3B：试剂换批比对

### 操作范围

使用同一患者样本在两批试剂下得到的成对检测结果。保存检测系统、旧/新试剂批号、时间、单位、匿名样本编号、方案、接受标准、配对数据及操作者；不要求采集姓名、证件号等患者身份信息。

支持手动录入及专用模板导入。先展示配对预览，校验重复编号、缺失一侧、非数值、不一致单位或项目；问题修正后再保存。显示差值、适用的相对差异和比较图，保存实验室结论与确认依据，输出专门报告。

### 判定边界

- 清楚定义比较方向和相对差异分母；分母为零时不输出无穷值或“通过”。需要浓度分段或绝对差异限值时明确显示条件。
- 必须根据适用标准或实验室方案确定样本量、浓度分布及接受标准，不预设一个适合所有项目的百分比。
- 质量目标中的 CV 限值不能直接作为试剂比对允许偏差；TEa 的采用也必须明确适用性和评价方法，不能自动搬用。
- 首轮针对真实检测值的定量项目。Ct/log、定性/半定量比对不直接套用百分比方案；需要时另定规格。
- 修改已保存配对数据或标准时保留版本；已确认报告不静默覆盖；历史通过不能绕过后续失败或既有批号状态检查。
- 这是具体换批用途，不扩展成通用性能验证平台。比较完成不自动切换默认试剂批号，复用既有人工切换与追溯流程。

### 验收

覆盖有效配对、低浓度、零值、缺失、重复编号、单位不匹配、条件阈值边界、方案不完整、报告修订及附件恢复。每项统计可从原配对数据复算；保存/导出和批号验证关联一致，原日常质控记录不被回写。

## 4. 3C：批量月报与汇总

- 按月份、仪器、项目选择一批 LJ / Z-score 报告，先预览待生成清单、批次、数据期间、数据是否充足及排除项，再批量生成。
- 一个月涉及多个质控批号时，首轮优先分批生成，在清单中说明；不将不同批号或参数版本无说明合并。
- 复用现有单份月报内容及生成器，包括质量目标、实际批号与参数追溯；与逐份生成的统计口径一致。
- 每份报告单独记录历史和生成结果，支持统一下载（例如 ZIP）。出现单份失败时明确失败原因，保留成功清单；重试不会无提示重复创建全部历史报告。
- 汇总各项目/月的失控情况、任务 1 的未完成处理及采用质量目标后的 CV 比较；明确检测次数的分母、Z-score 的 run 粒度、统计月份、在控点数及不能评价的原因。
- 未配置执行计划时不生成“质控漏做率”；没有采用质量要求或数据不足时不算作 CV 达标。汇总不是自动月度审核或签字。
- 即时法月报仍不在首轮范围；其转入 LJ 后按现有 LJ 月报规则处理。

验收覆盖多仪器、多项目、LJ/2/3 水平 Z-score、同月多批号、空月份、无法评价 CV、单份失败和重试、报告历史追溯。解包后每份 PDF 能打开，逐页渲染检查；文件名可区分项目、批号、月份，同名文件不覆盖。

## 5. 实现位置与共同验收

主要复用 `services/lot_lifecycle_service.py`、`pages/lot_lifecycle_section.py`、`services/quality_target_service.py`、`services/report_service.py`、`services/report_pdf_layout.py`、报告历史页及存储服务。成对样本与比较计算放在独立 service，页面只负责输入和结果展示。

每个子阶段独立记录数据库变更、原数据影响、测试结果、浏览器操作与 PDF 验收，再推进下一子阶段。使用隔离库及用户库副本；附件应随备份恢复。涉及具体标准或算法时，先核对适用原文并将来源、公式和边界写入实施说明，不依据竞品截图推导通用判定规则。
