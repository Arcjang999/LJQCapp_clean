# 任务 2A：基础资料、panel 批量配置与邦德盛目录

更新：2026-09-21。状态：任务书已拆分，增量功能未开发。当前不执行开发或数据库操作。

## 1. 目标与已有基础

用户在现有系统设置中维护实验室资料；在对应仪器下创建大项目（panel），批量带入检测项，选取邦德盛质控产品及明确的实际批次，为日常整组录入提供关系。

已有项目模板、批量配置/导入、产品与浓度水平/编号、实际批号及编辑弹窗应复用。实验室信息已在“系统设置 → 报告默认信息”，由 `app_settings` 保存；目前没有独立实验室标识与账号关联。参考 [原基础资料增量](project_material_workflow_alignment.md#8-2026-09-21-面聊合并后的基础资料增量)，其中历史问题不等于全部仍待重做。

## 2. 范围与依赖

| 交付项 | 必须形成的行为 |
|---|---|
| 实验室上下文 | 复用系统设置资料，不重复建实验室信息页；仪器使用当前实验室上下文，独立组织标识和账号范围交任务 4 决定 |
| 厂家分类 | 仪器、试剂、质控品厂家按类别分别维护和选择，错误类别不混入相应候选；一个厂家承担多类业务时能分别表达 |
| panel 与检测项 | 一次带入一组检测项，共用设置可批量编辑，各项可以调整；名称、单位、方法学、输入类型和质量目标保持各自明确 |
| 质控品独立入口 | 复用产品、水平、批号对象与已完成弹窗，维护其关联的在用检测项，关系可供任务 2 查询 |
| 邦德盛产品目录 | 选产品/货号后带入经过核实的规格及覆盖项；目录来源、版本及更新方式明确，不把检验项目字典当作产品目录 |
| 实际批次选择 | 产品有多个采购批次时必须明确选择本次批次，不混合保存。多水平组合保留实际材料来源；全库互斥范围未确认时不新增此限制 |
| 配置导入导出 | 复用现有模板、预览、错误定位和导入服务，保存后关联一致；本项不是日常结果批量录入 |

任务 0 的统一质量目标核对作用到每个带入检测项。任务 2 消费本任务的有效资料关系，后续开发阶段必须采用同一查询与保存规则，不能按名称另猜一次关联。

## 3. 实施边界

数据库采用类别关联还是分表属于技术方案，不预先写死。目录查找不到不编造产品或覆盖项；新建空项目若无人工关联或可靠目录关系，不宣称已关联质控品。目录更新不覆盖已有批次和报告的历史资料。

不在本任务实现账号、软件许可、多租户、临时质控或新的统计算法。仪器与实验室的业务归属需要体现，但新增组织标识及迁移由任务 4 的最终范围衔接，不能把整个账号系统作为本任务前置。

优先核对：`pages/settings_page.py`、`services/settings_service.py`、`services/master_data_service.py`、`services/master_data_edit_service.py`、`services/project_config_service.py`、`services/project_config_io_service.py`、`services/material_workflow_service.py`、`ui/project_dialogs.py` 及 `ui/master_data_*`。

## 4. 验收条件

- 已有实验室信息只维护一份；设置修改继续作用于新报告，旧报告内容不被改写。
- 用核实目录或明确标注的隔离测试资料，一次带入生化 18—20 个检测项并批量配置；逐项调整不被以后修改默认值覆盖。
- 三类厂家候选正确，多类别厂家可正确选择；旧引用和历史显示不丢失。
- 质控品关联项在重新打开后保持一致；产品选定后仍需确定实际批次；停用资料不误进入新增选择。
- 为任务 2 提供稳定的检测项、仪器、产品、水平及批次标识，不能只返回一串名称。
- 配置导入有预览与错误定位，失败不留下半条关联；导出、备份恢复及现有多水平材料链保持一致。
- 没有正式邦德盛资料时，分别报告功能验证与目录内容的缺口，不能以测试资料冒充正式目录。

## 5. 待明确与交付

待明确：邦德盛目录的正式资料、首批范围和维护方式；跨仪器的当前批次限制；多水平当前材料的选择表达。实验室复用系统设置已明确，不重复询问是否新建页面。

交付包含界面/服务增量、必要迁移与兼容验证、实际浏览器整组配置证据，以及给任务 2 的关联接口说明。状态和依赖回填 [任务书总览](TASK_BOOKS.md) 与交接。
