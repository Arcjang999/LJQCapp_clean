表中“界面名称”是基于标准概念和用户习惯拟定的产品名称，并非全部都是标准原文。

| 当前用语或含混表达 | 整理后的界面名称 | 说明 |
|---|---|---|
| 更换质控品批次 | 更换质控品批次 | 保留用户已明确确定的入口名称 |
| 质控品换批与并行、平行观察 | 新旧批号比对 | 指质控品换批时的同时检测、分别统计和结果查看；不得误标成患者样本比对 |
| 建靶、重新建靶 | 均值和标准差建立 | 进一步注明暂定均值、暂定标准差；不能仅改标签就声称已有暂定到常用的完整流程 |
| 靶值版本 | 均值和标准差管理 | 同时提供当前值、来源、生效日期和变更记录；保留必要的版本追溯 |
| 靶值CV、实测CV、CV要求 | 设定变异系数、实测变异系数、允许不精密度（CV） | 三者分开；允许不精密度可能用标准差表示，不可全部强制百分数 |
| 草稿、配置已启用 | 待确认、批次设置已确认 | 属于资料状态，不等同于质控品正式使用状态 |

| 患者样本比对计算 | 试剂换批比对 | 本轮讨论限同一患者样本在新旧试剂批号下的成对结果；不扩展为通用性能验证平台 |
| 质量目标库 | 质量目标 | 页面内用“分析质量要求”“标准来源”“允许不精密度”“允许偏倚”“允许总误差” |
| 结构化失控闭环 | 失控原因分析与处理、失控报告 | 保留原因、纠正措施、复测及效果确认，不展示开发术语 |
| 验证附件上传 | 上传附件 | 放在换批验证或失控报告中，附上已有文件；上传本身不计算、不代表验证通过 |

## 3. 换批、均值建立和比对

标准规定在旧批用完前同时检测新旧批，为新批确定均值和控制限。稳定性较长的质控品，以至少20个独立分析批的至少20次结果建立暂定均值和标准差，再积累在控数据；稳定性较短的质控品另有方法。不能把20个数据点或某一种精密度沿用方式一律应用于所有质控品。

软件流程应区分“同一产品更换批号”和“更换质控品产品”。新批正式使用应承接其比对期间的数据，不能再建一个空批重复积累；旧批结果不冒充新批结果。即使产品未变，新批也需要自己的适用均值，不能自动照搬旧批均值。历史精密度的利用须说明适用条件、数据来源和确认依据。

现有代码有新旧批同时使用、状态变更和参数保存能力，但不能据此声称已完整实现标准的暂定/常用参数阶段、独立分析批计数、长期精密度利用或伯乐式新旧批号比对报告。下一步应核查并列出差距，再修改计算；本次没有证明现有正式启用会清空新批结果，不能把待核查项写成已发现缺陷。

新旧质控品比对与试剂换批比对都可以采用平行检测，但对象不同：前者测两批不同质控材料，后者用同一患者样本比较两批试剂。新旧质控品原始浓度不同不直接等于试剂检测偏倚，不能共用一个简单差值合格算法。

## 4. 后续五项需求的当前口径

1. 历史检测记录批号更正：保留原记录、更正原因和时间。用户已理解。质控品批号更正涉及适用参数时需专门核查，不仅替换显示文字。
2. 上传附件：用于存放已有验证表、原始记录或报告扫描件，不单设业务入口。用途解释已获用户认可；具体文件类型、保存与备份方式属于后续实现细节。
3. 试剂换批比对：录入新旧试剂对同一患者样本的结果，计算差异并形成报告。已向用户说明并获得认可：它与质控品新旧批号比对的材料和目的不同，不能共用同一判断方案。
4. 质量目标：按适用WS/T标准预置/导入，并关联检验项目、单位、浓度区间、标准版本及实施日期；实验室选择适用标准后使用。不是让每个用户重新手填标准库。现有项目字典和CV上限填写不等于质量目标库已完成。不可将允许总误差按固定比例代替标准给出的允许不精密度。
5. 失控原因分析与报告：以原因排查、纠正措施、复测结果、处理效果、患者结果影响评估及报告保存/导出组织功能。用户明确不需要“结构化闭环”等名称；权限与电子签名仍未纳入。

上述五项为用户选定的后续功能范围，不代表本次同时实施或已经完成。新 session 先完成术语和换批核查，再按任务书分阶段推进。即时法月报、LIS、权限与电子签名、安装包发布不因手册涉及而纳入。本次仅更新文档，无应用代码、用户数据库或历史记录变化；未运行功能回归，因为没有功能改动。
