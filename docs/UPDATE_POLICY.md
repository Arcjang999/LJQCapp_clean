# 更新执行约束

**每次执行 GitHub 推送、云端更新或桌面自动更新发布前，执行者必须先阅读本文件。**

本文件规定后续更新的默认流程，优先于历史交付记录中的全量验收、每轮独立工具及临时核验步骤。历史记录用于追溯当次结果，不自动成为下次更新的要求。

先按用户本次要求确定源码推送、网页部署和桌面发版的范围，再执行对应流程。

## 服务器操作入口

服务器命令、部署、日志查看和文件传输统一通过本机 **OrcaTerm 桌面客户端**执行，复用现有服务器连接，不再使用浏览器中的腾讯云 / OrcaTerm 网页终端。连接失效时在客户端恢复。连接信息及文件传输步骤见[云端部署说明](CLOUD_DEPLOYMENT.md#服务器操作入口2026-11-10)。

业务网页版的页面查看和功能验收继续使用浏览器；GitHub 既有自动构建、签名和发布流程继续执行，需要人工或助手进行的服务器操作使用上述客户端。

## 常规更新流程

**本地验证 → 备份最新数据 → 部署并重启 → 快速核对。**

1. **本地完成主要功能验证。** 记录已验证的代码版本和本次改动范围；源码及相关环境未变化时，直接引用已有通过结果。
2. **备份服务器当前资料。** 使用现有机制保存更新当时的数据、附件和配置，确认备份可用。保留当前数据库、报告、附件和保存位置。
3. **部署已验证版本。** 更新程序并重启现有服务。没有依赖变化时，沿用当前运行环境。
4. **云端快速验收。** 确认服务健康、版本正确、本次改动涉及的页面或关键操作正常，并核对原有数据、报告和附件保持。功能检查使用隔离资料，不向在用库写入测试记录。

完成后简要记录发布版本、验收结果和备份位置，引用已有日志即可。

## 按本次范围执行

| 本次修改 | 执行范围 |
| --- | --- |
| README、约束或交付记录等维护文档 | 检查内容和链接；不触发程序构建、云端部署或桌面发版。 |
| 网页功能、文案、输入控件、常规修复 | 本地验证后，执行上述云端常规流程；仅补跑受影响的少量检查。 |
| 桌面程序新版 | 通过既有 GitHub 流程完成 Windows/Mac 构建、原生验证、签名和发布。云端业务网页只在本次要求更新时部署。 |

桌面以用户2026年11月12日明确授权替换的 **1.01.1 一体安装包**（内部版本`1.1.1`、构建`2026111201`）作为新的固定基础发行，包含源码编译保护、首次启动验证码授权和自动更新器。后续常规仅从服务器拉取累计程序更新，只有用户再次明确要求重新打包发布时才替换完整Setup/DMG；原1.01、1.00文件及已有客户更新通道保留。签名、文件完整性及资料保护检查由既有自动流程执行；同一版本已通过的程序成品沿用原文件和原签名。验收工具的独立提交与受验程序来源分别记录，不能将后续工具或下载清单提交冒充原程序来源。

## 需要扩大验证的情况

仅在数据库结构或迁移、运行依赖或环境、更新器或签名发布通道、核心算法或跨模块联动发生变化时，增加相应检查。执行前说明具体变化和追加检查范围，覆盖受影响部分。

**本地已完成的完整功能回归，不在云端重复整套执行；云端全系统回归不作为每次更新的默认门槛。** 用户明确要求全系统复查时，按本次要求执行。

## 复用工具，保留当前资料

- 复用现有构建、备份、部署和更新通道。常规更新不临时新建发布框架、证据延续工具或逐轮专用核验脚本。
- 已有自动检查照常执行，不额外安排同内容的人工全量下载、凭证往返或多轮重复验收。
- 检查失败时定位具体问题，修复后重跑受影响项，保留原结果；不要因此重新开展全部检查或新增一套验收体系。
- 实际业务或资料核对出现差异时，先处理差异再切换。保留最新业务资料，旧备份不得覆盖更新后新增的记录、报告或附件。

云端操作入口见[云端部署说明](CLOUD_DEPLOYMENT.md)，桌面构建和更新入口见[桌面更新说明](desktop-updates.md)。
