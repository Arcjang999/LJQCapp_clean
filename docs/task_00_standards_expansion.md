## 1. 已确定的要求

2026-09-22 最新补充：质量要求工作目录只显示现行且适用的依据，不展示废止或尚未生效版本，参考区间不混入质控要求；按实际检验项目查找分子/免疫等依据。界面永久禁止显示编程语言标签、代码、开发说明注释、堆栈和内部实现提示；保留必要文件类型和业务条件。来源的历史元数据仅为内部核查及既有采用记录追溯保留。

2026-09-22 用户补充：任务 0 必须完成可见、可用的目录及项目/批次流程；旧数据不作为适配约束，不需要为旧数据延后交付。新增全软件搜索栏的模糊匹配要求，检索结果仍需按实际条件确认，不能用模糊匹配直接采用质量标准。以下旧数据保护条款不再构成此次交付的前置条件；本轮无需主动删除原库。

2026-09-21 需求合并：面聊中的“有适用精密度要求自动带入、无适用要求时允许自定”直接并入本任务，不再建第二套质量目标功能。总归属见 [需求合并稿](requirements_merged_2026_09_21.md)。当日仅更新文档；2026-09-22 的开发结果见上方实施记录。

选择检验项目后，必须带出国家已发布、现行且适用的标准；匹配明确时默认选择，项目确认和新批次确认前必须完成采用。不能跳过适用标准、清空来源或换成较宽松的自定值来启用配置。没有适用条目才允许实验室要求，并记录查找结果、依据、版本、确认人和日期。

“国家有的标准”按来源准确分为国家标准、卫生行业标准等。强制采用是本软件的配置要求，不把推荐性 WS/T 写成法律强制国家标准。国家标准与行业标准需按适用内容、时效和引用关系一起核查，不能仅按标准层级机械替代。

项目可以混合分子、免疫、生化检测和单水平/多水平方式，标准落实到**具体检验项目、检测方法、结果尺度及质控水平**。工作分组不决定标准，也不决定 LJ/Z-score；Ct 值、浓度定量、log 值、S/CO 等信号和阳性/阴性结果不能视为同一种结果。

大项目（panel）可批量带入检测项；各项仍分别匹配适用要求，不能给整组统一套一个 CV。邦德盛产品目录用于带入货号、规格和关联检测项，质量目标采用仍来自本任务的标准/实验室要求，不因选择品牌自动确定标准。

## 2. 开工前系统边界（历史基线，当前见实施记录）

- `resources/quality_targets_2024.json` 已有 WS/T 403—2024 的 82 条及 WS/T 406—2024 的 12 条，共 94 条。403 已包含部分免疫球蛋白、甲状腺激素和肿瘤标志物；406 是血液与凝血，不是两份都只有生化。
- `quality_review_service.py` 已要求新项目/新批次完成来源核对；当前候选主要按名称/别名匹配，用户可填写不适用原因后采用实验室要求。**这还不等于经结构化条件判断后锁定适用标准**。本任务需要补齐条件匹配、明确适用时禁止绕过，以及目录未覆盖时的标准登记复核。
- 当前一个质量目标来源不能完整表达“项目定量指标＋PCR方法质控要求”等多个并行依据。后续在保留原 `quality_goal_json` 读写兼容的前提下增加相关标准采用记录，不把全部要求挤进一个 `cv_limit`。
- 自动比较只支持现有 CV 路径；SD、偏倚、TEa 等仍只展示。文字条款、定性一致性、对照设置等可以先保存适用依据与核对记录，不伪造计算结果。只保存依据不等于已落实全部条款。

## 4. 数据和服务调整

1. 新建可审查的来源索引：标准编号、类型、名称、版本、发布日期/实施日/废止日或替代关系、官方 URL、全文校验值、核对日期、条款与页码、核对状态。只有正式发布并核对通过且到实施日期的条目进入可采用目录。
2. 将适用条件与质量指标分开：检测对象及标准化代码/别名、方法、标本/基质、定量或定性、结果尺度、单位、浓度/类别和使用目的；允许标准未限定某字段，不能伪造限制。项目名称和工作分组仅用于检索推荐。
3. 区分数值型 CV/SD/偏倚/总误差、定性要求、过程/对照要求和参考区间。当前不支持计算的指标写明“已登记依据，尚无自动评价”，不能因为没有数值 CV 就说没有标准。
4. 在 `services/quality_review_service.py` 统一判断：明确适用→必须采用；信息不足→待补充不能确认；明确不适用→记录与条款对应的具体条件/依据。自由文本“不想用”不能放行已确定适用的标准。多个标准互补可并行关联；冲突需记录取舍依据，不能按任意排序取第一项。
5. 实验室可在满足标准前提下采用更严要求，保留标准基准及补充来源；两者须同量纲、同用途、同浓度条件，不能直接比较不同指标数值大小。
6. 当前目录缺少条目时显示“目录尚未收录/待核查”，允许保存草稿。补充官方来源并核实后采用；确认没有适用条目或仅无对应数值指标时，可登记实验室补充要求，但仍关联适用的过程标准。不可直接把“搜索不到”当作“国家没有标准”。
7. 项目保存/确认、新批次确认、复制、配置导入、整批及部分水平换批共用校验；从不同页面或服务调用不能绕过。旧已确认批次保留旧采用版本，新/编辑草稿按新规则核对。
8. 若增加标准/适用条件表，采用只增不损迁移，先在副本检查重复初始化、旧数据、报告和备份还原；不得在真实库上做测试。

## 5. 界面与交付顺序

范围保持：实验室上下文、厂家分类、质控品独立页和产品目录并入任务 2A；批量结果录入归任务 2，独立临时质控归任务 2B；账号权限为主框架后的任务 4，更正、补录及联动重算为任务 5。本任务复用现有弹窗，不重复开发上述功能。后续新入口接入同一质量来源服务，不能把尚未实现的入口列作本次已经通过的验收项。

1. 先完成 403 已有免疫项目覆盖核对及 230/494 的逐条来源清单；不要直接把整份 PDF 数值批量写成 CV。
2. 在检验项目新增/编辑弹窗内显示适用标准、依据类型及待补充条件。确认按钮明确说明未完成原因；选项目后不能留到日常录入才发现标准未配好。
3. 批次按实际质控品/水平核对适用范围；标准版本和核对结果进入批次及报告追溯。与 LJ/多水平/即时法选择独立。
4. 完成跨入口禁止绕过与旧数据保护测试，再做整条流程、高缩放和打包验收；最后继续任务 1→2→3。本任务不扩展成通用性能验证、临床患者诊断或自动报告放行系统。

## 6. 必须通过的验收样例

- 已有免疫项目如 IgG、TSH、AFP 能找到正确来源，不因分组不同漏掉；单位或浓度条件不同不盲目采用。
- 适用标准未选、自定值更宽、只填排除理由但实际适用、导入/复制绕过均不能确认新配置；允许保存待补充草稿。
- 实时荧光 PCR 与测序/恒温扩增分开；Ct/log、IU/mL 等浓度、定性/S/CO 不互套限值。阴性对照不被当成缺失浓度或用于计算不适用的 CV。
- 适用的过程标准必须关联，但未实现的核对/评价清楚显示范围；不把关联标准等同全条款符合。
- 新版未生效、旧版废止、标准互补/冲突、目录未收录、确无适用条目均有明确去向；旧批及历史报告不被目录升级改写。
- 混合分子/免疫项目逐检验项目采用标准，单/多水平和即时法 3/20 点流程不改变。全链同一数据的统计、规则和历史判读不变。
- 同一 panel 中批量带入的检测项分别显示适用依据及缺项；统一设置或从产品目录带入不能覆盖各项适用条件。未来新增目录选取/批量录入入口时补做接入验收。
