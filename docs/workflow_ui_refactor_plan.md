# 项目中心流程与弹窗交互改造计划

日期：2026-09-20。工作分支：`codex/project-workflow-alignment`。

最新状态：用户已授权先实现一版试用，首版已接通并完成 29 套相关回归，范围、独立预览、迁移与浏览器结果见 [首版实施与验收](ui_workflow_trial_implementation.md)。详细批次参数及其他字典界面仍待统一，完整高缩放及打包待验收；本计划不是全部已完成。全部未提交工作继续保留。

下文保留开发前的整合方案和分阶段验收要求，下一步以用户对首版的试用反馈及实施说明中的未完成项为准。

## 1. 总体判断

需要重点重做的是用户进入系统的路径、资料之间的关系、编辑与确认操作，以及承接这些流程的状态管理。现有质控计算、结果存储、参数版本、质量目标来源、历史追溯、报告生成能力继续复用。

用户已明确的交互模式是：**主页面查看列表与详情；新增、编辑在弹窗完成；删除或停用在确认弹窗完成。** 日常质控录入、查看图表仍留在主工作区，不把每次检测录入也变成弹窗。

建议先继续使用 Streamlit，做一个真实可操作的列表与弹窗样板，再决定是否扩大到全部页面。若样板无法达到需要的键盘操作、表格交互和布局稳定性，优先评估 PySide6 原生界面；计算服务和 SQLite 数据可继续复用。不要通过大量依赖网页内部结构的样式、脚本去维持难以验证的交互。

## 2. 不变边界与验证办法

以下规则和算法不因本次改造而变化：

- LJ 的参数统计、控制限、现有 Westgard 规则及连续窗口口径。
- Z-score 的标准化计算、2/3 水平支持、整次检测的联合结论、建靶维护按整次检测联动。
- 即时法的格拉布斯检验、SI 提示、3 个有效点开始检验、20 个有效建立点后人工确认转入 LJ。
- 输入值类型为真实检测值、Ct 值或 log 值；不重新引入录入时随意转换输入尺度。
- 建靶点的纳入/禁用、正式参数冻结与生效时间、已进入正式期的维护锁定。
- 质量目标按来源与版本确认，CV 比较继续采用既定有效统计口径；SD、偏倚、总误差不因界面改造扩展为自动评价。
- 旧检测、旧判读、旧参数版本与旧报告保留原始来源，不跟随新资料设置回写。

“算法不变”需要通过同一批输入的回归比较证明。建立覆盖正常、警告、失控、建靶禁用、参数变更、不同输入值类型、Z-score 整次检测、即时法转换的固定样例；改造前后比较阶段、有效点数、均值、SD、CV、Z/SI、触发规则和最终结论。浮点统计使用与现有算法一致的容差，身份和规则结论准确匹配。

实际材料与参数映射改变，可能让同一个计算函数收到错误数据。因此，还要校验输入适配与顺序，而不能只检查算法文件是否发生差异。

## 3. 统一业务层次

| 层次 | 内容 | 约束 |
|---|---|---|
| 工作分组 | 如血筛、分子、生化；用于组织和筛选 | 可包含多个仪器项目，不决定使用 LJ 或 Z-score |
| 仪器项目 | 某台实际仪器上的一组检验项目与适用资料 | 沿用现有项目能力；不同仪器在同一工作分组下建立各自项目 |
| 检验项目 | 检测项、试剂、方法学、单位、输入值类型、质控方式 | 项目默认值带入，逐项可调整；实际配置是最终依据 |
| 质控产品与浓度规格 | 厂家、产品系列、浓度水平、浓度编号，必要时规格货号 | 编号为文本，保留前导零；不等同具体赋值或组合位置 |
| 实际质控材料 | 产品规格、实际生产批号、效期 | 兼容各水平不同批号及同号多水平；不能用一个主批号代表全部材料 |
| 使用批次/组合 | 检验项目本次选用的一个或多个实际材料 | 单水平可使用任意浓度规格；多水平按组合位置保存各自身份 |
| 参数及检测 | 对应材料的适用均值、SD、质量目标、检测记录和判读 | 独立版本与适用时间，完整追溯 |

首次建立多水平配置和以后仅更换其中一个水平，使用同一套材料选择与校验能力，不再设计两套不一致的资料关系。

“方法学”和“质控方式”分开。LJ 图并非分子专用，Z-score 也不是生化/免疫专用；Z-score 可用于标准化不同质控材料的结果，LJ 图可显示多水平数据。专业分类不能自动锁定计算流程。[Westgard 对多材料绘图及标准化的说明](https://www.westgard.com/lessons/westgard-rules/westgard-rules/quest4.html)

## 4. 即时法的界面位置

主入口不再要求先选 LJ、Z-score、即时法。进入检验项目及批次后，界面显示两个独立信息：**本次使用的水平数量**和**当前参数状态/建立流程**。

| 本批设置 | 用户看到的流程 | 现有内部实现 |
|---|---|---|
| 单水平，已有适用且经确认的参数 | 正式质控，查看 LJ 图与判读 | 复用 LJ |
| 单水平，按常规流程积累本批数据 | 参数建立期，之后进入正式质控 | 复用 LJ 建靶流程 |
| 单水平，选择即时法积累 | 即时法参数建立；3 点起检验，20 点后提示人工确认转入 LJ | 复用即时法和原转换服务 |
| 多水平，参数未齐/未确认 | 各水平参数建立与确认 | 复用 Z-score 建靶流程 |
| 多水平，全部参数适用并确认 | 多水平联合质控，查看分水平图或合并图 | 复用 Z-score |

即时法仍是用户明确选择的路径，不由“患者样本量少”“分子专业”或记录尚不足 20 条自动推定。不给现有多水平项目补造一套即时法算法，也不自动把已有数据在 LJ 与 Z-score 之间转换。

暂保留底层 `qc_method` 编码和已有方法服务。先调整外部入口、状态说明与适配层，不为改变术语而批量重命名或迁移历史方法记录。

## 5. 目标界面

### 5.1 页面框架

采用固定模块导航、紧凑工具栏、列表和详情组成的界面。减少大标题、大卡片、整页展开表单和逐层下拉框。

```text
模块导航       当前工作分组 / 仪器项目 / 检验项目 / 使用批次
项目工作台     搜索…  筛选…       新增  编辑  停用  导入/导出
基础资料       ┌───────────────────────────────────┐
质量目标       │ 记录列表：点选一行，明确高亮当前记录 │
报告历史       └───────────────────────────────────┘
系统设置       详情 / 当前批次 / 参数与目标 / 历史
               [查看内容或日常录入与图表]
```

首轮不要求复杂可拖动树或多个浮动窗口。分组与项目列表可固定在左侧区域；右侧显示选中内容。窄屏/高缩放时允许详情移到列表下方，避免挤压录入框和图表。

单击选择记录，使用明确的“编辑”按钮打开弹窗。双击编辑、右键菜单、全局快捷键可在样板阶段评估，不将默认组件没有保证的行为写成首版承诺。

### 5.2 各页改法

| 页面 | 主页面保留 | 弹窗操作 |
|---|---|---|
| 项目工作台 | 工作分组/项目与检验项目列表、当前批次、数据录入、图表与结论 | 新增/编辑项目、检验项目、建立批次、批次资料编辑 |
| 基础资料 | 厂家、仪器、试剂、质控品等分类列表；选中记录详情 | 新增、编辑、批号及浓度规格登记、停用/恢复确认 |
| 质控品详情 | 产品基本资料、浓度规格列表、实际批号及效期 | 在同一登记弹窗选规格并填批号；需要新增规格时在该弹窗内完成 |
| 项目设置 | 默认配置摘要、逐项配置列表、完整性提示 | 编辑默认值、添加/编辑检验项目；改默认值不覆盖既有逐项设置 |
| 批次/换批 | 各水平实际材料、参数状态、质量目标及历史组合 | 建立/编辑未使用批次、逐水平换批、确认参数或目标；已固定内容改为查看详情/新版本入口 |
| 质量目标 | 标准目录与项目目标列表、来源详情 | 选择/调整项目目标、实验室自定义/编辑；批次内确认其具体适用条件 |
| 检测记录 | 正常记录列表与图表、原判读与维护状态 | 编辑/更正、禁用/恢复并填写原因；保留不可修改阶段的只读查看 |
| 报告历史 | 已生成报告列表、筛选、下载及预览 | 必要时填写报告生成选项；不覆盖历史报告 |

资料缺失的提示应定位到具体对象并提供“新增…”操作，完成后带回原选择。不能为了登记一个水平把用户送到另一个大页面并丢失原批次草稿。

### 5.3 新增与编辑弹窗约定

1. 标题明确对象与动作，例如“新增质控材料”“编辑检验项目：CRP”；同一表单复用新增和编辑的字段与校验。
2. 查看状态不开大量可编辑框。点击编辑才载入当前记录及版本，只有“保存”会写入正式数据。
3. 底部固定语义为“取消 / 保存”。大批次设置可在一个较宽弹窗内分步骤，显示当前步骤与必需信息。
4. 校验失败在字段附近说明原因，保留全部输入；不因一次错误清空整个弹窗。
5. 保存成功关闭弹窗，返回原列表位置并选中新记录；保留搜索、筛选、当前项目与批次。
6. 脏草稿的取消操作显示“放弃修改/继续编辑”。为实现可靠检查，编辑弹窗可禁用点击外部和 Esc 直接关闭，使用明确取消按钮；在同一弹窗里切换确认视图。
7. 不叠加第二个弹窗：例如编辑批次时新增一个浓度规格，在当前弹窗切换子步骤，并能返回已保留的批次草稿。
8. 普通页面重绘不能丢输入。浏览器关闭/强制刷新不承诺自动恢复未保存输入；长流程如需跨会话恢复，另提供明确的“保存草稿”。
9. 键盘 Enter 不触发删除；多行备注保留换行。保存触发方式、Tab 顺序和焦点返回需在浏览器及打包桌面窗口实际验证。

### 5.4 删除与停用确认

用户要求的是确认交互，同时继续遵循现有历史保留规则：

| 对象 | 操作语义与确认内容 |
|---|---|
| 未保存的新增草稿 | 取消/放弃填写，存在修改时确认；不创建空记录 |
| 已保存的基础资料/配置 | 优先提供“停用”或可恢复移除；弹窗显示对象名称、引用关系、原因与影响 |
| 已被批次或检测引用的资料 | 使用停用、新版本或更正；不能以删除按钮物理删除历史引用 |
| 原始检测结果 | 保留原值及原判读，通过允许的禁用/恢复或更正处理；不增加硬删除路径 |
| 正式期不可维护的记录 | 只读查看，隐藏不可用操作并解释锁定原因 |

若界面使用“删除”一词，确认框必须如实说明是移入可恢复区域还是不可删除；不能把“只停用”伪装成彻底删除。不会因本次 UI 改造开放已禁止的硬删除。

确认对话框默认突出“取消”，操作按钮写“确认停用 ××”或“确认删除 ××”，不使用含糊的“是/确定”。弹窗仅用于保存边界及必要确认，不给普通搜索、切换视图增加确认步骤。

### 5.5 有适用标准时，质量目标必须关联并确认

2026-09-20 用户补充：存在适用质量标准的检验项目，希望选择时必须带上标准；无适用标准的项目由实验室设置要求。该要求纳入本计划，尚未实现。

这是软件的配置规则。界面使用“标准来源”，准确显示国家标准/卫生行业标准等来源类型；不能把所有内置条目统称“国标”，也不能把软件要求解释为法律强制。当前内置 WS/T 403—2024、WS/T 406—2024 均为推荐性卫生行业标准。[国家卫生健康委发布通告](https://www.nhc.gov.cn/fzs/c100048/202407/758b8a012f4748c9b23ee48d22d0a79a.shtml)

| 匹配与确认状态 | 新增/编辑检验项目中的行为 |
|---|---|
| 有明确适用的已收录标准条目 | 自动带出候选来源、版本、指标及范围，用户确认采用；确认配置时不可留空，也不可清空改成无来源的手填值 |
| 有多个候选或适用条件未明确 | 显示“待确认”，核对检测对象、方法、单位、输入尺度和浓度/类别后选择适用条目；不按名称相似度自动正式采用 |
| 候选标准对当前检测方法/输入尺度不适用 | 记录不适用的具体依据，重新确定适用来源；不能因为有同名候选而套用错误指标 |
| 当前目录未找到适用条目 | 明确写“当前目录未找到适用标准”，允许补充经核对的标准来源，或登记实验室自定要求、说明书/SOP 等依据；不宣称该检测项客观上不存在任何标准 |
| 实验室或说明书要求更严 | 保留已确认标准原文及版本，另记实验室采用值和依据；仅对同一指标、尺度、范围及比较口径验证是否更严，不覆盖标准原值或允许随意放宽 |

选择具体检验项目时就展示标准匹配和确认状态，避免用户事后另去质量目标页搜索。项目阶段确认来源与适用性，批次阶段再按实际材料逐水平核对浓度/类别，保存冻结副本。允许中途保存草稿；新配置确认/启用前完成相应核对，不把“草稿已保存”当成“已确认适用”。不改变既有建靶点数或进入正式期的计算条件。

“分子类”不是自动豁免标识，要看具体检测对象、结果尺度和要求。当前质量目标服务只接受原始浓度/检测值，Ct/log 不能直接采用本轮浓度尺度标准，连自定义目录也有此限制。新界面应保留现有参数设置，支持记录实验室要求及依据；不为满足必填强塞 CV，也不在本次交互改造中增加 Ct/log、SD、偏倚或总误差的自动评价算法。未支持的指标明确显示“仅记录，暂不自动评价”。

实现需补齐统一服务校验：项目匹配关系使用稳定检测项身份并保留人工适用性确认；目前名称/别名仅用于推荐，不足以执行强制规则。检查 `adopt_requirement`、`clear_requirement`、`validate_lot_goal` 及配置确认、导入、复制、换批、工作台绑定入口，避免只禁用一个下拉框，却能通过其它路径绕过。现有空目标可通过校验的行为需要按上述状态区分；自定依据、适用状态与更严要求的存储/版本方案应单独设计，不把它们塞进无结构的备注后假定校验已完成。

规则用于新建或重新确认的配置。已固定的旧批次、参数、结果和报告不自动补配或回写；发现缺少关联时提示，在后续新批次或明确的新版本流程处理。

## 6. Streamlit 的可行性与限制

本机开发环境为 Streamlit `1.63.0`，已核对 `st.dialog`、`st.dataframe` 的本地函数签名。`ui/dialogs.py` 已使用 `@st.dialog` 做检测记录维护，因此不是从零验证弹窗是否存在。`requirements.txt` 尚未固定 Streamlit 版本；样板通过后应固定验收版本及必要依赖，再做打包回归。

| 目标 | 当前路线 |
|---|---|
| 新增/编辑/确认弹窗 | 原生 `st.dialog`，复用公共草稿、校验、关闭和通知逻辑 |
| 点选列表行查看详情 | `st.dataframe` 的行选择事件加稳定记录 ID；行号不能直接充当业务身份 |
| 批量数据输入 | `st.data_editor` 或既有录入表单；支持范围在样板中实际核对 |
| 输入时减少整页刷新 | 弹窗局部重绘；独立工作区酌情使用 fragment；保存后再刷新受影响列表 |
| 批量提交字段 | 简单表单使用 `st.form`；有级联选择的表单使用显式草稿状态和局部重绘 |
| 传统列表、工具栏、左右区域 | 可用标准容器和统一样式实现；先验证固定布局与高缩放，不追求任意拖动布局 |
| 原生多窗口、停靠面板、复杂右键、全局快捷键与精准焦点 | Streamlit 非主要优势；超出样板能力时评估原生 Qt，不承诺直接复刻桌面软件 |

一次运行只允许一个弹窗；弹窗里的输入通常只重绘该弹窗。关闭行为和写入副作用需由应用管理。[Streamlit 弹窗文档](https://docs.streamlit.io/develop/api-reference/execution-flow/st.dialog)

表单里的关联输入不会在每次选择时向后端更新，不能把产品选择、规格列表联动和保存全部塞进一个 form 后期待即时联动。[Streamlit 表单说明](https://docs.streamlit.io/develop/concepts/architecture/forms)

局部重绘和行选择能力已有官方支持，仍需自行正确管理跨区域状态。[Fragments](https://docs.streamlit.io/develop/concepts/architecture/fragments)、[1.63.0 数据表选择](https://docs.streamlit.io/1.63.0/develop/api-reference/data/st.dataframe)

QCBOX 的具体实现技术尚未有可靠证据，不能从外观判断其是否使用 Unity 引擎。伯乐的 Unity 同时是质控软件产品名称，不能仅凭同名当作游戏引擎的技术证明。[伯乐 Unity 软件资料](https://www.qcnet.com/qc-data-management/unity-software-solutions)

项目已有 `packaging/desktop_qt_launcher.py`，使用 PySide6 的窗口与 QWebEngineView 装载网页；这能提供桌面启动体验，但不会让内部 Streamlit 页面自动变成原生控件。

如果最终要求接近传统 Windows 专业软件的多窗口、复杂表格和快捷键，PySide6/Qt Widgets 是更直接的候选。它提供原生主窗口、表格和对话框；迁移界面仍有成本，应在共享服务边界稳定后实施。[Qt Widgets 官方说明](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/)

## 8. 当前初稿必须重新检查的地方

- **UI 与新偏好不符**：`ui/materials.py`、`ui/project_navigation.py` 仍是展开区/下拉式初稿，应改为列表和弹窗后再验收。
- **同一行联合筛选**：现有初稿分别汇总一个项目的全部方式与全部方法学；多条件可能分别由不同检验项目命中。应明确按同一检验项目同时匹配，并展示匹配项。
- **材料唯一性与效期**：初稿按产品+批号复用批号记录，且拒绝同号不同效期；新增同名水平也会拒绝。应重新审定“产品规格+实际批号”的身份边界，兼容真实包装方式，不能仅按显示名判重。
- **新组合与原主批号**：初稿为兼容旧表保留配置主批号。所有效期校验、下游身份、列表摘要和历史来源必须以实际材料为依据，不能遗漏一个仍读取主批号的消费者。
- **固定边界**：已保存、已确认、已开始使用、已有结果是不同状态；不能仅以“已有检测结果”作为保护历史参数或材料身份的唯一条件。
- **即时法转换后的入口**：转入后首页应打开正确 LJ 批次，原即时法保留历史入口；需查证现有转换绑定与导航，不能只改页面标签。
- **测试状态**：现有四个相关套件初轮通过，不代表新工作流验收通过；`cv_setup` 的旧选择器测试需要改为验证新路径的同一业务结果，不能删掉断言以求通过。

## 10. 样板与最终回归检查

交互样板使用测试数据和独立数据库，不连接实际用户库。它必须使用真实 Streamlit 控件验证能力；静态设计图只能说明布局，不能证明焦点、保存与重绘行为。

- 点选、排序、筛选后编辑正确记录；筛选改变后不因行号变化误删其它对象。
- 新增/编辑出错保留输入；取消不写库；重复提交不重复新增；提交时发现停用/修订变化能明确提示。
- 关闭带修改的弹窗有放弃提示；保存返回同一列表位置；连续打开不同记录不串值。
- 新建批次逐水平选择不同实际批号；仅换一个水平后，旧检测与旧报告仍对应原组合。
- 单水平可使用厂家高值或 Level 3；浓度编号 `001`/`L02` 原样保留。
- 默认设置改变不覆盖既有逐项配置；分组、方式、方法学筛选的结果准确且可解释。
- 有明确适用标准时必须关联确认；存在多个候选、目录无匹配、同名不适用、Ct/log、SD 条目、不同水平条件及实验室更严要求分别验证；清空、导入、复制或旧入口不能绕过新配置规则，旧批次不回写。
- 即时法有效点条件、禁用后计数、转 LJ 确认与返回新批次正确；不自动转换原数据方法。
- Enter、Tab、长备注、输入失焦、双击/重复点按在实际浏览器验证；不把 AppTest 当成所有键盘行为的证据。
- 验证常规窗口和实际可取得的高缩放环境；记录未覆盖的系统分辨率，不能把缩小网页视口等同系统缩放验收。
- 原三方法计算基线和相关 smoke suites 通过；新生成 PDF 检查中文、图例、材料编号/批号和分页；备份恢复包含新增资料与引用。

本轮没有运行上述未来验收，也没有改变计算实现、真实数据库或提交状态。
