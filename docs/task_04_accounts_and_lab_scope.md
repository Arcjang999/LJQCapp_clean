# 任务 4：账号权限与实验室关联

更新：2026-09-21。状态：主框架后的任务书草案，未开发。实验室组织模型和授权范围仍有待确认项；当前不执行开发或数据库操作。

## 1. 目标与已确认范围

区分普通账号与管理员：普通账号不可直接修改历史数据，管理员能够进入后续更正、补录和记录排除流程。实验室信息复用已有系统设置，不能另建一份重复资料。

实验室当前保存的是实验室名称、科室、负责人等默认文本；填写负责人或审核人不构成账号、认证或权限。任务 5 需要真实的身份与权限判断。

## 2. 建议方案与待确认边界

以下是实现建议，不是已经确认的新增业务要求：

- 在系统设置管理账号及实验室资料，管理员维护账号状态和角色。
- 实验室作为共用组织资料；成员账号与角色关联实验室，仪器关联实验室，panel 仍为业务项目。
- 当前一个实验室可以先支持多个账号；独立实验室标识用于稳定引用，改名称不改变身份。

待明确：是否只需一个实验室、账号是否可属于多个实验室、谁维护实验室资料、普通账号的补录权限、首次管理员建立与恢复方式。“授权账号”是否还包括软件使用许可另行确认，不能默认增加付费、联网激活、订阅或多租户平台。

## 3. 交付范围与职责

| 范围 | 交付边界 |
|---|---|
| 身份与会话 | 按确认方案建立账号、登录/退出、身份识别和会话失效；管理员来源不能依靠填写操作者姓名 |
| 角色与账号管理 | 普通/管理员权限、账号启停、角色变更；管理操作记录实际账号身份。其他角色或多级审批没有确认为本次需求 |
| 服务层权限 | 录入、历史维护、批量导入等入口共用授权判断；不能只隐藏按钮而允许服务调用绕过 |
| 实验室设置 | 复用现有设置入口；若确认引入组织标识，保留现有实验室和报告默认信息，关联仪器与成员，不改变历史报告内容 |
| 任务 5 对接 | 提供当前账号、授权范围及权限校验能力；任务 5 调用同一机制，更正、补录和排除的业务实现仍由任务 5 交付 |
| 旧数据与备份 | 未记录账号的历史操作者保留原文本，不伪造账号来源；身份、角色及实验室关系的迁移和恢复纳入验证 |

账号停用、退出或权限变化后，陈旧页面不能继续凭旧会话保存受限操作。具体认证存储与恢复方案在实施时确定，不把这份任务书当作已选定技术栈。

## 4. 验收条件

- 普通账号不能从界面、导入入口或服务路径修改历史；管理员能通过受限操作的统一权限检查。
- 手工填写“管理员”或修改操作者文本不会提升权限；退出、停用或撤销角色后，未保存旧窗口无法绕过限制。
- 实验室设置复用原有资料，账号接入不导致报告默认信息丢失，也不要求用户重复登记实验室。
- 如最终选择多实验室范围，验证账号访问与仪器数据隔离；如仅单实验室，明确未实现多实验室，不能以标签筛选冒充隔离。
- 旧检测结果、原判读和未知历史人员信息保留；迁移重复运行以及备份恢复不产生重复账号关系或越权。
- 任务 5 尚未接入时，明确本任务完成的是身份/权限能力，不声称历史更正与重算已交付。

交付身份与角色机制、设置入口、服务层校验、必要迁移与隔离验证，以及任务 5 可复用的身份/授权接口说明。按 [任务书总览](TASK_BOOKS.md) 回填状态，保留未确认方案，不擅自上线。
