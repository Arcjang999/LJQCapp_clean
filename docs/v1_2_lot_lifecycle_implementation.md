# V1.2 批号生命周期：实现与验收

日期：2026-09-11。适用分支：`codex/v1-2-lj-integration`，当前为本地开发版本。

## 使用入口

打开「项目/批次」→「批号使用与追溯」。日常录入仍在 LJ、Z-score、即时法工作台完成。

1. **试剂批号**：登记试剂产品、生产批号、效期；按检测系统登记验证结论、依据和确认人。验证通过后，明确勾选本次受影响的检测项，确认默认批号切换。日常结果保存实际使用批号，默认批号变更不回写既往结果。
2. **质控品换批**：在同一项目下复制到新质控品批号，可只选择部分检测项。新序列从空记录开始，旧序列保留；新旧批可平行使用，参数确认及验证后再正式启用，旧批可结束使用。未来的状态计划按生效时间应用。
3. **部分水平更换**：Z-score 可建立新的 2/3 水平组合，各水平保存实际质控批号。未更换水平保留旧参数版本的引用，确认界面可预填其参考值；完整组合仍需确认全部水平参数，或按本批次建靶流程完成后，才能正式联合判定。
4. **控制参数**：LJ/Z-score 可确认人工、厂家来源或修订后的完整参数版本，填写依据、确认人及生效时间。厂家参考值不会仅因复制而直接成为正式参数。即时法继续沿用单水平建靶及人工转入 LJ 的流程。
5. **历史追溯**：工作台及管理页可查看逐次检测的配置、实际试剂批号、各水平质控批号、参数版本和判定版本，并导出。试剂切换错误通过追加更正事件处理，既往检测记录保持原上下文。

2026-09-11 接续修正：质控批验证按本检测系统、实际批号和生效时间的最新结论校验，旧通过不能绕过后续失败；正式启用检查每个实际批号效期及批号/水平停用状态。混合组合正式启用须逐批选择验证，完整关联保存于事件详情；未换水平的预填参数仍须在全部水平确认后生效。试剂换批预览先选择启用时间，再展示当时最新验证。录入同时检查当前只读锁与检测时间对应的质控批使用状态。

## 计算和历史行为

- 同一试剂产品换批，沿用适用的控制参数版本和原序列；不因试剂批号不同自动清空连续规则窗口。
- 质控品新批/新水平组合建立新序列；参数修订建立新版本。跨参数版本分别计算适用的连续窗口，沿用既有 Westgard 判定规则。
- LJ/Z-score 首次完成本批次建靶时冻结正式参数。旧系统已存在的正式点与首个自动建靶版本之间保留适用的连续规则窗口。
- Z-score 最终判定仍按整次 run，建靶维护仍按整个 run；合并视图连续录入后保持原视图。
- 即时法保持 3 个有效点开始 SI、20 个有效建靶点后人工确认转入 LJ；每条记录的实际批号和来源追溯随转换保留，源批次只读。
- 已有结果的来源配置不会随字典改名或上游同步被覆盖。原始结果禁止物理删除；允许的维护/重算保留判定版本链。既有显式演示数据刷新可清理演示项目，服务拒绝借此清理正式项目。
- 保存结果、上下文和判定采用同一事务。陈旧表单中的批号版本会被拒绝并要求刷新；导入确认整批成功或整批回滚。

## 导入、导出和报告

LJ/Z-score 的 CSV/XLSX 导入支持可选「实际试剂批号」列。预览校验产品、验证适用日期和效期；空白保持「未记录」，不会拿今天的默认批号填历史数据。旧模板仍可导入。

图表支持实际试剂批号变化标记；LJ 控制线按参数版本分段，Z-score 各水平取对应版本均值和 SD。LJ/Z-score 月报增加追溯附页，列出实际批号、相关变更事件、参数来源和按参数版本/水平分组的统计。跨版本的总体均值、SD、CV 不再混作单一参数汇总；既有报告历史保留生成时的摘要。

## 数据库迁移

新增迁移：`migrations/v1_2_lot_lifecycle.py`。新增批号、验证、事件、使用状态、参数版本、逐次上下文、判定版本及水平组合表；原配置仅增加组合键，不重建或删除检测结果。

旧检测只根据已有可靠快照回填来源上下文。没有实际试剂批号的历史数据保持「未记录」；没有原始判定快照的数据只能标记迁移后复核，不能声称恢复了当时判定。

迁移前停止应用，运行以下命令。脚本自动在数据库所在目录的 `backups` 下创建备份，检查原始结果各列及基础资料内容、SQLite 完整性和外键。默认使用当前配置数据库，也可通过 `--database` 明确指定。

```bash
python scripts/migrate_lot_lifecycle.py
```

审计结果默认保存在 `output/lot-lifecycle-migration/migration-audit.json`。内置词典初始化会更新来源的刷新时间字段，审计明确列出这些字段；它们不参与基础资料内容一致性比较，原始检测结果全部列严格核对。迁移失败时保留备份，恢复备份是独立操作，不自动覆盖数据库。

## 当前边界与后续事项

- 验证功能保存实验室输入的结论及依据/资料位置，不自动完成患者样本比对、不制定统一接受界限、不提供附件上传或电子签名。
- 换批流程限同一试剂/质控品产品；仪器、方法、单位、值类型或产品变化需另建适用配置，不能覆盖已有结果的检测系统身份。
- 旧 LJ 的换批布尔标记保留，但无法据此推断真实批号，也没有自动补造成独立验证事件。
- 当前有试剂使用事件追加更正；尚无单条历史检测实际批号的专用更正界面。原始上下文保持不可回写，不应通过改默认批号来修正旧记录。
- 全部上游配置停用后的记录可从管理页追溯查看；已结束使用但配置仍启用的批次保留原工作台只读查询与报告入口。
- 未新增即时法月报、LIS、用户权限或防止直接修改 SQLite 文件的审计防篡改能力。
- 本轮浏览器验收不是 `2880×1800 @ 200%` 的硬件适配验收；Windows/macOS 打包安装与高缩放环境仍需专项复测。
