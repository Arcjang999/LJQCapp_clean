# 实验室室内质控工作台使用说明

## 1. 这个软件是做什么的

这是一个本地单机版实验室室内质控工具，用来帮助实验室完成日常质控数据管理、图表查看、规则提示、月报生成和报告追溯。

当前主要入口包括：

- 单水平（LJ法）
- 多水平（Z-score法）
- 即时法
- 报告历史
- 系统设置

数据保存在本机数据库中，不依赖云端。正式使用时，请把它当作本机质控记录工具来管理，并定期备份数据。

适合使用的场景：

- 实验室内部试用
- 培训和演示
- 小范围单机部署
- 日常室内质控数据记录和月度回顾

## 2. 第一次使用：先做什么

1. 打开软件后，先看页面上方的几个入口。
2. 如果只做一个水平的日常质控，选择“单水平（LJ法）”。
3. 如果一个项目有 2 个或 3 个水平一起判断，选择“多水平（Z-score法）”。
4. 如果单水平项目仍处于建靶累计阶段，选择“即时法”先过渡，批次建靶次数可设为 5～20 次。
5. 第一次正式使用前，建议先进入“系统设置”。
6. 在“系统设置”里确认实验室名称、科室名称、质控负责人、审核人和报告声明。
7. 如果只是练习，可以先使用演示数据。演示数据项目名称一般以“【演示】”开头。
8. 正式录入前，请先确认当前选择的项目和批次，不要把数据录到错误批次里。

## 3. 单水平（LJ法）怎么用

适合情况：一个检测项目只有一个质控水平，需要做日常 LJ 图和 Westgard 规则判断。

日常操作顺序：

1. 点击顶部“单水平（LJ法）”。
2. 在“项目与批次管理”里先新建项目。
3. 项目名称建议写清楚检测项目，例如“ALT 质控”。
4. 按页面要求填写单位、数值类型等信息，然后保存项目。
5. 选中刚建好的项目，再新建批次。
6. 批次里填写仪器、试剂、质控品、浓度水平、批号、建靶数量、CV 要求等信息。
7. 保存批次后，进入当前批次页面。
8. 每天检测后，在结果录入区填写检测时间、检测人和检测值。
9. 建靶期主要看均值、SD、CV 和离群提示。
10. 建靶数量达到要求后，后面的数据会进入正式期。
11. 正式期主要看 LJ 图、Westgard 规则提示和最新结果分析。
12. 如果发现录错了，或者需要处理离群点，到“记录维护”区域处理。
13. 月底需要总结时，在月报区域选择月份并生成月报。

小提醒：

- 每次录入前先确认项目和批次。
- 建靶期和正式期不要混着理解。
- 录错数据不要重复录一条来“抵消”，应到记录维护里处理。
- 月报通常看正式期数据，所以生成前先确认当月数据已经录完整。

## 4. 多水平（Z-score法）怎么用

适合情况：一个项目有 2 个或 3 个质控水平，需要一起判断。

日常操作顺序：

1. 点击顶部“多水平（Z-score法）”。
2. 在“项目与批次管理”中新建项目。
3. 新建项目时选择水平数：2 水平或 3 水平。
4. 选中项目后，新建批次。
5. 批次里填写仪器、试剂、质控品、批号、各水平名称和建靶数量。
6. 进入当前批次页面。
7. 每次检测作为一次记录。一次检测里要同时填写各水平结果。
8. 例如 2 水平项目，一次检测要填低水平和高水平两个结果。
9. 建靶期分别查看每个水平的均值、SD、CV 和离群提示。
10. 所有水平都达到建靶要求后，后续检测进入正式期。
11. 正式期可以查看单水平图、合并图、本次检测结论和规则证据。
12. 如果某一次检测需要修改，到记录维护区按“本次检测”进行处理。
13. 月底需要总结时，在月报区域选择月份并生成月报。

小提醒：

- Z-score 不是一条一条单独水平乱录，而是按“一次检测”录入多个水平。
- 2 水平和 3 水平的模板不同，导入时不要用错。
- 修改历史数据后，应重新查看图表和本次检测结论。

## 5. 即时法怎么用

适合情况：单水平项目刚开始做，需要按批次设定的建靶次数逐次累计和判断。

日常操作顺序：

1. 点击顶部“即时法”。
2. 新建即时法项目。
3. 新建批次，并设置本批次建靶所需次数（5～20 次，默认 20 次）。
4. 每次检测后，录入检测时间、检测人和检测值。
5. 数据点较少时，系统主要帮你累计数据。
6. 达到可以判断的数量后，页面会显示即刻法 SI 提示。
7. 如果页面提示疑似离群，先复核当天检测、仪器、试剂、质控品和录入值。
8. 如果确认是异常点，按页面维护入口处理。
9. 累计到本批次设定的有效点数后，可以按页面提示确认转入 LJ 法。
10. 转入后，到“单水平（LJ法）”里查看对应项目和批次。

小提醒：

- 即时法是过渡用的，不是长期正式质控的最终入口。
- 转入 LJ 法后，后续日常质控应在 LJ 法里继续做。
- 转入前请确认用于本批次建靶的有效点没有明显录入错误。

## 6. 如何导入数据

适合情况：已经有一批检测结果，不想一条一条手工录入。

操作顺序：

1. 先进入对应方法页面，例如“单水平（LJ法）”或“多水平（Z-score法）”。
2. 选择正确的项目。
3. 选择正确的批次。
4. 找到页面里的“导入/导出”区域。
5. 先下载当前批次、当前阶段对应的导入模板。
6. 打开模板，按列填写检测时间、检测人、检测值和备注。
7. 回到软件，上传填好的 CSV 文件。
8. 先看导入审查结果。
9. 如果有红色错误，先回到文件里修改，再重新上传。
10. 审查通过后，再点击确认导入。
11. 导入完成后，回到图表和记录区确认数据是否正确。

导入前请特别注意：

- 导入是追加写入，不是覆盖原数据。
- 一定先确认项目和批次选对了。
- 建靶期模板不要导入正式期。
- 正式期模板不要导入建靶期。
- LJ 法和 Z-score 法模板不能混用。
- Z-score 的 2 水平和 3 水平模板不能混用。

## 7. 如何导出数据和生成月报

导出数据：

1. 进入对应方法页面。
2. 选择项目和批次。
3. 找到导出区域。
4. 选择要导出的数据范围。
5. 按页面按钮导出 Excel 或 CSV。
6. 如需保存图表，使用图表导出按钮保存 PNG。

生成月报：

1. 进入对应方法页面。
2. 选择项目和批次。
3. 找到月报区域。
4. 选择要生成月报的月份。
5. 生成前确认该月正式期数据已经录完整。
6. 点击生成月报。
7. 生成后可以在“报告历史”里再次查看或重新生成。

小提醒：

- 月报主要用于月度回顾，生成前请先检查当月数据。
- 如果后续修改了历史数据，建议重新生成月报。

## 8. 如何查看报告历史

1. 点击页面右上角或全局入口中的“报告历史”。
2. 在筛选区输入项目名称，或选择方法、批次、月份。
3. 找到需要查看的报告记录。
4. 先查看摘要，确认是不是目标报告。
5. 如果需要当前最新数据的报告，点击按当前数据重新生成。
6. 重新生成后，再下载或查看新的报告。

小提醒：

- 报告历史里的摘要用于帮助你确认报告。
- 如果原始数据后来改过，旧报告摘要可能和当前数据不完全一致。
- 需要最新结果时，请按当前数据重新生成。

## 9. 如何使用系统设置

系统设置用于维护全局信息，不属于某一个具体方法页面。

常用操作：

1. 打开页面右上角或全局入口中的“系统设置”。
2. 确认实验室名称、科室名称、质控负责人和审核人。
3. 维护报告声明和默认报告信息。
4. 查看当前数据库位置。
5. 需要换电脑或迁移数据时，先备份，再按页面提示迁移或恢复。
6. 迁移或恢复后，按页面提示重启软件。

小提醒：

- 系统设置里的实验室信息会影响后续新生成的报告。
- 恢复旧备份前，请确认备份文件来源正确。
- 不确定时，先备份，再操作。

## 10. 演示数据与月报展示

演示数据是用来培训、练习和现场展示的，不是真实检测数据。项目名称均以“【演示】”开头，批次信息中包含“仅演示，请勿用于真实质控”的说明。

这套演示数据的“两个月月报数据”指正式期两个月，不包含建靶期。建靶期是独立阶段，固定 20 个有效点 / 20 个建靶 run。

full profile 中每个月报演示批次包含：

- 2026-03：20 条建靶期数据 / 20 个建靶 run
- 2026-04：30 条正式期数据 / 30 个正式期 run
- 2026-05：30 条正式期数据 / 30 个正式期 run

所以：

- LJ 月报批次总结果数为 80 条，即 20 条建靶期 + 60 条正式期。
- Z-score 月报批次总 run 数为 80 次，即 20 个建靶 run + 60 个正式期 run。
- Z-score 双水平每个 run 包含 Level 1 / Level 2。
- Z-score 三水平每个 run 包含 Level 1 / Level 2 / Level 3。
- 月报月份下拉只显示正式期月份，即 2026年04月、2026年05月，不显示建靶期 2026年03月。

练习顺序：

1. 在主页“如何使用演示数据”里勾选确认框。
2. 点击“导入/刷新标准演示数据”。
3. 导入完成后，进入“单水平（LJ法）”。
4. 选择“【演示】LJ-MR-01 ...”或“【演示】LJ-MR-02 ...”，练习建靶期、正式期、图表和月报。
5. 再进入“多水平（Z-score法）”。
6. 选择“【演示】Z2-MR ...”或“【演示】Z3-MR ...”，练习多水平图表、月报预览和 PDF 下载。
7. 再进入“即时法”。
8. 选择“【演示】Instant ...”开头的项目，练习 SI 提示和转入 LJ 法流程。

月报展示建议：

1. LJ 月报选择 2026年04月或 2026年05月，均可生成月报预览和 PDF。
2. Z-score 月报选择 2026年04月或 2026年05月，均可生成月报预览和 PDF。
3. `LJ-MR-02`、`Z2-MR-02`、`Z3-MR-02` 已预置异常/失控记录和纠正措施备注。
4. 月报中的“异常/失控记录表”和“原因与纠正措施”会展示这些备注，不应出现“未填写”。

小提醒：

- 刷新标准演示数据只处理演示项目，不应删除真实项目。
- 正式使用时，请注意不要把真实检测结果录入演示项目。
- 如果只是培训或练习，优先刷新演示数据，不要重置整个数据库。

## 11. 数据备份、恢复和重置说明

日常建议：

1. 正式使用前，先到“系统设置”确认当前数据库位置。
2. 重要数据录入后，建议定期备份。
3. 更换电脑或移动数据前，先做备份。
4. 如果需要恢复旧数据，到“系统设置”里使用恢复功能。
5. 恢复或迁移数据库后，通常需要重启软件。

关于重置：

- “刷新演示数据”只处理演示项目，适合培训和练习。
- “重置数据库”会删除当前数据库，不只是删除演示数据。
- 一线工作人员不要随便重置数据库。
- 如果确实要重置，请先联系管理员或确认已有备份。

## 12. 常见问题

### Q1：我应该选 LJ 法、Z-score 法还是即时法？

如果一个项目只有一个质控水平，通常选“单水平（LJ法）”。
如果一个项目有 2 个或 3 个水平一起判断，选“多水平（Z-score法）”。
如果现在数据还不够 20 个点，只是先积累数据，选“即时法”。

### Q2：录错数据怎么办？

不要再录一条相反的数据来抵消。
请进入对应批次的“记录维护”区域，找到错误记录后按页面提示修改或处理。

### Q3：导入后发现批次选错了怎么办？

先停止继续录入。
到记录维护区确认错误数据范围。
如无法自行处理，请联系管理员先备份数据库，再处理错误数据。

### Q4：为什么我看不到正式期？

通常是建靶期有效数据还没达到要求。
请先确认建靶数量、有效点数量，以及是否有点被禁用。

### Q5：月报生成前要检查什么？

先确认月份选对了。
再确认该月正式期数据已经录完整。
如果刚刚修改过历史数据，建议重新生成月报。

### Q6：演示数据会影响真实数据吗？

标准演示数据项目名称通常以“【演示】”开头。
刷新标准演示数据时，应只替换演示项目，不应删除真实项目。
正式使用时，请注意不要把真实检测结果录入演示项目。

### Q7：能不能随便重置数据库？

不能。
重置数据库会删除当前数据库，不只是删除演示数据。
如果只是想练习，请使用演示数据。
如果确实要重置，请先备份，并联系管理员确认。

## 附录：管理员操作

下面内容主要给管理员、部署人员或内部测试人员使用。一线工作人员日常使用时，优先按软件页面上的按钮操作。

### 安装依赖

```powershell
py -m pip install -r requirements.txt
```

### 启动软件

```powershell
py -m streamlit run app.py --server.port 8506
```

也可以使用：

```powershell
py run_app.py
```

或者：

```powershell
run_app.bat
```

### 通过命令刷新演示数据

```powershell
py tools\seed_demo_data.py --profile full --replace-demo
```

此方式用于恢复标准演示环境，只替换“【演示】”前缀项目，不应删除真实项目。也可以双击 `seed_demo_data.bat`。

### 通过命令只删除演示数据

```powershell
py tools\seed_demo_data.py --delete-demo
```

此方式只删除“【演示】”前缀项目，不应删除真实项目。也可以双击 `delete_demo_data.bat`。

### 通过命令重置并导入演示数据

```powershell
py tools\seed_demo_data.py --profile full --reset-all --yes-reset-all
```

此方式会重置整个当前配置数据库，再导入 full profile 演示数据。双击 `reset_and_seed_demo_data.bat` 时会要求输入 `RESET` 确认。

### 重置整个数据库

```powershell
py reset_db.py
```

也可以使用：

```powershell
reset_db.bat
```

重置数据库会删除当前数据库。执行前必须确认已经备份。
如果只是恢复演示环境，请优先刷新演示数据，不要重置整个数据库。
